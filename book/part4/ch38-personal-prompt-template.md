# บทที่ 38 — Prompt template ส่วนตัว

---

## 38.1 ทำไมต้องมี template

สังเกตว่าทุกบทในภาค 2 และ 3 ลงท้ายด้วย prompt ที่หน้าตาคล้ายกัน

นั่นไม่ใช่เรื่องบังเอิญ — prompt ที่ใช้ได้ทุกอันมีโครงเดียวกัน และการรู้โครงนั้นมีค่ากว่าการจำ prompt ทีละอัน

**ประโยชน์สามข้อของการมี template**

1. **ไม่ต้องคิดใหม่ทุกครั้ง** — เติมช่องว่างแทนการเขียนจากศูนย์
2. **ไม่ลืมข้อห้ามสำคัญ** — ข้อห้ามที่เคยช่วยเราไว้จะอยู่ในนั้นตลอด
3. **คุณภาพสม่ำเสมอ** — ผลลัพธ์ไม่ขึ้นกับว่าวันนั้นเราอารมณ์ดีหรือรีบ

---

## 38.2 โครง prompt 6 ส่วน

```
┌─────────────────────────────────────────────┐
│  1. บทบาท     ให้มันสวมบทอะไร                │
│  2. บริบท     สถานการณ์ ผู้รับ ข้อจำกัด       │
│  3. ข้อมูล     ของจริงที่เราวางให้             │
│  4. สิ่งที่ต้องการ  ผลลัพธ์ที่อยากได้           │
│  5. รูปแบบ     ความยาว โครงสร้าง ตาราง        │
│  6. ข้อห้าม    สิ่งที่ต้องไม่ทำ ← สำคัญที่สุด    │
└─────────────────────────────────────────────┘
```

### ส่วนที่ 1 — บทบาท

บอกว่าให้มันทำงานในฐานะอะไร

```
✅ "ผู้ช่วยจัดทำรายงานการประชุม"
✅ "ผู้อนุมัติสินเชื่อที่กำลังพิจารณาเมโมนี้"
❌ "ผู้เชี่ยวชาญด้านการเงินระดับโลก"
```

**อย่าให้บทบาทที่ทำให้มันมั่นใจเกินจริง** — บทบาท "ผู้เชี่ยวชาญ" ทำให้มันตอบด้วยน้ำเสียงที่มั่นใจขึ้น แต่ไม่ได้ทำให้ถูกขึ้น ซึ่งอันตรายกว่า

### ส่วนที่ 2 — บริบท

ทุกอย่างที่มันต้องรู้เพื่อให้ผลลัพธ์ตรงกับสถานการณ์จริง

```
ผู้รับ / ผู้อ่านคือใคร
ความสัมพันธ์
ข้อจำกัด (เวลา ความยาว อำนาจ)
สิ่งที่เรารู้อยู่แล้ว (จะได้ไม่บอกซ้ำ)
```

### ส่วนที่ 3 — ข้อมูล

**ส่วนที่สำคัญที่สุดสำหรับความถูกต้อง** (หลักข้อ 5 ในบทที่ 3)

วางของจริงลงไป แทนที่จะให้มันหาเอง

### ส่วนที่ 4 — สิ่งที่ต้องการ

บอกให้ชัดว่าต้องการอะไร และอย่าให้มันทำสองอย่างในคำสั่งเดียวถ้าสองอย่างนั้นมีความเสี่ยงต่างกัน

*ตัวอย่าง:* แยก "คำนวณ" กับ "ตีความ" ออกจากกัน (บทที่ 21)

### ส่วนที่ 5 — รูปแบบ

```
ความยาว (บรรทัด / ย่อหน้า / จำนวนข้อ)
โครงสร้าง (หัวข้ออะไรบ้าง เรียงอย่างไร)
ตาราง / รายการ / ความเรียง
สิ่งที่ต้องมีในทุกข้อ (เช่น ที่มา จำนวนแถวที่รองรับ)
```

### ส่วนที่ 6 — ข้อห้าม

> ## **ส่วนนี้สำคัญที่สุด และเป็นส่วนที่คนไม่เขียน**

ข้อห้ามคือสิ่งที่แยก prompt ที่ใช้ได้ออกจาก prompt ที่ได้ผลลัพธ์สวยแต่เชื่อไม่ได้

**ข้อห้ามที่ควรมีในเกือบทุก prompt**

```
□ ห้ามเพิ่มข้อมูลที่ไม่มีในสิ่งที่ให้ไป
□ ถ้าข้อมูลไม่พอ ให้บอกว่าไม่พอ ห้ามเดา
□ ห้ามอ้างระเบียบ ประกาศ หรือเอกสารที่ฉันไม่ได้ให้
□ ห้ามให้ตัวเลขที่ไม่มีแหล่งที่มา
```

**ข้อห้ามเฉพาะงาน** มาจากบันทึกจุดพลาดของเราเอง (บทที่ 39) — และนี่คือจุดที่ template ส่วนตัวมีค่ากว่า prompt ที่ลอกมาจากที่ไหน

## 38.3 template กลางที่ใช้ได้กับเกือบทุกงาน

```
บทบาท: [ผู้ช่วย...]

บริบท:
- สถานการณ์: [...]
- ผู้รับ/ผู้อ่าน: [...]
- ข้อจำกัด: [...]
- สิ่งที่ฉันรู้อยู่แล้ว ไม่ต้องบอกซ้ำ: [...]

ข้อมูล:
[วางของจริง]

สิ่งที่ต้องการ:
[อธิบายให้ชัด]

รูปแบบ:
- [โครงสร้าง]
- [ความยาว]
- [สิ่งที่ต้องมีในทุกข้อ เช่น ที่มา]

ข้อห้าม:
- ห้ามเพิ่มข้อมูลที่ไม่มีในสิ่งที่ให้ไป
- ถ้าข้อมูลไม่พอ ให้ระบุว่าไม่พอ ห้ามเดา
- ห้ามอ้างระเบียบหรือเอกสารที่ฉันไม่ได้ให้
- [ข้อห้ามเฉพาะงานนี้ จากบันทึกจุดพลาด]

ท้ายผลลัพธ์ ให้ระบุ:
A. จุดที่ข้อมูลที่ฉันให้ไม่เพียงพอ
B. จุดที่คุณไม่มั่นใจ
C. สิ่งที่ฉันควรตรวจเป็นอันดับแรก
```

### ทำไมส่วน A–B–C ท้ายผลลัพธ์ถึงสำคัญ

สามบรรทัดนี้ใช้เวลาพิมพ์ 15 วินาที และเปลี่ยนคุณภาพการทำงานอย่างมาก

| ส่วน | ได้อะไร |
|---|---|
| **A** | รู้ว่าเราให้ข้อมูลไม่ครบตรงไหน — เติมแล้วผลลัพธ์ดีขึ้นทันที |
| **B** | ดึงสิ่งที่มันไม่มั่นใจออกมา ซึ่งปกติมันจะไม่บอก (บทที่ 1) |
| **C** | ได้รายการสิ่งที่ต้องตรวจ โดยไม่ต้องคิดเอง |

**ส่วน B แก้ปัญหาที่ใหญ่ที่สุดของ AI ได้บางส่วน** — มันพูดผิดด้วยน้ำเสียงเดียวกับพูดถูก แต่ถ้าถามตรงๆ มันบอกได้ว่าตรงไหนที่ไม่มั่นใจ

## 38.4 วิธีสร้างและเก็บ template ของตัวเอง

### เก็บไว้ที่เดียว

```
✅ ไฟล์เดียวในเครื่ององค์กร
✅ แยกเป็นหัวข้อตามประเภทงาน
✅ ค้นหาได้ด้วยการค้นคำ
❌ กระจายอยู่ในแชท หาไม่เจอ
❌ จำไว้ในหัว
```

**รูปแบบไฟล์ไม่สำคัญ** — Word, Notepad, OneNote อะไรก็ได้ที่เปิดเร็วและค้นหาได้

### โครงไฟล์ที่แนะนำ

```
📄 prompt ของฉัน

  ## template กลาง
  [โครง 6 ส่วน]

  ## งานประจำ
  ### สรุปประชุม
    prompt: [...]
    จุดที่ต้องตรวจ: [...]
    แก้ครั้งล่าสุด: [วันที่] เพราะ [...]

  ### ร่างหนังสือ
    ...

  ## ข้อห้ามที่ใช้ได้ทุกงาน
  [รวมข้อห้ามที่เจอจากบันทึกจุดพลาด]

  ## prompt ที่เลิกใช้แล้ว
  [เก็บไว้พร้อมเหตุผล — กันไม่ให้กลับไปลองใหม่]
```

**หัวข้อสุดท้ายมีค่ากว่าที่คิด** — ป้องกันไม่ให้ตัวเราในอีกหกเดือนกลับไปลองวิธีที่เคยพิสูจน์แล้วว่าใช้ไม่ได้

### ปรับทีละนิด ไม่ใช่เขียนใหม่

> **กฎ: แก้ครั้งละหนึ่งอย่าง**

ถ้าแก้หลายอย่างพร้อมกันแล้วผลลัพธ์ดีขึ้น เราจะไม่รู้ว่าอะไรทำให้ดีขึ้น และถ้าแย่ลงก็ไม่รู้ว่าเพราะอะไร

**บันทึกทุกครั้งที่แก้**
```
[วันที่] เพิ่มข้อห้าม "ห้ามแปลงคำบอกเวลาคลุมเครือเป็นวันที่เฉพาะเจาะจง"
         เพราะ: มันใส่วันที่ 31 ต.ค. ที่ไม่มีใครพูดในที่ประชุม
```

## 38.5 ตัวอย่างการพัฒนา prompt ทีละรอบ

*(ตัวอย่างสมมติ — งานสรุปประชุม)*

**รอบที่ 1 (เริ่มต้น)**
```
ช่วยสรุปประชุมจากโน้ตนี้ให้หน่อย
[โน้ต]
```
→ ได้สรุปที่ยาวเกิน และรวมข้อเสนอเป็นมติ

**รอบที่ 2 (เพิ่มรูปแบบ)**
```
ช่วยสรุปประชุมจากโน้ตนี้ ตามโครง:
ประเด็น / มติ / สิ่งที่ต้องทำต่อ
[โน้ต]
```
→ โครงดีขึ้น แต่ยังเปลี่ยนข้อเสนอเป็นมติอยู่

**รอบที่ 3 (เพิ่มข้อห้าม — จากบันทึกจุดพลาด)**
```
... + ข้อห้าม: ห้ามใช้คำว่า "มติ" เว้นแต่ในโน้ตระบุชัด
     ถ้าไม่ชัดให้เขียนว่า "มีผู้เสนอ"
```
→ แก้ปัญหามติได้ แต่พบปัญหาใหม่: มันใส่วันที่ที่ไม่มีใครพูด

**รอบที่ 4 (เพิ่มข้อห้ามที่สอง)**
```
... + ห้ามแปลงคำบอกเวลาคลุมเครือ ("ต้นเดือนหน้า")
     เป็นวันที่เฉพาะเจาะจง
```
→ แก้ได้ แต่ยังตัดข้อท้วงติงทิ้ง

**รอบที่ 5 (เพิ่มข้อห้ามที่สาม + ส่วนรายงาน)**
```
... + ถ้ามีความเห็นต่าง ให้แสดงทั้งสองฝั่ง ห้ามรวบ
    + ท้ายเอกสาร ระบุจุดที่ข้อมูลในโน้ตไม่เพียงพอ
```
→ **ใช้ได้จริง** เวลาตรวจลดจาก 15 นาทีเหลือ 7 นาที

**สังเกตว่า prompt ที่ใช้ได้ในรอบที่ 5 คือสิ่งที่ปรากฏในบทที่ 6** — และข้อห้ามทั้งสามข้อมาจากความผิดพลาดที่เจอจริง ไม่ได้มาจากการคิดล่วงหน้า

> **prompt ที่ดีไม่ได้เขียนขึ้น แต่ค่อยๆ ถูกขัดเกลาจากความผิดพลาด**

## 38.6 ข้อผิดพลาดที่พบบ่อยในการทำ template

| ข้อผิดพลาด | ปัญหา | วิธีแก้ |
|---|---|---|
| **ไม่มีส่วนข้อห้าม** | ได้ผลลัพธ์สวยแต่มีข้อมูลที่แต่งขึ้น | ทุก template ต้องมีข้อห้ามอย่างน้อย 3 ข้อ |
| **ยาวเกินจนไม่ใช้** | เปิดมาแล้วขี้เกียจกรอก | ถ้ากรอกไม่เสร็จใน 3 นาที ให้ตัด |
| **ลอก prompt มาจากที่อื่นทั้งดุ้น** | ข้อห้ามไม่ตรงกับความผิดพลาดของงานเรา | ใช้เป็นจุดตั้งต้น แล้วปรับจากบันทึกจุดพลาด |
| **แก้หลายอย่างพร้อมกัน** | ไม่รู้ว่าอะไรได้ผล | แก้ครั้งละหนึ่งอย่าง |
| **ไม่บันทึกว่าทำไมถึงแก้** | อีกหกเดือนไม่รู้ว่าข้อห้ามนี้มีไว้ทำไม แล้วลบทิ้ง | เขียนเหตุผลกำกับทุกครั้ง |
| **เก็บกระจัดกระจาย** | หาไม่เจอตอนต้องใช้ | ไฟล์เดียว ค้นหาได้ |
| **ใส่ข้อมูลลูกค้าลงใน template** | ความเสี่ยงด้านข้อมูล | template ต้องเป็นโครงเปล่า ข้อมูลกรอกตอนใช้ |

## 38.7 ข้อห้ามที่ควรมีติดตัวทุกงาน

รวบรวมจากความผิดพลาดที่ปรากฏบ่อยที่สุดตลอดทั้งเล่ม

```
【 ข้อมูล 】
□ ห้ามเพิ่มข้อมูล ตัวเลข หรือเหตุผลที่ไม่มีในสิ่งที่ให้ไป
□ ถ้าข้อมูลไม่พอ ให้ระบุว่าไม่พอ ห้ามเดา
□ ห้ามอ้างระเบียบ ประกาศ กฎหมาย หรือเอกสารที่ฉันไม่ได้ให้
□ ห้ามใส่ความรู้ทั่วไปเกี่ยวกับอุตสาหกรรมนี้

【 ตัวเลข 】
□ ทุกตัวเลขต้องระบุที่มา
□ ตัวเลขที่เป็นช่วง ต้องคงเป็นช่วง ห้ามทำเป็นค่าเดียว
□ ห้ามคำนวณตัวเลขใหม่ที่ไม่ได้ขอ
□ เปอร์เซ็นต์ต้องมีตัวเลขดิบกำกับ

【 ภาษา 】
□ ห้ามใช้คำว่า "มีศักยภาพ" "มีแนวโน้มที่ดี" "อย่างมีนัยสำคัญ"
  โดยไม่มีตัวเลขในบรรทัดเดียวกัน
□ ห้ามเปลี่ยน "ควร" เป็น "ต้อง" หรือกลับกัน
□ ห้ามรวบความเห็นต่างเป็นข้อสรุปเดียว

【 ขอบเขต 】
□ ห้ามให้ข้อสรุปหรือข้อเสนอแนะ ถ้าฉันขอแค่ข้อเท็จจริง
□ ห้ามตัดสินใจแทนฉัน
```

**ไม่ต้องใส่ทุกข้อในทุก prompt** — เลือกที่เกี่ยวกับงานนั้น แต่ให้รู้ว่ามีอะไรให้เลือกบ้าง

## สรุปบทที่ 38

- prompt ที่ใช้ได้มีโครงเดียวกัน 6 ส่วน: **บทบาท / บริบท / ข้อมูล / สิ่งที่ต้องการ / รูปแบบ / ข้อห้าม**
- **ส่วนข้อห้ามสำคัญที่สุด** และเป็นส่วนที่คนไม่เขียน
- ปิดท้ายทุก prompt ด้วย 3 คำถาม: ข้อมูลไม่พอตรงไหน / ไม่มั่นใจตรงไหน / ควรตรวจอะไรก่อน
- เก็บ template ไว้ที่เดียว ค้นหาได้ **แก้ครั้งละหนึ่งอย่าง บันทึกเหตุผลทุกครั้ง**
- **ข้อห้ามที่ดีมาจากความผิดพลาดที่เจอจริง ไม่ใช่จากการคิดล่วงหน้า**
- prompt ที่ลอกมาจากที่อื่นเป็นจุดตั้งต้น ไม่ใช่คำตอบ

## แบบฝึกหัดท้ายบท

**1. สร้างไฟล์ template วันนี้**
เปิดไฟล์ใหม่ วาง template กลางลงไป แล้วเพิ่มงานที่ทำบ่อยที่สุด 3 งาน

**2. เติมส่วนข้อห้ามจากประสบการณ์**
ย้อนดูงานที่ AI ทำให้ในเดือนที่ผ่านมา มีอะไรที่มันทำแล้วเราไม่ชอบบ้าง — เขียนเป็นข้อห้าม

**3. ทดสอบส่วน A–B–C**
เอา prompt ที่ใช้อยู่ เพิ่มสามบรรทัดท้าย (ข้อมูลไม่พอตรงไหน / ไม่มั่นใจตรงไหน / ควรตรวจอะไรก่อน) แล้วดูว่าได้อะไรกลับมาบ้าง
