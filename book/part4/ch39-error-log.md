# บทที่ 39 — บันทึกจุดพลาด: สินทรัพย์ที่มีค่าที่สุด

---

## 39.1 สิ่งเดียวที่ควรเก็บจากการใช้ AI

หลังใช้ AI ไปหนึ่งปี เราจะมีสามอย่าง

```
1. งานที่ทำเสร็จแล้ว        → ส่งไปแล้ว ไม่ได้อยู่กับเรา
2. prompt ที่ใช้ได้         → มีค่า แต่เปลี่ยนไปเมื่อเครื่องมือเปลี่ยน
3. ความรู้ว่ามันพลาดตรงไหน  → มีค่าที่สุด และอยู่กับเราตลอด
```

**อย่างที่สามคือสิ่งเดียวที่ไม่ล้าสมัย** เพราะความผิดพลาดของ AI ส่วนใหญ่ไม่ได้มาจากข้อจำกัดทางเทคนิคของรุ่นใดรุ่นหนึ่ง แต่มาจากธรรมชาติของวิธีที่มันทำงาน — ไม่รู้บริบทของเรา · เติมช่องว่างเสมอ · ไม่บอกว่าไม่แน่ใจ

**และมันเป็นความรู้ที่ไม่มีใครเขียนหนังสือให้ได้ เพราะมันขึ้นกับงานของเราโดยเฉพาะ**

## 39.2 แบบฟอร์ม 5 ช่อง

| ช่อง | เขียนอะไร | ทำไม |
|---|---|---|
| **วันที่** | | ดูว่าพลาดถี่ขึ้นหรือน้อยลง |
| **งาน** | ประเภทงาน | จัดกลุ่มได้ |
| **AI พลาดอะไร** | เขียนให้เจาะจง | คลุมเครือ = ใช้ไม่ได้ |
| **เราจับได้อย่างไร** | **ช่องที่สำคัญที่สุด** | กลายเป็น checklist |
| **ป้องกันครั้งหน้าอย่างไร** | ข้อห้ามใน prompt / ขั้นตรวจ / เลิกใช้ | เปลี่ยนความรู้เป็นการกระทำ |

### ช่อง "AI พลาดอะไร" — ต้องเจาะจง

| ❌ คลุมเครือ | ✅ เจาะจง |
|---|---|
| "สรุปผิด" | "รวมความเห็นของสองคนที่เห็นต่างกันเป็นข้อสรุปเดียว" |
| "ตัวเลขไม่ตรง" | "คำนวณยอดรายปีจากยอดรายเดือนที่เป็นช่วง โดยใช้ค่ากลางของช่วง" |
| "เขียนไม่ดี" | "เติมประโยค 'ตามนโยบายของธนาคาร' ที่ไม่มีนโยบายนั้นอยู่จริง" |

**เกณฑ์:** ถ้าอ่านแล้วยังไม่รู้ว่าต้องระวังอะไร แปลว่าเขียนไม่พอเจาะจง

### ช่อง "เราจับได้อย่างไร" — ช่องที่สำคัญที่สุด

**เพราะช่องนี้จะกลายเป็น checklist ส่วนตัวของเรา**

เขียนเป็นขั้นตอนที่ทำซ้ำได้

| ❌ ใช้ไม่ได้ | ✅ ใช้ได้ |
|---|---|
| "อ่านแล้วรู้สึกแปลกๆ" | "ไล่ค้นคำว่า 'มติ' ทุกจุด แล้วย้อนหาในโน้ต" |
| "บังเอิญเห็น" | "เทียบผลรวมในตารางสรุปกับ SUM ของข้อมูลดิบ" |
| "เพราะรู้จักลูกค้ารายนี้ดี" | "เทียบข้อสรุปกับสิ่งที่บันทึกใน Call Report ครั้งล่าสุด" |

**ถ้าจับได้โดยบังเอิญ ให้เขียนว่า "จับได้โดยบังเอิญ"** แล้วคิดต่อว่า *"ถ้าจะจับให้ได้ทุกครั้ง ต้องทำอะไร"* — คำตอบนั้นคือสิ่งที่ควรเขียนลงช่องนี้

## 39.4 ทบทวนทุกเดือน — จุดพลาดซ้ำคือกฎใหม่

### วิธีทบทวน (30 นาที/เดือน)

```
1. อ่านทุกแถวของเดือนนั้น
2. จัดกลุ่มตามประเภทความผิดพลาด
3. หาว่ามีกลุ่มไหนที่เกิดซ้ำ
4. เปลี่ยนจุดพลาดซ้ำเป็นกฎถาวร
5. ทบทวนว่าข้อห้ามที่เพิ่มไปแล้วได้ผลไหม
```

### จุดพลาดซ้ำ = สัญญาณสามอย่าง

จากตารางข้างบน จะเห็นว่างานสรุปประชุมพลาดถึง 3 ครั้ง (3 ก.ย., 11 ก.ย., 15 ต.ค.)

**ความหมายที่เป็นไปได้**

| สัญญาณ | แปลว่า | ทำอย่างไร |
|---|---|---|
| พลาดเรื่องเดิม แม้เพิ่มข้อห้ามแล้ว | **ข้อห้ามแก้ไม่ได้ด้วย prompt** | ย้ายไปเป็นขั้นตรวจถาวร |
| พลาดเรื่องใหม่ทุกครั้ง | งานนี้มีจุดเสี่ยงหลายจุด | ทำ checklist เฉพาะงานนี้ |
| พลาดบ่อยและตรวจนาน | **งานนี้อาจไม่คุ้มที่จะใช้ AI** | ประเมินใหม่ตามสมการบทที่ 1 |

**ในตัวอย่างข้างบน:** 3 ก.ย. กับ 15 ต.ค. เป็นความผิดพลาดกลุ่มเดียวกัน — **การทำให้เรียบร้อยเกินจริง** (รวบความเห็นต่าง / ตัดข้อท้วงติง)

→ นี่คือ **นิสัยของเครื่องมือ** ไม่ใช่เรื่องที่ prompt แก้หายได้ (กลุ่ม B ในบทที่ 4)

→ **กฎใหม่:** สรุปประชุมทุกครั้ง ต้องมีขั้นตรวจ *"ในห้องมีใครเห็นต่างบ้าง และความเห็นนั้นอยู่ในสรุปไหม"* — ทำทุกครั้ง ไม่ว่า prompt จะเขียนดีแค่ไหน

## 39.5 เปลี่ยนจุดพลาดเป็นสามอย่าง

ทุกแถวในบันทึกควรแปลงเป็นอย่างใดอย่างหนึ่ง

```
┌──────────────────────────────────────────────┐
│  1. ข้อห้ามใน prompt                          │
│     สำหรับความผิดพลาดที่ป้องกันได้ด้วยคำสั่ง     │
│                                              │
│  2. ขั้นตรวจถาวร                              │
│     สำหรับนิสัยของเครื่องมือที่ prompt แก้ไม่หาย │
│                                              │
│  3. เลิกใช้กับงานนี้                           │
│     เมื่อพลาดบ่อยและตรวจนานพอๆ กับทำเอง         │
└──────────────────────────────────────────────┘
```

**ข้อ 3 ไม่ใช่ความล้มเหลว** — มันคือการตัดสินใจที่ถูกต้องบนข้อมูลที่เรามี และการบันทึกไว้ป้องกันไม่ให้ตัวเราในอนาคตเสียเวลาลองใหม่

**เขียนเหตุผลกำกับเสมอ**
```
[วันที่] เลิกใช้ AI กับงานประเมินราคาที่ดิน
เพราะ: ไม่มีทางตรวจว่าตัวเลขที่ให้มาถูกหรือผิด
       และมันให้ตัวเลขทุกครั้งแม้จะสั่งห้าม
ทดลองไปแล้ว 8 ครั้ง ไม่มีครั้งไหนที่ใช้ได้
```

## 39.6 ทำไมบันทึกนี้มีค่ากว่าที่คิด

### 1. เป็นสิ่งเดียวที่ไม่ล้าสมัย

prompt ที่ใช้ได้วันนี้อาจต้องปรับเมื่อเครื่องมือเปลี่ยน แต่ **"งานประเภทนี้ต้องเช็คตรงนี้เป็นอันดับแรก"** ยังใช้ได้เสมอ

### 2. เป็นเครื่องมือสอนคนใหม่ที่ดีที่สุด

*(บทที่ 40 ว่าด้วยเรื่องนี้)*

การบอกคนใหม่ว่า "ระวังนะ AI มันผิดได้" ไม่มีผลอะไร แต่การให้เขาอ่านบันทึกจุดพลาด 20 แถวที่เป็นเรื่องจริงในงานของเขา เปลี่ยนวิธีทำงานได้ทันที

### 3. เป็นหลักฐานว่าเราตรวจ

ถ้ามีคนถามว่าเราใช้ AI อย่างมีความรับผิดชอบไหม — บันทึกนี้คือคำตอบที่เป็นรูปธรรมกว่าคำพูดใดๆ

### 4. เปลี่ยนความกลัวเป็นความรู้

คนที่ไม่เคยจับผิด AI ได้ มีสองแบบ: กลัวจนไม่กล้าใช้ หรือเชื่อจนไม่ตรวจ

**คนที่จับผิดได้แล้ว 20 ครั้ง อยู่ตรงกลาง** — ใช้อย่างมั่นใจในขอบเขตที่รู้ว่าตรวจได้ (บทที่ 4)

## 39.7 ข้อผิดพลาดในการทำบันทึก

| ข้อผิดพลาด | ปัญหา | วิธีแก้ |
|---|---|---|
| **จดเฉพาะครั้งที่พลาดหนัก** | พลาดเล็กๆ ที่เกิดซ้ำคือสิ่งที่สำคัญกว่า | จดทุกครั้งที่ต้องแก้ แม้แก้แค่คำเดียว |
| **เขียนคลุมเครือ** | อ่านย้อนแล้วไม่รู้ว่าต้องระวังอะไร | เขียนให้เจาะจงจนคนอื่นอ่านแล้วเข้าใจ |
| **ข้ามช่อง "จับได้อย่างไร"** | เสียส่วนที่มีค่าที่สุดไป | ช่องนี้บังคับต้องกรอก |
| **ไม่ทบทวน** | มีข้อมูลแต่ไม่ได้ใช้ | ตั้งเตือนทุกสิ้นเดือน 30 นาที |
| **เก็บไว้คนเดียว** | ทีมต้องพลาดซ้ำแบบเดียวกันทุกคน | แชร์กับทีม (บทที่ 40) |
| **จดแล้วไม่แปลงเป็นการกระทำ** | รู้แต่ไม่เปลี่ยนวิธีทำงาน | ทุกแถวต้องจบที่ 1 ใน 3 อย่างในหัวข้อ 39.5 |
| **ใส่ข้อมูลลูกค้าลงไป** | ความเสี่ยงด้านข้อมูล | เขียนเป็นลักษณะปัญหา ไม่ใช่รายละเอียดเคส |

## 39.8 เริ่มต้นอย่างไร

**วันนี้**
```
□ สร้างไฟล์ "บันทึกจุดพลาด" ในเครื่ององค์กร
□ ใส่หัวตาราง 5 ช่อง
□ ย้อนนึกความผิดพลาดที่จำได้ในเดือนที่ผ่านมา กรอก 3 แถว
```

**สัปดาห์นี้**
```
□ ทุกครั้งที่แก้งานที่ AI ทำ ให้จดหนึ่งบรรทัด
□ ไม่ต้องเขียนยาว 30 วินาทีพอ
```

**สิ้นเดือน**
```
□ ทบทวน 30 นาที
□ หาจุดพลาดซ้ำ
□ แปลงเป็นข้อห้าม / ขั้นตรวจ / เลิกใช้
□ อัปเดต prompt template (บทที่ 38)
```

**ไม่ต้องรอให้พร้อม** — บันทึกที่มี 5 แถวและได้ใช้จริง มีค่ากว่าระบบที่สมบูรณ์แบบที่ยังไม่ได้เริ่ม

## สรุปบทที่ 39

- **ความรู้ว่า AI พลาดตรงไหน คือสิ่งเดียวจากการใช้ AI ที่ไม่ล้าสมัย**
- แบบฟอร์ม 5 ช่อง โดยช่อง **"เราจับได้อย่างไร"** สำคัญที่สุด — มันจะกลายเป็น checklist ส่วนตัว
- เขียนให้เจาะจง ถ้าอ่านแล้วไม่รู้ว่าต้องระวังอะไร แปลว่ายังไม่พอ
- ทบทวนทุกเดือน 30 นาที — **จุดพลาดซ้ำคือกฎใหม่**
- ทุกแถวต้องแปลงเป็น: ข้อห้ามใน prompt / ขั้นตรวจถาวร / เลิกใช้กับงานนี้
- **การเลิกใช้ไม่ใช่ความล้มเหลว** — และต้องบันทึกเหตุผลไว้
- บันทึกนี้คือเครื่องมือสอนคนใหม่ที่ดีที่สุด และเป็นหลักฐานว่าเราทำงานอย่างรับผิดชอบ

## แบบฝึกหัดท้ายบท

**1. สร้างไฟล์วันนี้ กรอก 3 แถวย้อนหลัง**

**2. หาจุดพลาดที่ "จับได้โดยบังเอิญ"**
แล้วเขียนว่าถ้าจะจับให้ได้ทุกครั้ง ต้องทำอะไร — คำตอบนั้นคือขั้นตรวจใหม่ของเรา

**3. ตั้งเตือนทบทวนสิ้นเดือน**
ใส่ในปฏิทิน 30 นาที ทำซ้ำทุกเดือน
