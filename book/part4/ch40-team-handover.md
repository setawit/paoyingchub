# บทที่ 40 — ส่งต่อทีม

---

## 40.1 ปัญหาที่เกิดขึ้นเมื่อคนเดียวในทีมใช้ AI เป็น

สมมติเราผ่านทั้งเล่มนี้มาแล้ว ใช้ AI ได้ดี ตรวจเป็น มีบันทึกจุดพลาด

**แล้วทีมล่ะ**

สิ่งที่มักเกิดขึ้นคือ

```
คนที่ 1 (เรา)     ใช้เป็น ตรวจเป็น งานเร็วขึ้นและยังถูกต้อง
คนที่ 2           เห็นว่าเราใช้แล้วดี เลยใช้บ้าง แต่ไม่ได้ตรวจ
คนที่ 3           ไม่กล้าใช้เลย เพราะกลัวผิด
คนที่ 4           ใช้กับงานที่ไม่ควรใช้ โดยไม่มีใครรู้
```

**คนที่ 2 และ 4 คือความเสี่ยงที่แท้จริงของทีม** และมักไม่มีใครรู้จนกว่าจะเกิดปัญหา

**สาเหตุไม่ใช่ว่าเขาไม่ระวัง** แต่เป็นเพราะเขาเห็นแค่ผลลัพธ์ที่ดีของเรา ไม่ได้เห็นขั้นตอนการตรวจที่อยู่เบื้องหลัง

---

## 40.2 สอนคนใหม่ด้วยบันทึกจุดพลาด ไม่ใช่ด้วยคำชม

### วิธีที่ไม่ได้ผล

```
❌ "AI ช่วยได้เยอะเลย ลองใช้ดูสิ"
   → เขาจะใช้โดยไม่ตรวจ

❌ "ระวังนะ AI มันผิดได้"
   → คำเตือนลอยๆ ไม่เปลี่ยนพฤติกรรม

❌ ส่ง prompt ที่ใช้ได้ให้
   → เขาได้ผลลัพธ์ที่ดี แต่ไม่รู้ว่าทำไมต้องมีข้อห้ามพวกนั้น
     พอเจองานใหม่ก็กลับไปเขียน prompt แบบไม่มีข้อห้าม
```

### วิธีที่ได้ผล

```
✅ ให้อ่านบันทึกจุดพลาดจริง 20 แถว
✅ ให้ลองทำงานที่รู้คำตอบอยู่แล้ว แล้วจับผิดเอง
✅ ให้เห็นเคสที่พลาดจริงในงานของหน่วยงานเรา
```

> **ความเข้าใจมาจากการได้เห็นมันพลาดต่อหน้า ไม่ใช่จากการถูกเตือน**

**ลำดับการสอนที่แนะนำ**

| ลำดับ | ทำอะไร | เวลา |
|---|---|---|
| 1 | ให้อ่านบันทึกจุดพลาดของทีม | 30 นาที |
| 2 | ให้ทำงานที่รู้คำตอบอยู่แล้ว 5 ครั้ง แล้วจับผิด | 2 ชั่วโมง |
| 3 | คุยกันว่าเขาจับได้อะไรบ้าง และพลาดอะไรไป | 30 นาที |
| 4 | ให้ prompt template และอธิบายว่าข้อห้ามแต่ละข้อมาจากไหน | 30 นาที |
| 5 | เริ่มใช้กับงานจริงในกลุ่ม ① เท่านั้น | — |
| 6 | ทบทวนหลัง 1 เดือน ขยายขอบเขตถ้าพร้อม | 30 นาที |

**ขั้นที่ 2 ห้ามข้าม** — มันคือสิ่งเดียวที่ทำให้เขาเข้าใจจริง

## 40.3 checklist ตรวจร่วมของทีม

เมื่อทั้งทีมใช้ AI ควรมีเกณฑ์ร่วมที่ทุกคนใช้เหมือนกัน

### ระดับที่ 1 — กฎที่ใช้กับทุกงาน

```
□ 1. ข้อมูลลูกค้าและข้อมูลภายใน → เครื่องมือในระบบเท่านั้น
□ 2. งานที่มีชื่อเราเซ็น / มีเงินเกี่ยว / คนอื่นเอาไปใช้ต่อ
     → ต้องมีการตรวจที่บันทึกได้
□ 3. ตัวเลขทุกตัวต้องย้อนไปหาต้นทางได้
□ 4. ห้ามอ้างระเบียบหรือราคาตลาดจาก AI
□ 5. ทุกคนจดบันทึกจุดพลาดในไฟล์ร่วมของทีม
```

### ระดับที่ 2 — checklist ต่องาน

ใช้ checklist ในภาคผนวก ข เป็นจุดตั้งต้น แล้วปรับตามบันทึกจุดพลาดของทีมเอง

### ระดับที่ 3 — งานที่ต้องมีคนที่สองดู

กำหนดให้ชัดว่างานประเภทไหนต้องผ่านตาคนที่สอง

*ตัวอย่างเกณฑ์*
```
□ เมโมที่วงเงินเกิน [X]
□ การปรับโครงสร้างหนี้ทุกกรณี
□ งานที่ใช้ AI ในเรื่องที่คนทำไม่เคยทำมาก่อน
□ งานที่ผลลัพธ์จะถูกส่งออกนอกองค์กร
```

**การมีคนที่สองดูไม่ได้แปลว่าไม่ไว้ใจกัน** — มันแปลว่างานนั้นสำคัญพอที่จะไม่ปล่อยให้พลาดได้

## 40.4 ใครรับผิดชอบอะไรเมื่อ AI พลาด

> ## **ต้องชัดก่อนเริ่ม ไม่ใช่ตอนเกิดปัญหา**

นี่คือบทสนทนาที่ทีมส่วนใหญ่ไม่เคยคุยกัน แล้วไปคุยกันในวันที่มีปัญหา ซึ่งเป็นวันที่แย่ที่สุดที่จะคุย

### คำตอบพื้นฐานที่ควรตกลงกัน

```
┌────────────────────────────────────────────────┐
│  คนที่เซ็นชื่อ = คนที่รับผิดชอบ 100%             │
│  ไม่ว่างานนั้นจะทำด้วยเครื่องมืออะไร              │
└────────────────────────────────────────────────┘
```

**"AI เขียนมา" ไม่ใช่คำแก้ตัว** (บทที่ 3 ข้อ 6) — และทีมต้องเห็นตรงกันในข้อนี้ตั้งแต่วันแรก

### คำถามที่ต้องตอบร่วมกัน

| คำถาม | ทำไมต้องตอบก่อน |
|---|---|
| ถ้างานที่ใช้ AI มีข้อผิดพลาด ใครรับผิดชอบ | ถ้าไม่ชัด จะเกิดการโยนกันในวันที่แย่ที่สุด |
| หัวหน้าที่อนุมัติงาน รับผิดชอบส่วนไหน | หัวหน้าต้องรู้ว่างานนี้ใช้ AI หรือไม่ |
| ถ้าคนในทีมใช้ AI กับงานที่ไม่ควรใช้ ใครเตือน | ต้องมีคนกล้าเตือน และต้องไม่ใช่เรื่องส่วนตัว |
| ถ้าเผลอใส่ข้อมูลลูกค้าในเครื่องมือนอกระบบ ทำอย่างไร | ต้องรายงาน ไม่ใช่เงียบ (บทที่ 5) |
| งานที่ใช้ AI ต้องแจ้งไหม | ขึ้นกับนโยบายองค์กร แต่ทีมควรรู้กันเอง |

### สิ่งที่ควรหลีกเลี่ยง

```
❌ วัฒนธรรมที่ทำให้คนไม่กล้าบอกว่าใช้ AI
   → จะกลายเป็นการใช้แบบซ่อนๆ ซึ่งอันตรายกว่ามาก

❌ วัฒนธรรมที่โทษคนที่พลาด
   → จะไม่มีใครบันทึกจุดพลาด และทุกคนพลาดซ้ำแบบเดิม

✅ วัฒนธรรมที่ให้คุณค่ากับการจับผิดได้
   → คนที่จับผิด AI ได้ ควรได้รับการยอมรับ ไม่ใช่คนที่ทำงานเร็วที่สุด
```

## 40.5 วัดผลจากอะไร

**นี่คือส่วนที่ทีมส่วนใหญ่วัดผิด**

### ตัวชี้วัดที่วัดง่ายแต่ไม่ควรใช้เดี่ยว

| ตัวชี้วัด | ปัญหา |
|---|---|
| เวลาที่ลดลง | ลดเวลาได้ง่ายมากถ้าไม่ตรวจ |
| จำนวนงานที่ทำได้ | ปริมาณไม่ได้บอกคุณภาพ |
| จำนวนคนที่ใช้ AI | ใช้เยอะไม่ได้แปลว่าใช้ดี |

**ถ้าวัดแค่สามอย่างนี้ ทีมจะถูกผลักไปสู่การใช้โดยไม่ตรวจ** เพราะการตรวจทำให้ตัวเลขทั้งสามแย่ลง

### สมการที่ควรใช้

```
ผลลัพธ์จริง = เวลาที่ลดลง − (ความผิดพลาดที่เพิ่มขึ้น × ต้นทุนของความผิดพลาด)
```

**ต้องวัดทั้งสองด้าน** ไม่งั้นจะได้ภาพที่ผิด

### ตัวชี้วัดที่ควรใช้ควบคู่

| วัดอะไร | อย่างไร |
|---|---|
| **เวลาที่ลดลง** | เทียบเวลาทำงานประเภทเดียวกันก่อน-หลัง |
| **ความผิดพลาดที่หลุดออกไป** | นับครั้งที่มีคนอื่นจับได้ (ที่ประชุม / ผู้ตรวจสอบ / ลูกค้า) |
| **ความผิดพลาดที่เราจับได้เอง** | จากบันทึกจุดพลาด — **ตัวเลขนี้สูงเป็นเรื่องดี** |
| **จำนวนงานในกลุ่มเสี่ยงสูงที่ใช้ AI โดยไม่ตรวจ** | ควรเป็นศูนย์ |

**ตัวชี้วัดที่สามต้องอธิบายให้ทีมเข้าใจ** — ถ้าบันทึกจุดพลาดมี 40 แถวในเดือนนี้ นั่นไม่ได้แปลว่าทีมแย่ มันแปลว่าทีมกำลังตรวจอยู่

**ทีมที่บันทึกจุดพลาดว่างเปล่า ไม่ใช่ทีมที่ไม่มีความผิดพลาด แต่เป็นทีมที่ไม่ได้ตรวจ**

## 40.6 เริ่มต้นกับทีมอย่างไร

### เดือนที่ 1 — สร้างฐานร่วม

```
□ คุยกันเรื่องความรับผิดชอบ (หัวข้อ 40.4) ให้จบก่อนอย่างอื่น
□ ตกลงกฎระดับที่ 1 (5 ข้อในหัวข้อ 40.3)
□ สร้างไฟล์บันทึกจุดพลาดร่วมของทีม
□ ทุกคนเริ่มจดตั้งแต่วันแรก
```

### เดือนที่ 2 — ฝึกร่วมกัน

```
□ เลือกงาน 1 ประเภทที่ทั้งทีมทำเหมือนกัน (เช่น สรุปประชุม)
□ ทุกคนทำงานเดียวกันกับ AI แล้วเอามาเทียบกัน
□ ดูว่าใครจับผิดอะไรได้บ้าง
□ รวมเป็น checklist ของทีมสำหรับงานนั้น
```

**ขั้นนี้มีค่ามาก** เพราะแต่ละคนจะจับผิดคนละจุด และการรวมสิ่งที่ทุกคนจับได้ ให้ checklist ที่ดีกว่าที่คนเดียวทำได้

### เดือนที่ 3 — ขยายและทบทวน

```
□ ทบทวนบันทึกจุดพลาดร่วมกัน 1 ชั่วโมง
□ หาจุดพลาดซ้ำ → แปลงเป็นกฎของทีม
□ ขยายไปงานประเภทที่ 2
□ ประเมินว่างานไหนที่ไม่ควรใช้ AI
```

### หลังจากนั้น — ทุกเดือน

```
□ ทบทวนบันทึกจุดพลาด 1 ชั่วโมง
□ อัปเดต checklist และ prompt ของทีม
□ คนใหม่ที่เข้ามา ให้ผ่านลำดับการสอนในหัวข้อ 40.2
```

## 40.7 สิ่งที่ไม่ควรทำกับทีม

| ไม่ควรทำ | เพราะ |
|---|---|
| **บังคับให้ทุกคนใช้** | คนที่ยังตรวจไม่เป็นจะใช้แบบอันตราย |
| **ตั้งเป้าหมายเป็นจำนวนงานที่ใช้ AI** | ผลักให้ใช้กับงานที่ไม่ควรใช้ |
| **ห้ามใช้ทั้งหมด** | จะกลายเป็นการใช้แบบซ่อนๆ |
| **ให้คนที่เก่งที่สุดทำ prompt ให้ทุกคน** | คนอื่นไม่ได้เรียนรู้ พอเจองานใหม่ก็ทำไม่เป็น |
| **ไม่คุยเรื่องความรับผิดชอบ** | ระเบิดเวลา |
| **ลงโทษคนที่รายงานว่าพลาด** | จะไม่มีใครรายงานอีก |

## 40.8 ปิดเล่ม

หนังสือเล่มนี้เริ่มด้วยประโยคเดียว

> **มั่นใจใน AI ไม่ได้ ต้องมั่นใจในวิธีตรวจของตัวเอง**

สี่สิบบทที่ผ่านมาคือการขยายประโยคนั้น

### สิ่งที่ควรเหลืออยู่หลังปิดเล่ม

**ถ้าจำได้แค่สามอย่าง ให้จำสามอย่างนี้**

```
1. คำถามเดียวก่อนใช้ทุกครั้ง
   "ถ้ามันผิด ฉันจะรู้ไหม และผิดแล้วเสียหายแค่ไหน"

2. หลักสองข้อที่ลากอีกสี่ข้อตามมา
   ป้อนข้อมูลจริงเอง  ·  ชื่อเราเซ็น = รับผิดชอบ 100%

3. สิ่งเดียวที่ควรสะสม
   บันทึกจุดพลาด
```

### สิ่งที่เล่มนี้ไม่ได้สัญญา

เล่มนี้ไม่ได้สัญญาว่าจะทำให้ทำงานเร็วขึ้นสองเท่า ไม่ได้สัญญาว่าจะไม่มีวันพลาด และไม่ได้สัญญาว่าเครื่องมือที่ใช้วันนี้จะยังใช้ได้ในอีกสองปี

**สิ่งเดียวที่เล่มนี้เสนอคือ: วิธีตรวจ**

เพราะเครื่องมือเปลี่ยน แต่คำถามว่า *"เรารู้ได้อย่างไรว่างานที่เราส่งออกไปถูกต้อง"* ไม่เคยเปลี่ยน — และเป็นคำถามที่มีอยู่ก่อนที่จะมี AI และจะยังอยู่ต่อไป

### ประโยคสุดท้าย

งานที่เราเซ็นชื่อ ยังเป็นงานของเรา

เครื่องมือที่ดีทำให้เราทำงานนั้นได้เร็วขึ้น มีเวลาคิดมากขึ้น และมีคนคอยเถียงเราเมื่อต้องการ

**แต่มันไม่เคยรับผิดชอบแทนเรา และไม่ควรจะรับ**

---

## แบบฝึกหัดท้ายบท

**1. คุยเรื่องความรับผิดชอบกับทีมภายในสัปดาห์นี้**
ใช้คำถาม 5 ข้อในหัวข้อ 40.4 เป็นหัวข้อสนทนา

**2. สร้างไฟล์บันทึกจุดพลาดร่วมของทีม**
แล้วเริ่มด้วยการที่เราเป็นคนแรกที่จดความผิดพลาดของตัวเอง

**3. เลือกงาน 1 ประเภทที่ทั้งทีมทำเหมือนกัน**
ให้ทุกคนทำกับ AI แล้วเอามาเทียบว่าใครจับผิดอะไรได้บ้าง
