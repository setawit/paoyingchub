# บทที่ 10 — งาน Excel: สูตร, pivot, ล้างข้อมูล

> **กลุ่มเสี่ยง:** ตรวจง่าย · เสียหายมาก — **ช่อง ②**
> เดิมพันสูง แต่มีวิธีตรวจที่ชัดเจนและใช้เวลาไม่ถึง 5 นาที ไม่มีข้ออ้างที่จะไม่ตรวจ

## 1. งานนี้คืออะไร ปกติทำอย่างไร ใช้เวลาเท่าไร

งาน Excel ที่ให้ AI ช่วยได้แบ่งเป็นสามกลุ่ม

| กลุ่ม | ตัวอย่าง | เวลาแบบเดิม |
|---|---|---|
| **เขียนสูตร** | VLOOKUP ซ้อน IF, SUMIFS หลายเงื่อนไข, สูตรหาวันครบกำหนด | 10–60 นาที (ส่วนใหญ่หมดไปกับการหาว่าเขียนยังไง) |
| **สร้าง pivot / สรุป** | สรุปยอดตามกลุ่ม ตามเดือน ตามสาขา | 15–30 นาที |
| **ล้างข้อมูล** | ชื่อสะกดไม่เหมือนกัน วันที่คนละรูปแบบ ช่องว่างเกิน ข้อมูลซ้ำ | 30 นาที – หลายชั่วโมง |

**เวลาที่ใช้เมื่อมี AI ช่วย:** เขียนสูตร 1 นาที + ทดสอบ 3 นาที

งานนี้เป็นงานที่ AI ช่วยได้ดีที่สุดงานหนึ่ง เพราะสูตร Excel เป็นภาษาที่มีกฎตายตัว และ AI เคยเห็นมาเยอะมาก

## 2. AI ช่วยตรงไหนได้ ตรงไหนช่วยไม่ได้

| ช่วยได้ดี | ช่วยไม่ได้ |
|---|---|
| เขียนสูตรที่เราจำไวยากรณ์ไม่ได้ | รู้ว่าข้อมูลในตารางเราหน้าตาเป็นอย่างไร |
| อธิบายว่าสูตรที่มีอยู่ทำงานอย่างไร | รู้ว่าเซลล์ว่างในคอลัมน์นี้แปลว่าอะไร |
| หาว่าสูตรที่พังพังเพราะอะไร | รู้ว่าข้อมูลแถวนี้ผิดหรือถูกแต่แปลก |
| เสนอวิธีล้างข้อมูลเป็นกฎ | รู้ว่าลูกค้าสองชื่อนี้เป็นคนเดียวกันไหม |
| แปลงสูตรเป็นภาษาที่คนอื่นเข้าใจ | รับผิดชอบเมื่อตัวเลขในรายงานผิด |

### กฎข้อที่หนึ่งของบทนี้: บอกโครงตารางก่อนขอสูตร

นี่คือสาเหตุอันดับหนึ่งที่สูตรจาก AI ใช้ไม่ได้

AI ไม่เห็นไฟล์ของเรา ถ้าเราไม่บอกโครง มันจะเดา และมันจะเดาว่าตารางเราสะอาด เรียงเป็นระเบียบ ไม่มีเซลล์ว่าง หัวตารางอยู่แถวที่ 1 — ซึ่งแทบไม่เคยเป็นจริง

**ต้องบอกอะไรบ้าง**

```
- หัวตารางอยู่แถวไหน ข้อมูลเริ่มแถวไหน จบแถวไหน
- แต่ละคอลัมน์คืออะไร (ตัวอักษรคอลัมน์ + ชื่อหัว + ชนิดข้อมูล)
- มีเซลล์ว่างไหม ว่างแล้วแปลว่าอะไร
- ตัวเลขเก็บเป็นตัวเลขหรือเป็นข้อความ
- วันที่เก็บรูปแบบไหน
- มีแถวรวม แถวว่างคั่น หรือ merge cell ปนอยู่ไหม
- ชื่อชีต
```

ใช้เวลาพิมพ์ 2 นาที ประหยัดเวลาแก้สูตร 20 นาที

### กฎข้อที่สอง: ขอสูตรพร้อมคำอธิบายทีละส่วน

อย่ารับสูตรยาวๆ มาวางเฉยๆ ให้สั่งว่า

> "ให้สูตร แล้วอธิบายว่าแต่ละส่วนของสูตรทำอะไร และบอกว่าถ้าเจอเซลล์ว่าง / ค่าที่หาไม่เจอ / ข้อความปนตัวเลข สูตรจะให้ผลอะไร"

เหตุผลไม่ใช่เพื่อเรียนรู้ (แม้จะได้ด้วย) แต่เพื่อ **ตรวจ** — ถ้าคำอธิบายกับสิ่งที่เราต้องการไม่ตรงกัน เราจะเห็นตั้งแต่ยังไม่ทดสอบ

### กฎข้อที่สาม: ล้างข้อมูล — ให้เสนอกฎ ไม่ใช่ให้แก้เอง

**อันตรายที่สุดของงาน Excel คือการให้ AI "ล้างข้อมูลให้"** แล้วได้ตารางใหม่กลับมา

เพราะเราจะไม่รู้ว่ามันแก้อะไรไปบ้าง แถวไหนหายไป ค่าไหนถูกเปลี่ยน และมันตัดสินใจจากอะไร

**สิ่งที่ควรทำแทน:** ให้มันเสนอ **กฎ** แล้วเราเป็นคนใช้กฎนั้นเอง

*ตัวอย่างผลลัพธ์ที่ต้องการ:*

> กฎที่ 1: คอลัมน์ C (ชื่อ) — ตัดช่องว่างหน้า-หลัง ใช้ TRIM
> กฎที่ 2: คอลัมน์ D (วันที่) — มี 2 รูปแบบปนกัน (dd/mm/yyyy กับ yyyy-mm-dd) ให้แปลงเป็นรูปแบบเดียว **แต่ระวัง**: แถวที่วันน้อยกว่า 13 แยกไม่ออกว่าเป็นวันหรือเดือน ต้องตรวจด้วยตา 47 แถว
> กฎที่ 3: คอลัมน์ F (จำนวนเงิน) — 12 แถวเก็บเป็นข้อความเพราะมีเครื่องหมายจุลภาค
> กฎที่ 4: พบชื่อที่คล้ายกันมาก 8 คู่ **ไม่ตัดสินใจให้** ให้ตรวจด้วยตาว่าเป็นคนเดียวกันหรือไม่

กฎที่ 4 คือตัวอย่างของสิ่งที่ AI **ต้องไม่ทำเอง** เพราะการรวมลูกค้าสองรายเป็นรายเดียวผิด สร้างความเสียหายที่ตามกลับยาก

## 3. Input ที่ต้องเตรียมก่อนสั่งงาน

```
1. โครงตาราง          ตามรายการในกฎข้อที่หนึ่ง
2. ตัวอย่างข้อมูล 5-10 แถว  รวมแถวที่แปลกด้วย ไม่ใช่เฉพาะแถวสวย
3. ผลลัพธ์ที่ต้องการ    อธิบายเป็นภาษาคน + ตัวอย่างคำตอบที่ถูก 1-2 กรณี
4. เวอร์ชัน Excel      (บางฟังก์ชันไม่มีในเวอร์ชันเก่า เช่น XLOOKUP, TEXTSPLIT)
5. ภาษาของสูตร        ไทยหรืออังกฤษ (ตัวคั่นต่างกัน , กับ ;)
```

**ข้อ 2 สำคัญกว่าที่คิด** — ถ้าให้ตัวอย่างเฉพาะแถวที่สวย จะได้สูตรที่ใช้ได้กับแถวสวยเท่านั้น ให้เลือกแถวที่มีปัญหามาด้วยอย่างน้อย 2 แถว

**ถ้าเป็นข้อมูลลูกค้าจริง** ต้องแทนด้วยข้อมูลสมมติที่โครงเหมือน (บทที่ 5) — สูตรใช้ได้เหมือนกันเพราะสูตรทำงานกับโครง ไม่ใช่กับเนื้อหา

## 4. กลุ่มความเสี่ยง

**ตรวจง่าย** — มีวิธีทดสอบที่ชัดเจน ให้ผลแน่นอน ใช้เวลาไม่กี่นาที

**เสียหายมาก** — เพราะ

- สูตรผิดหนึ่งเซลล์ ลากลงไป 3,000 แถว ผิดหมด 3,000 แถว
- ตัวเลขที่ได้ไปอยู่ในรายงานที่คนใช้ตัดสินใจ
- ความผิดพลาดของสูตรมักไม่ใช่ error แต่เป็น**ตัวเลขที่ดูปกติ** — `#N/A` เรามองเห็น แต่ตัวเลขที่ต่ำกว่าความจริง 8% เพราะ VLOOKUP หาไม่เจอแล้วถูก IFERROR แปลงเป็น 0 เรามองไม่เห็น

**ข้อสังเกตสำคัญ:** งานนี้ผิดได้เงียบที่สุดในบรรดางานทั้งหมดในภาค 2 เอกสารที่เขียนผิดเราอ่านแล้วสะดุด แต่ตารางที่คำนวณผิดไม่สะดุดอะไรเลย

## 5. วิธีตรวจ

### ขั้นที่ 1 — ทดสอบกับ 3 แถวที่รู้คำตอบ *(2 นาที)*

นี่คือวิธีตรวจหลักของบทนี้ ทำทุกครั้ง ไม่มีข้อยกเว้น

**เลือกสามแถวแบบนี้เสมอ**

| แถวที่ | เลือกอย่างไร | จับอะไรได้ |
|---|---|---|
| **1. ค่าปกติ** | แถวธรรมดาที่สุด | ตรรกะพื้นฐานถูกไหม |
| **2. ค่าสุดขั้ว** | ค่ามากสุด น้อยสุด หรือติดลบ | เงื่อนไขขอบเขตถูกไหม |
| **3. ค่าว่าง/ผิดปกติ** | เซลล์ว่าง ข้อความปนตัวเลข ค่าที่หาไม่เจอ | สูตรพังหรือให้ค่าผิดเงียบๆ |

**คำนวณคำตอบที่ถูกด้วยมือก่อน** แล้วค่อยดูว่าสูตรให้ค่าตรงไหม — ไม่ใช่ดูค่าที่สูตรให้แล้วคิดว่าน่าจะถูก

แถวที่ 3 คือแถวที่จับความผิดพลาดได้มากที่สุด และเป็นแถวที่คนข้ามบ่อยที่สุด

### ขั้นที่ 2 — ตรวจ pivot ด้วยผลรวม *(1 นาที)*

> **กฎ: ผลรวมใน pivot ต้องเท่ากับผลรวมข้อมูลดิบ**

ทำง่ายๆ: ที่เซลล์ว่างสักที่ ใส่ `=SUM(คอลัมน์ทั้งหมดในข้อมูลดิบ)` แล้วเทียบกับยอดรวมใน pivot

ถ้าไม่เท่า แปลว่ามีอย่างน้อยหนึ่งในสามอย่างนี้
- ช่วงข้อมูลที่ pivot อ้างถึงไม่ครอบคลุมทุกแถว (พบบ่อยที่สุด เมื่อมีการเพิ่มแถวใหม่)
- มีตัวกรองซ่อนอยู่
- มีค่าที่เก็บเป็นข้อความจึงไม่ถูกนับรวม

**ตรวจเพิ่มอีกจุด:** จำนวนแถวที่นับได้ใน pivot ต้องเท่ากับจำนวนแถวข้อมูลดิบด้วย ไม่ใช่แค่ผลรวมเท่ากัน

### ขั้นที่ 3 — ล้างข้อมูล: นับแถวก่อน-หลัง *(2 นาที)*

```
จำนวนแถวก่อนล้าง:  ______
จำนวนแถวหลังล้าง:  ______
หายไป:            ______ แถว
เหตุผลที่หาย:      ______________
```

**ถ้าตอบช่องสุดท้ายไม่ได้ ห้ามใช้ข้อมูลชุดนั้น**

ต้องรู้ว่าหายไปเพราะอะไร — ซ้ำจริง? ว่างจริง? หรือถูกลบเพราะ "ดูผิด" ทั้งที่ถูก?

เพิ่มการตรวจอีกชั้น: เอาแถวที่ถูกลบมาดูด้วยตา 5 แถว ว่าสมควรถูกลบจริงไหม

### ขั้นที่ 4 — ตรวจปลายตาราง *(1 นาที)*

เลื่อนไปดูแถวสุดท้ายของข้อมูล และตรวจว่าสูตรลากลงไปครบทุกแถวหรือไม่

ความผิดพลาดคลาสสิก: สูตรอ้างช่วง `A2:A1000` แต่ข้อมูลมี 1,247 แถว — 247 แถวสุดท้ายไม่ถูกนับ และไม่มี error ใดๆ ปรากฏ

**วิธีกันถาวร:** ใช้การอ้างอิงแบบตาราง (Table) หรืออ้างทั้งคอลัมน์ `A:A` แทนการระบุช่วงตายตัว

### ขั้นที่ 5 — เช็คสมเหตุสมผลของผลลัพธ์รวม *(1 นาที)*

ถามตัวเองว่าตัวเลขที่ได้ "อยู่ในช่วงที่ควรเป็นไหม" จากความรู้ที่มี

ถ้ายอดรวมสินเชื่อของสาขาออกมา 340 ล้าน ทั้งที่รู้ว่าปกติอยู่ราว 200 ล้าน — ไม่ต้องหาว่าผิดตรงไหนก่อน แค่รู้ว่าต้องหา

**รวมเวลาตรวจ: 5–7 นาที**

## 6. จุดพลาดที่พบบ่อย

| จุดพลาด | อาการ | วิธีกัน |
|---|---|---|
| **สูตรใช้ได้กับตัวอย่าง แต่พังกับข้อมูลจริง** | ทดสอบ 2 แถวแรกผ่าน แถวที่ 400 ผิด | ขั้นตรวจที่ 1 โดยเฉพาะแถวค่าว่าง |
| **IFERROR กลบความผิดพลาด** | ค่าที่หาไม่เจอกลายเป็น 0 เงียบๆ ผลรวมต่ำกว่าจริง | สั่งห้ามใช้ IFERROR ในรอบทดสอบ ให้เห็น error ก่อน |
| **ช่วงข้อมูลไม่ครอบคลุม** | แถวท้ายๆ ไม่ถูกนับ | ขั้นตรวจที่ 4 + ใช้ Table |
| **ล้างข้อมูลแล้วลบแถวที่ "ดูผิด" แต่จริงๆ ถูก** | ข้อมูลหายโดยไม่มีใครรู้ | ขั้นตรวจที่ 3 + ให้เสนอกฎ ไม่ให้แก้เอง |
| **รวมชื่อที่คล้ายกันเป็นรายเดียว** | ลูกค้าสองรายกลายเป็นรายเดียว | ห้ามให้ AI ตัดสินใจเรื่องนี้เด็ดขาด |
| **VLOOKUP หาค่าใกล้เคียง** | ลืมใส่ FALSE ได้ค่าที่ใกล้เคียงแทนค่าที่ตรง | สั่งให้ระบุพารามิเตอร์ครบและอธิบายทุกตัว |
| **สูตรอ้างเซลล์แบบสัมพัทธ์ทั้งที่ควรตรึง** | ลากลงแล้วช่วงอ้างอิงเลื่อนตาม | ขั้นตรวจที่ 1 แถวที่อยู่ท้ายๆ |

## 7. เคสจริง 1 เคส

### สถานการณ์

มีตารางรายการชำระของลูกค้า 1,847 แถว ต้องการสรุปยอดชำระรวมรายเดือนแยกตามประเภทสินเชื่อ

โครงตาราง: A=วันที่ชำระ, B=รหัสลูกค้า, C=ประเภทสินเชื่อ, D=จำนวนเงิน

### ก่อน — สูตรที่ได้มา

```excel
=SUMIFS($D$2:$D$1000, $C$2:$C$1000, $F2,
        $A$2:$A$1000, ">="&DATE(2025,G$1,1),
        $A$2:$A$1000, "<="&EOMONTH(DATE(2025,G$1,1),0))
```

ใส่ลงไป ลากเต็มตาราง ได้ตัวเลขออกมาครบทุกช่อง ไม่มี error ตารางสรุปสวยงาม

### จับผิดอย่างไร

**ขั้นตรวจที่ 2 (ผลรวม pivot เทียบข้อมูลดิบ)** — ทำก่อนเพราะเร็วที่สุด

```
ผลรวมในตารางสรุป:  18,432,150
=SUM(D2:D1848):    24,891,300
ต่างกัน:            6,459,150  (26%)
```

หายไปหนึ่งในสี่ ถ้าไม่ตรวจขั้นนี้ ตัวเลขนี้จะเข้าไปอยู่ในรายงาน

**หาสาเหตุ — ขั้นตรวจที่ 4 (ปลายตาราง)** จับได้ทันที: สูตรอ้าง `$D$2:$D$1000` แต่ข้อมูลมีถึงแถว 1848 — **848 แถวสุดท้ายไม่ถูกนับเลย**

สาเหตุคือตอนบอกโครงตาราง เราบอกว่า "ประมาณพันแถว" AI จึงใส่ 1000 ลงไป และเราลืมไปว่าข้อมูลเติมเข้ามาหลังจากนั้น

**ขั้นตรวจที่ 1 (ทดสอบ 3 แถว)** — หลังแก้ช่วงแล้ว ทดสอบต่อ พบปัญหาที่สอง

- แถวปกติ: ผ่าน
- แถวค่าสุดขั้ว (รายการคืนเงิน จำนวนติดลบ): ผ่าน แต่ทำให้เห็นว่ามีรายการติดลบอยู่ในข้อมูล ซึ่งเราไม่ได้บอก AI ตั้งแต่แรก — ต้องตัดสินใจว่าจะรวมหรือแยก
- **แถวค่าว่าง: ไม่ผ่าน** — พบว่าคอลัมน์ C มี 23 แถวที่เว้นว่าง (ลืมกรอกประเภทสินเชื่อ) แถวเหล่านี้ไม่ตรงกับเงื่อนไขไหนเลย จึงหายไปจากทุกกลุ่ม

ยอด 23 แถวนี้รวมกัน 1,240,000 บาท — ไม่ได้อยู่ในตารางสรุป และไม่มีสัญญาณอะไรบอกว่าหายไป

**ขั้นตรวจที่ 5 (สมเหตุสมผล)** — หลังแก้ทั้งสองจุด ยอดรวมออกมา 24,891,300 ตรงกับข้อมูลดิบพอดี และอยู่ในช่วงที่คาดไว้

### หลัง — สูตรที่แก้แล้ว + การตรวจเพิ่ม

```excel
=SUMIFS($D:$D, $C:$C, $F2,
        $A:$A, ">="&DATE($G$1,H$1,1),
        $A:$A, "<="&EOMONTH(DATE($G$1,H$1,1),0))
```

แก้สามอย่าง: อ้างทั้งคอลัมน์แทนช่วงตายตัว · ตรึงปีเป็นเซลล์อ้างอิงแทนการเขียนตายในสูตร · เพิ่มแถว "ไม่ระบุประเภท" ในตารางสรุปเพื่อรับ 23 แถวที่ว่าง

และเพิ่มเซลล์ตรวจสอบถาวรไว้มุมตาราง

```excel
=IF(SUM(ตารางสรุป)=SUM($D:$D), "OK", "ไม่ตรง ต่าง "&TEXT(SUM($D:$D)-SUM(ตารางสรุป),"#,##0"))
```

เซลล์นี้จะเตือนทันทีทุกครั้งที่มีข้อมูลเพิ่มเข้ามาแล้วตัวเลขไม่ตรง — เป็นการเปลี่ยนการตรวจครั้งเดียวให้เป็นการตรวจถาวร

### บทเรียนจากเคสนี้

**สูตรไม่มี error เลย ทั้งสองความผิดพลาด** ไม่มี `#N/A` ไม่มี `#VALUE!` ตารางดูสมบูรณ์แบบ ตัวเลขทุกช่องมีค่า

นี่คือเหตุผลที่งาน Excel ต้องตรวจด้วยขั้นตอน ไม่ใช่ด้วยการดู

**เวลาที่ใช้ตรวจและแก้ทั้งหมด: 11 นาที** เทียบกับความเสียหายจากการรายงานตัวเลขที่ต่ำกว่าจริง 26%

### สำหรับขอสูตร

```
บทบาท: ผู้ช่วยเขียนสูตร Excel

โครงตาราง (ชีตชื่อ [...]):
- หัวตารางอยู่แถวที่ 1 ข้อมูลเริ่มแถวที่ 2 ถึงแถวที่ [X]
  (จำนวนแถวเพิ่มขึ้นได้ในอนาคต)
- คอลัมน์ A = [ชื่อ] ชนิด [วันที่/ตัวเลข/ข้อความ] รูปแบบ [...]
- คอลัมน์ B = ...
- คอลัมน์ C = ... มีเซลล์ว่าง [กี่แถว] ว่างแปลว่า [...]
- หมายเหตุ: [มีแถวรวม / merge cell / ตัวเลขเก็บเป็นข้อความ / รายการติดลบ]

ตัวอย่างข้อมูลจริง (รวมแถวที่มีปัญหาด้วย):
[วาง 5-10 แถว]

ต้องการ: [อธิบายเป็นภาษาคน]
ตัวอย่างคำตอบที่ถูก: แถว [X] ควรได้ค่า [Y] เพราะ [เหตุผล]

เวอร์ชัน Excel: [...]  ตัวคั่นในสูตร: [, หรือ ;]

สิ่งที่ต้องให้มา:
1. สูตร
2. อธิบายแต่ละส่วนของสูตรว่าทำอะไร
3. ระบุว่าสูตรจะให้ผลอะไรในกรณีเหล่านี้:
   - เซลล์ว่าง
   - ค่าที่หาไม่เจอ
   - ข้อความปนในคอลัมน์ตัวเลข
   - ค่าติดลบ
4. เสนอ 3 แถวที่ควรใช้ทดสอบ (ปกติ / สุดขั้ว / ผิดปกติ)
   พร้อมบอกว่าคำตอบที่ถูกของแต่ละแถวควรเป็นเท่าไร

ข้อห้าม:
- ห้ามใช้ IFERROR หรือ IFNA ในรอบนี้ ฉันต้องการเห็น error
- ห้ามอ้างช่วงตายตัวถ้าข้อมูลจะเพิ่ม ให้ใช้ทั้งคอลัมน์หรือ Table
- ห้ามสมมติว่าข้อมูลสะอาด
```

### สำหรับล้างข้อมูล

```
บทบาท: ผู้ช่วยตรวจคุณภาพข้อมูล

[วางโครงตาราง + ตัวอย่างข้อมูล 20-30 แถว]

สิ่งที่ต้องการ: ตรวจว่าข้อมูลชุดนี้มีปัญหาอะไรบ้าง
และเสนอ "กฎ" การแก้ทีละข้อ

รูปแบบแต่ละกฎ:
- ปัญหาที่พบ + คอลัมน์ + จำนวนแถวที่กระทบ
- วิธีแก้ (สูตรหรือขั้นตอน)
- ความเสี่ยงของการแก้แบบนี้
- ระดับ: [แก้อัตโนมัติได้] หรือ [ต้องให้คนตัดสินทีละแถว]

ข้อห้ามเด็ดขาด:
- ห้ามส่งตารางที่แก้แล้วกลับมา ให้เสนอกฎอย่างเดียว
- ห้ามตัดสินใจว่าชื่อสองชื่อเป็นรายเดียวกัน
  ให้ระบุเป็นคู่ที่น่าสงสัยให้ฉันตรวจเอง
- ห้ามลบแถวใดๆ ให้ระบุแถวที่น่าสงสัยพร้อมเหตุผล

ท้ายสุด: บอกจำนวนแถวที่จะกระทบจากกฎทั้งหมด
และแถวที่ต้องให้คนตรวจด้วยตา
```
