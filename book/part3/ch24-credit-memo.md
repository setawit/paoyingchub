# บทที่ 24 — ร่าง Credit Memo

> **กลุ่มเสี่ยง:** ตรวจง่าย · **เสียหายมาก** — เพราะชื่อเราเซ็น
>
> *ตัวเลขและเคสในบทนี้เป็นตัวเลขสมมติ*

---

## 1. งานนี้คืออะไร ปกติทำอย่างไร ใช้เวลาเท่าไร

รวมทุกอย่างที่วิเคราะห์มา — Call Report, งบการเงิน, statement, DSCR — เป็นเอกสารเสนอขออนุมัติที่ผู้อนุมัติอ่านแล้วตัดสินใจได้

**เวลาที่ใช้แบบเดิม:** 2–5 ชั่วโมงต่อเคส

**เวลาที่ใช้เมื่อมี AI ช่วย:** เรียบเรียง 5 นาที + **ตรวจ 40–60 นาที**

**ข้อสำคัญ:** งานนี้ **ต้องไม่ใช่งานวิเคราะห์** ถ้าเรามาถึงบทนี้แล้วยังไม่รู้คำตอบ แปลว่าเรายังทำบทที่ 21–23 ไม่เสร็จ

> **Credit Memo คือการเรียบเรียงสิ่งที่เรารู้แล้ว ไม่ใช่การค้นหาว่าเรารู้อะไร**

ถ้าให้ AI "วิเคราะห์และเขียนเมโม" ในคราวเดียว เราจะได้เอกสารที่มีข้อสรุปที่เราไม่ได้เป็นคนคิด แต่มีลายเซ็นของเรากำกับ

---

## 2. AI ช่วยตรงไหนได้ ตรงไหนช่วยไม่ได้

| ช่วยได้ดี | ช่วยไม่ได้ |
|---|---|
| เรียบเรียงผลวิเคราะห์ให้เป็นโครง | ตัดสินใจว่าควรอนุมัติหรือไม่ |
| ทำให้ภาษาสม่ำเสมอทั้งฉบับ | รู้ว่าผู้อนุมัติคนนี้ให้ความสำคัญกับอะไร |
| ตรวจว่าครบตามโครงมาตรฐานไหม | รู้ว่าเรื่องไหนเคยเป็นประเด็นในอดีต |
| ชี้ประโยคที่ไม่มีหลักฐานรองรับ | รู้ระเบียบและเกณฑ์ภายใน |
| สวมบทผู้อนุมัติแล้วยิงคำถาม | รับผิดชอบเมื่อเคสมีปัญหา |

### หลักที่ 1 — ป้อนผลวิเคราะห์ที่ทำเสร็จแล้ว

ให้ AI ทำงานกับ **ข้อสรุปที่เราได้มาแล้ว** ไม่ใช่ข้อมูลดิบ

```
❌ "นี่คืองบ 3 ปี statement 12 เดือน ช่วยเขียนเมโมให้หน่อย"
✅ "นี่คือผลวิเคราะห์ที่ฉันทำแล้ว [DSCR 1.18 / ความเสี่ยงหลัก 3 ข้อ /
    ข้อเสนอโครงสร้างวงเงิน] ช่วยเรียบเรียงตามโครงนี้
    ห้ามเพิ่มข้อมูลหรือข้อสรุปที่ไม่มีในที่ให้ไป"
```

### หลักที่ 2 — แยกสามชั้นให้ชัด

เหมือน Call Report แต่เข้มกว่า เพราะเมโมคือเอกสารที่ใช้ตัดสินใจ

| ชั้น | คืออะไร | ตรวจได้อย่างไร |
|---|---|---|
| **ข้อเท็จจริง** | ตัวเลขจากงบ/statement/เอกสาร | ย้อนไปหาต้นทางได้ |
| **ข้อวิเคราะห์** | การตีความข้อเท็จจริง | ต้องมีข้อเท็จจริงในย่อหน้าก่อนหน้ารองรับ |
| **ข้อเสนอ** | สิ่งที่เราเสนอให้ทำ | ต้องตามมาจากข้อวิเคราะห์ |

**ลำดับต้องเป็น ข้อเท็จจริง → ข้อวิเคราะห์ → ข้อเสนอ เสมอ** ถ้าข้อเสนอปรากฏก่อนหลักฐาน ผู้อนุมัติจะอ่านหลักฐานที่เหลือด้วยสายตาที่ระแวง

### โครง Credit Memo มาตรฐาน

```
1. สรุปคำขอและข้อเสนอ         (ผู้อนุมัติอ่านแค่ส่วนนี้ก็ตัดสินใจได้)
2. ข้อมูลลูกค้าและธุรกิจ
3. ผลการวิเคราะห์ทางการเงิน     ข้อเท็จจริง + ตัวเลข
4. ความสามารถในการชำระหนี้      DSCR + stress test
5. หลักประกัน
6. ความเสี่ยงและการบริหารความเสี่ยง
7. ข้อเสนอ                    วงเงิน เงื่อนไข หลักประกัน
8. เอกสารประกอบ
```

**ข้อ 6 คือข้อที่วัดคุณภาพของเมโมทั้งฉบับ** เมโมที่ข้อ 6 สั้นกว่าข้อ 3 มาก คือเมโมที่ยังไม่ได้คิดเรื่องความเสี่ยงจริง

## 3. Input ที่ต้องเตรียมก่อนสั่งงาน

```
1. ผลวิเคราะห์ที่ทำเสร็จแล้วทั้งหมด   จากบทที่ 20-23
2. ตัวเลขทุกตัวพร้อมที่มา            ระบุว่ามาจากเอกสารไหน
3. ข้อสรุปของเรา                   เราคิดว่าอย่างไร
4. ความเสี่ยงที่เราระบุได้
5. ข้อเสนอที่เราจะเสนอ
6. โครงเมโมมาตรฐานของ ธ.ก.ส.
7. ผู้อนุมัติคือใคร                  เพื่อใช้ในการ red team (บทที่ 33)
```

> ### ⚠️ Credit Memo มีข้อมูลลูกค้าครบถ้วนที่สุดในบรรดาเอกสารทั้งหมด
> **เครื่องมือในระบบองค์กรเท่านั้น ไม่มีข้อยกเว้น**

## 4. กลุ่มความเสี่ยง

**ตรวจง่าย** — ทุกอย่างในเมโมต้องย้อนกลับไปหาต้นทางได้ ถ้าย้อนไม่ได้ก็รู้ทันที

**เสียหายมากที่สุดในบรรดางานทั้งหมดในเล่ม** เพราะ

1. **ชื่อเราเซ็น** — เราค้ำประกันทุกประโยคในนั้น
2. **มีคนตัดสินใจจากมัน** — และตัดสินใจเรื่องเงิน
3. **มันอยู่ในแฟ้มตลอดอายุสัญญา** — และจะถูกอ่านย้อนหลังเมื่อมีปัญหา
4. **มันถูกใช้วัดคุณภาพงานของเรา** — ในการตรวจสอบภายใน

**คำถามที่ต้องถามตัวเองก่อนเซ็น:** *"ถ้าเคสนี้เป็น NPL ในอีก 2 ปี แล้วมีคนหยิบเมโมนี้มาอ่าน ฉันจะอธิบายทุกประโยคในนั้นได้ไหม"*

## 5. วิธีตรวจ

### ขั้นที่ 1 — ทุกตัวเลข ย้อนไปหาต้นทางได้ *(15 นาที)*

ไล่ขีดเส้นใต้ตัวเลขทุกตัวในเมโม แล้วเขียนกำกับว่ามาจากไหน

```
ตัวเลข → เอกสารต้นทาง → หน้า/บรรทัด
```

**ถ้ามีตัวเลขไหนที่เขียนที่มาไม่ได้ ตัดทิ้งหรือไปหาที่มาก่อน**

จุดที่ต้องระวังเป็นพิเศษ
- ตัวเลขที่ AI คำนวณเพิ่มจากตัวเลขที่เราให้ (ยอดรายปีจากรายเดือน สัดส่วน เปอร์เซ็นต์)
- ตัวเลขที่ปัดจนเปลี่ยนความหมาย
- ตัวเลขที่อ้างจาก Call Report ที่จริงๆ เป็นคำบอกเล่าของลูกค้า

### ขั้นที่ 2 — ทุกข้อสรุป มีหลักฐานในย่อหน้าก่อนหน้า *(10 นาที)*

ไล่หาทุกประโยคที่เป็นการตัดสิน แล้วถามว่า **"หลักฐานของประโยคนี้อยู่ตรงไหนในเมโม"**

ถ้าหลักฐานอยู่ในหัวเรา แต่ไม่อยู่ในเอกสาร **ต้องใส่เข้าไป** เพราะผู้อนุมัติอ่านเอกสาร ไม่ได้อ่านหัวเรา

*ประโยคที่มักไม่มีหลักฐานรองรับ*
- "ผู้บริหารมีประสบการณ์ในธุรกิจนี้มายาวนาน" → กี่ปี รู้ได้อย่างไร
- "กิจการมีความสัมพันธ์ที่ดีกับคู่ค้า" → วัดจากอะไร
- "ธุรกิจมีแนวโน้มเติบโต" → จากตัวเลขไหน
- "ลูกค้ามีวินัยทางการเงินดี" → จากประวัติการชำระใช่ไหม ระบุมา

### ขั้นที่ 3 — อ่านในบทบาทผู้อนุมัติ *(10 นาที)*

อ่านทั้งฉบับโดยสวมบทผู้อนุมัติที่ขี้สงสัยที่สุด แล้วขีดเส้นใต้ทุกจุดที่จะถูกถาม

**คำถามที่ผู้อนุมัติถามบ่อยที่สุด**

```
1. ตัวเลขนี้มาจากไหน
2. ทำไมถึงเชื่อว่าลูกค้าจะทำได้ตามที่คาด
3. ถ้า [สถานการณ์แย่] เกิดขึ้น จะเป็นอย่างไร
4. ความเสี่ยงข้อนี้ เราจะรู้ตัวเมื่อไร
5. หลักประกันครอบคลุมแค่ไหน ถ้าต้องบังคับจริงจะได้เท่าไร
6. เคสนี้ต่างจากเคสที่เคยมีปัญหาอย่างไร
```

**ทุกจุดที่เราตอบไม่ได้ ต้องแก้ก่อนส่ง** ไม่ใช่เตรียมคำตอบไว้ตอบในที่ประชุม

*(บทที่ 33 ว่าด้วยการให้ AI สวมบทผู้อนุมัติอย่างเป็นระบบ)*

### ขั้นที่ 4 — ตัดประโยคที่ฟังดูดีแต่พิสูจน์ไม่ได้ *(5 นาที)*

ค้นหาคำเหล่านี้แล้วตรวจทีละจุด

```
มีศักยภาพ · มีแนวโน้มที่ดี · มีความมั่นคง · มีประสบการณ์
มีความสัมพันธ์ที่ดี · มีการบริหารที่เป็นระบบ · น่าเชื่อถือ
มีความพร้อม · เหมาะสม · อย่างมีนัยสำคัญ
```

**สำหรับแต่ละคำ:**
- ถ้ามีหลักฐานเฉพาะเจาะจงรองรับ → **แทนที่ด้วยหลักฐานนั้น**
- ถ้าไม่มี → **ตัดทิ้ง**

*ตัวอย่างการแก้*

| ก่อน | หลัง |
|---|---|
| "ผู้บริหารมีประสบการณ์ในธุรกิจมายาวนาน" | "เจ้าของดำเนินกิจการนี้มา 14 ปี (ตั้งแต่ปี [X]) และผ่านภาวะราคาตกต่ำในปี [X] มาแล้ว" |
| "กิจการมีการบริหารจัดการที่เป็นระบบ" | "บุตรชายรับผิดชอบงานบัญชี ใช้โปรแกรมบัญชีสำเร็จรูป มีงบการเงินย้อนหลัง 3 ปีที่ผ่านการตรวจสอบ" |
| "ธุรกิจมีศักยภาพในการเติบโต" | ตัดทิ้ง (หรือแสดงตัวเลขการเติบโตย้อนหลัง) |

**ประโยคที่แก้แล้วยาวกว่า แต่มีน้ำหนักมากกว่าหลายเท่า** เพราะผู้อนุมัติตรวจสอบได้

### ขั้นที่ 5 — เทียบความยาวส่วนข้อดีกับส่วนความเสี่ยง *(3 นาที)*

นับบรรทัด

```
ส่วนที่พูดถึงจุดแข็งและเหตุผลสนับสนุน:  ____ บรรทัด
ส่วนที่พูดถึงความเสี่ยง:                ____ บรรทัด
```

**ถ้าส่วนความเสี่ยงสั้นกว่ามาก แปลว่ายังไม่ได้คิดเรื่องความเสี่ยงจริง**

เมโมที่ดีจะมีส่วนความเสี่ยงที่ยาวใกล้เคียงกับส่วนจุดแข็ง และที่สำคัญกว่าคือ **แต่ละความเสี่ยงต้องมีมาตรการรองรับที่เฉพาะเจาะจง**

| ความเสี่ยงที่เขียนแบบใช้ไม่ได้ | ที่เขียนแบบใช้ได้ |
|---|---|
| "ความเสี่ยงด้านราคาผลผลิต — ติดตามสถานการณ์อย่างใกล้ชิด" | "ราคาลงเกิน 12% ทำให้ DSCR < 1 → กำหนดเงื่อนไขรายงานราคาขายเฉลี่ยรายไตรมาส และทบทวนวงเงินหากราคาเฉลี่ย 2 ไตรมาสติดต่อกันต่ำกว่า [X]" |

### ขั้นที่ 6 — เช็คความสอดคล้องระหว่างส่วน *(5 นาที)*

```
□ ตัวเลขในส่วนสรุป ตรงกับในเนื้อหา
□ ความเสี่ยงที่ระบุในข้อ 6 ถูกพูดถึงในข้อ 3-4 หรือไม่
□ ข้อเสนอในข้อ 7 ตอบความเสี่ยงในข้อ 6 หรือไม่
□ วงเงินที่เสนอ สอดคล้องกับความต้องการที่วิเคราะห์ไว้
□ เงื่อนไขที่เสนอ ตรวจสอบได้จริงในทางปฏิบัติ
```

**ข้อที่สามคือข้อที่พลาดบ่อย** — ระบุความเสี่ยงไว้สวยงามในข้อ 6 แล้วข้อ 7 เสนอวงเงินโดยไม่มีเงื่อนไขอะไรที่เกี่ยวกับความเสี่ยงนั้นเลย

**รวมเวลาตรวจ: 48 นาที**

## 6. จุดพลาดที่พบบ่อย

| จุดพลาด | ลักษณะ | วิธีกัน |
|---|---|---|
| **เขียนเชียร์เกินหลักฐาน** | ภาษาบวกที่ไม่มีตัวเลขรองรับ | ขั้นตรวจที่ 4 |
| **ข้อเสี่ยงเขียนสั้นกว่าข้อดี** | ส่วนความเสี่ยง 3 บรรทัด ส่วนจุดแข็ง 2 หน้า | ขั้นตรวจที่ 5 |
| **ใช้ภาษากว้างๆ แทนตัวเลข** | "มีศักยภาพ" แทน "โต 12% ต่อปี 3 ปีติดต่อกัน" | ขั้นตรวจที่ 4 |
| **ตัวเลขไม่ตรงกันระหว่างส่วน** | สรุปเขียน 2.4 ล้าน เนื้อหาเขียน 2.6 ล้าน | ขั้นตรวจที่ 6 |
| **ข้อสรุปไม่มีหลักฐานรองรับ** | สรุปลอยๆ ที่ผู้อนุมัติตรวจไม่ได้ | ขั้นตรวจที่ 2 |
| **มาตรการรองรับความเสี่ยงที่ทำไม่ได้จริง** | "ติดตามอย่างใกล้ชิด" ที่ไม่มีใครทำ | ขั้นตรวจที่ 5 |
| **ใช้คำบอกเล่าลูกค้าเป็นข้อเท็จจริง** | ตัวเลขที่ยังไม่ได้ตรวจสอบ | ขั้นตรวจที่ 1 + ระบุ "ลูกค้าแจ้ง" |
| **AI เติมข้อมูล sector ทั่วไป** | ย่อหน้าที่ฟังดูดีแต่ไม่เกี่ยวกับเคสนี้ | สั่งห้ามเพิ่มข้อมูลที่ไม่ได้ให้ |

## 7. เคสจริง 1 เคส

*(ตัวเลขทั้งหมดเป็นของสมมติ)*

### สถานการณ์

เคสสินเชื่อกิจการแปรรูปสินค้าเกษตร ขอวงเงินหมุนเวียนเพิ่ม 5 ล้านบาท

ผลวิเคราะห์ที่ทำมาแล้ว: DSCR 1.18 · คู่ค้ารายใหญ่คิดเป็น 65% ของยอดขาย · รายได้โต 8% ต่อปี · เจ้าของดำเนินกิจการมา 11 ปี · statement แสดงเงินตึงช่วง มิ.ย.–ส.ค. ทุกปี

### ก่อน — ส่วน "ความเสี่ยง" และ "ข้อเสนอ" ที่ AI ร่างมา

> **6. ความเสี่ยงและการบริหารความเสี่ยง**
>
> 6.1 ความเสี่ยงด้านราคาวัตถุดิบ — ราคาวัตถุดิบทางการเกษตรมีความผันผวนตามฤดูกาลและสภาพอากาศ อย่างไรก็ตาม กิจการมีประสบการณ์ในการบริหารจัดการมายาวนาน จึงมีความสามารถในการปรับตัว
>
> 6.2 ความเสี่ยงด้านการแข่งขัน — ธุรกิจแปรรูปสินค้าเกษตรมีการแข่งขันสูง ทั้งนี้ กิจการมีความสัมพันธ์ที่ดีกับคู่ค้า จึงคาดว่าจะสามารถรักษาส่วนแบ่งตลาดได้
>
> 6.3 การบริหารความเสี่ยง — ธนาคารจะติดตามผลการดำเนินงานของกิจการอย่างใกล้ชิด และประเมินสถานการณ์เป็นระยะ
>
> **7. ข้อเสนอ**
>
> เห็นควรอนุมัติวงเงินหมุนเวียนเพิ่มเติม จำนวน 5,000,000 บาท อัตราดอกเบี้ย [...] ระยะเวลา 1 ปี ต่ออายุได้ โดยใช้หลักประกันเดิม
>
> เนื่องจากกิจการมีผลการดำเนินงานที่ดีอย่างต่อเนื่อง มีศักยภาพในการเติบโต และมีความสามารถในการชำระหนี้อยู่ในเกณฑ์ที่ยอมรับได้

### จับผิดอย่างไร

**ขั้นตรวจที่ 5 (เทียบความยาว)**

```
ส่วนจุดแข็งและเหตุผลสนับสนุน (ข้อ 2-4):  ประมาณ 60 บรรทัด
ส่วนความเสี่ยง (ข้อ 6):                  9 บรรทัด
```

**สัดส่วน 7:1** → สัญญาณชัดว่ายังไม่ได้คิดเรื่องความเสี่ยงจริง

**ขั้นตรวจที่ 4 (ประโยคที่พิสูจน์ไม่ได้)** — ในเก้าบรรทัดนั้น มีถึง 4 ประโยคที่ตัดได้

- "มีประสบการณ์ในการบริหารจัดการมายาวนาน จึงมีความสามารถในการปรับตัว" — **ไม่มีหลักฐาน** และเป็นการใช้ข้อดีมากลบความเสี่ยง
- "มีความสัมพันธ์ที่ดีกับคู่ค้า จึงคาดว่าจะสามารถรักษาส่วนแบ่งตลาดได้" — **ไม่มีหลักฐาน**
- "ติดตามอย่างใกล้ชิด และประเมินสถานการณ์เป็นระยะ" — **ไม่ใช่มาตรการ** ไม่มีใครรู้ว่าต้องทำอะไร เมื่อไร
- "มีศักยภาพในการเติบโต" — ตัดทิ้ง

**ขั้นตรวจที่ 6 (ความสอดคล้อง)** — **จับได้จุดที่ใหญ่ที่สุด**

ผลวิเคราะห์ที่เราทำมาระบุความเสี่ยงสำคัญสองข้อ

1. **คู่ค้ารายใหญ่ 65% ของยอดขาย**
2. **เงินตึงช่วง มิ.ย.–ส.ค. ทุกปี**

**ทั้งสองข้อไม่ปรากฏในส่วนความเสี่ยงเลย** แต่กลับมีความเสี่ยงทั่วไปเรื่องราคาวัตถุดิบและการแข่งขัน ซึ่งเป็นความเสี่ยงที่ใช้กับธุรกิจไหนก็ได้

AI เขียนความเสี่ยงจากความรู้ทั่วไปเกี่ยวกับ sector แทนที่จะเขียนจากผลวิเคราะห์ของเรา — เพราะเราไม่ได้สั่งให้มันใช้เฉพาะที่เราให้

**ตรวจต่อ:** ข้อ 7 เสนอวงเงิน 1 ปี ต่ออายุได้ หลักประกันเดิม **โดยไม่มีเงื่อนไขใดที่เกี่ยวกับความเสี่ยงทั้งสองข้อเลย**

**ขั้นตรวจที่ 3 (อ่านในบทบาทผู้อนุมัติ)**

คำถามที่จะถูกถามทันที
- "ลูกค้ารายนี้ขายให้ใครบ้าง สัดส่วนเท่าไร" → เรารู้ (65%) แต่ไม่ได้เขียน
- "เงินตึงช่วงไหน ให้วงเงินหมุนเวียนแล้วจะพอไหม" → เรารู้ แต่ไม่ได้เขียน
- "ถ้าคู่ค้ารายใหญ่หายไป จะเป็นอย่างไร" → เรามี stress test แต่ไม่ได้ใส่

**ทั้งสามคำถาม เรามีคำตอบอยู่แล้ว แต่ไม่ได้อยู่ในเมโม** — ซึ่งแปลว่าการวิเคราะห์ที่ทำมาทั้งหมดเสียเปล่า

### หลัง — ส่วนที่แก้แล้ว

> **6. ความเสี่ยงและการบริหารความเสี่ยง**
>
> **6.1 การกระจุกตัวของคู่ค้า** *(ความเสี่ยงหลักของเคสนี้)*
>
> ยอดขายของกิจการ **65% มาจากคู่ค้ารายเดียว** (โรงงาน ก.) คิดเป็นมูลค่าประมาณ [X] ล้านบาทต่อปี ที่เหลือกระจายใน 3 ราย
>
> จากการทดสอบภาวะวิกฤต (ข้อ 4.3) **หากคู่ค้ารายนี้ลดปริมาณรับซื้อลง 50% DSCR จะลดจาก 1.18 เหลือ 0.71** ซึ่งต่ำกว่าระดับที่ชำระหนี้ได้
>
> *ข้อมูลที่บรรเทาความเสี่ยง:* กิจการค้าขายกับคู่ค้ารายนี้ต่อเนื่องมา 7 ปี และตรวจสอบจาก statement พบว่าการชำระเงินสม่ำเสมอ ไม่เคยเกิน 35 วัน
>
> **มาตรการ:**
> - กำหนดเงื่อนไขให้ลูกค้ารายงานสัดส่วนยอดขายแยกตามคู่ค้า **ทุกไตรมาส**
> - หากสัดส่วนคู่ค้ารายใหญ่เกิน 75% หรือมีการเปลี่ยนแปลงเงื่อนไขการชำระเงิน **ให้ทบทวนวงเงินทันที**
> - RM เข้าพบทุกไตรมาส สอบถามสถานะความสัมพันธ์กับคู่ค้าโดยตรง
>
> **6.2 ความเสี่ยงด้านสภาพคล่องตามฤดูกาล**
>
> จาก statement 24 เดือนย้อนหลัง พบว่ากิจการมี**ยอดคงเหลือต่ำที่สุดในช่วง มิ.ย.–ส.ค. ทุกปี** (ต่ำสุด [X] บาท ในเดือน ก.ค. ปี [X]) ซึ่งเป็นช่วงนอกฤดูการผลิต
>
> *ข้อมูลที่บรรเทาความเสี่ยง:* เป็นรูปแบบที่เกิดซ้ำทุกปีและกิจการผ่านมาได้ทุกครั้งใน 3 ปีที่ผ่านมา ไม่ใช่ปัญหาเฉียบพลัน
>
> **มาตรการ:**
> - **กำหนดตารางชำระให้หลีกเลี่ยงงวดหนักในช่วง มิ.ย.–ส.ค.**
> - วงเงินหมุนเวียนที่เสนอครอบคลุมความต้องการในช่วงดังกล่าว (คำนวณในข้อ 7.2)
>
> **6.3 ความเสี่ยงด้านราคาวัตถุดิบ**
>
> จาก sensitivity analysis (ข้อ 4.4) **ราคาวัตถุดิบที่สูงขึ้น 10% ทำให้ DSCR ลดจาก 1.18 เหลือ 0.96**
>
> **มาตรการ:**
> - รายงานราคาวัตถุดิบเฉลี่ยที่ซื้อเข้า พร้อมงบการเงินรายปี
> - ทบทวนวงเงินหากต้นทุนวัตถุดิบเฉลี่ยสูงกว่าฐานที่ใช้วิเคราะห์เกิน 10% ติดต่อกัน 2 ไตรมาส
>
> **6.4 ประเด็นที่ยังไม่มีข้อมูลเพียงพอ**
>
> - ยังไม่ได้ตรวจสอบสัญญาซื้อขายกับคู่ค้ารายใหญ่ (ลูกค้าแจ้งว่าไม่มีสัญญาเป็นลายลักษณ์อักษร ใช้การสั่งซื้อเป็นครั้งคราว) — **เป็นข้อเท็จจริงที่เพิ่มความเสี่ยงในข้อ 6.1**
>
> **7. ข้อเสนอ**
>
> **7.1 วงเงินที่เสนอ**
> วงเงินหมุนเวียน 5,000,000 บาท ระยะเวลา 1 ปี ต่ออายุได้ หลักประกันเดิม
>
> **7.2 ที่มาของวงเงิน**
> คำนวณจากวงจรเงินสด [แสดงการคำนวณ] ครอบคลุมความต้องการเงินทุนหมุนเวียนสูงสุดในช่วง [เดือน] ซึ่งประมาณ [X] ล้านบาท
>
> **7.3 เงื่อนไขที่เสนอ**
> 1. รายงานสัดส่วนยอดขายแยกตามคู่ค้า ทุกไตรมาส ภายใน 30 วันนับจากสิ้นไตรมาส
> 2. รายงานราคาวัตถุดิบเฉลี่ย พร้อมงบการเงินรายปี
> 3. ทบทวนวงเงินเมื่อเข้าเงื่อนไขในข้อ 6.1 หรือ 6.3
> 4. จัดตารางชำระหลีกเลี่ยงช่วง มิ.ย.–ส.ค.
>
> **7.4 เหตุผลสนับสนุน**
> - DSCR 1.18 (คำนวณหลังหักภาษีและเงินถอนเจ้าของแล้ว — ข้อ 4.1)
> - รายได้เติบโตเฉลี่ย 8% ต่อปี ต่อเนื่อง 3 ปี (ข้อ 3.2)
> - เจ้าของดำเนินกิจการมา 11 ปี ผ่านภาวะราคาวัตถุดิบสูงในปี [X] มาแล้วโดยไม่ผิดนัดชำระ
> - ประวัติการชำระหนี้กับธนาคารปกติตลอด [X] ปี ไม่มีการค้างชำระ
>
> **7.5 ข้อจำกัดของการวิเคราะห์**
> ตัวเลขรายได้ในข้อ 3 ตรวจสอบได้จาก statement ประมาณ 86% ของที่แสดงในงบการเงิน ส่วนต่างเป็นรายการขายเงินสดที่ลูกค้าแจ้งว่าไม่ผ่านบัญชี ซึ่งยังไม่สามารถตรวจสอบได้

### ผลที่ต่างกัน

**ฉบับแรก** ผู้อนุมัติอ่านแล้วจะถามคำถามที่เรามีคำตอบอยู่แล้วแต่ไม่ได้เขียน ทำให้ดูเหมือนเราไม่ได้วิเคราะห์ ทั้งที่วิเคราะห์มาแล้ว

**ฉบับแก้** ผู้อนุมัติอ่านแล้วเห็นว่าเรารู้ว่าความเสี่ยงคืออะไร วัดได้เท่าไร และจะรู้ตัวเมื่อไรถ้ามันเกิดขึ้น

**และที่สำคัญที่สุด:** ถ้าเคสนี้มีปัญหาในอีกสองปีเพราะคู่ค้ารายใหญ่ถอนตัว

- ฉบับแรก: ไม่มีอะไรบอกว่าเรารู้ความเสี่ยงนี้ → คำถามคือ "ทำไมไม่เห็น"
- ฉบับแก้: มีบันทึกว่าเราเห็น วัดผล ตั้งเงื่อนไขติดตาม → คำถามเปลี่ยนเป็น "ระบบเตือนทำงานไหม" ซึ่งเป็นคำถามที่ต่างกันโดยสิ้นเชิง

  อย่างมีนัยสำคัญ / อย่างใกล้ชิด
- **ห้ามเขียนมาตรการแบบ "ติดตามอย่างใกล้ชิด"**
  ทุกมาตรการต้องระบุ: ทำอะไร / ความถี่ / เกณฑ์ที่ทำให้ต้องทบทวน
- ห้ามคำนวณตัวเลขใหม่ที่ไม่มีในที่ให้ไป
- ทุกตัวเลขต้องมีที่มากำกับในวงเล็บ
- ข้อมูลที่มาจากคำบอกเล่าลูกค้า ต้องเขียนว่า "ลูกค้าแจ้งว่า"

B. จำนวนบรรทัดของส่วนจุดแข็ง เทียบกับส่วนความเสี่ยง
C. ความเสี่ยงข้อไหนที่ไม่มีเงื่อนไขในข้อ 7 รองรับ
