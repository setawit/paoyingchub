# บทที่ 33 — Red team: ให้ AI สวมบทผู้อนุมัติ

> **กลุ่มเสี่ยง:** ตรวจง่าย · เสียหายน้อย — **ช่อง ①**
> บทนี้คือการใช้ AI ที่ให้ผลตอบแทนสูงที่สุดในภาค 3 และมีความเสี่ยงต่ำที่สุด
>
> *ตัวอย่างในบทนี้เป็นของสมมติ*

---

## 1. งานนี้คืออะไร ปกติทำอย่างไร ใช้เวลาเท่าไร

เมโมเขียนเสร็จแล้ว ก่อนส่งเข้าที่ประชุมพิจารณา ต้องรู้ว่าจะโดนถามอะไร และเราตอบได้ไหม

**เวลาที่ใช้แบบเดิม:** ส่วนใหญ่ไม่ได้ทำ หรืออ่านทวนเองซึ่งไม่เห็นจุดอ่อนของตัวเอง

**เวลาที่ใช้เมื่อมี AI ช่วย:** 30–45 นาที

### ทำไมบทนี้คุ้มที่สุด

**เพราะโหมดนี้กลับด้านความเสี่ยงทั้งหมดของการใช้ AI**

| โหมดปกติ (บทอื่น) | โหมด red team (บทนี้) |
|---|---|
| AI ผลิตของ เราตรวจ | เราผลิตของ AI โจมตี |
| ถ้ามันผิด ความผิดไหลเข้าเอกสาร | ถ้ามันถามผิด เราแค่ข้าม |
| ต้องระวังว่ามันจะแต่งข้อมูล | มันแต่งคำถามได้ ไม่เสียหาย |
| ความเสี่ยงสูง | **ความเสี่ยงเกือบเป็นศูนย์** |

**ขาลงแทบไม่มี ขาขึ้นสูงมาก** — และสิ่งที่ได้ไม่ใช่เมโมที่เขียนดีขึ้น แต่คือ **การค้นพบว่าเมโมยังไม่พร้อม ก่อนที่จะส่ง**

## 2. AI ช่วยตรงไหนได้ ตรงไหนช่วยไม่ได้

| ช่วยได้ดี | ช่วยไม่ได้ |
|---|---|
| หาช่องโหว่ในตรรกะของเมโม | รู้ว่าผู้อนุมัติคนนี้เป็นอย่างไร |
| ชี้ประโยคที่ไม่มีหลักฐาน | รู้วัฒนธรรมการพิจารณาขององค์กร |
| ถามคำถามที่เราเลี่ยงไม่คิด | รู้ว่าเคสไหนเคยถูกปฏิเสธเพราะอะไร |
| สวมบทบาทได้ทันทีและซ้ำได้ | รู้ว่าใครไม่ถูกกับใคร |
| ตรวจความสอดคล้องทั้งฉบับ | ประเมินว่าคำตอบเราดีจริงไหม |

### หลักที่ 1 — ป้อนเมโมทั้งฉบับ ไม่ใช่บางส่วน

จุดอ่อนที่สำคัญที่สุดมักไม่ได้อยู่ในย่อหน้าใดย่อหน้าหนึ่ง แต่อยู่ระหว่างย่อหน้า

- ตัวเลขในส่วนสรุปไม่ตรงกับในเนื้อหา
- ความเสี่ยงที่ระบุในข้อ 6 ไม่มีเงื่อนไขในข้อ 7 รองรับ
- ข้อสรุปที่ไม่ตามมาจากหลักฐานในย่อหน้าก่อนหน้า

**สิ่งเหล่านี้เห็นได้เฉพาะเมื่อดูทั้งฉบับ**

*(เครื่องมือในระบบองค์กรเท่านั้น — เมโมมีข้อมูลลูกค้าครบถ้วน)*

### หลักที่ 2 — สร้างบทบาทผู้อนุมัติให้เหมือนคนจริง

ความแม่นยำของคำถามขึ้นกับความชัดของบทบาท ไม่ใช่ความเก่งของเครื่องมือ

**สิ่งที่ต้องระบุ**
```
1. ประสบการณ์ในงานนี้กี่ปี รู้ sector นี้แค่ไหน
2. เขาให้ความสำคัญกับอะไรที่สุด
3. เขากังวลเรื่องอะไร
4. เคยปฏิเสธเคสแบบไหนมาก่อน ด้วยเหตุผลอะไร
5. คำถามที่เขาถามเป็นประจำ (ถ้าจดไว้ ให้ใส่เลย)
6. เขาอ่านเมโมละเอียดแค่ไหน
7. เวลาที่เขามีต่อเคส
```

**ข้อ 4 และ 5 มีค่าที่สุด** — ถ้าองค์กรมีบันทึกคำถามในที่ประชุมพิจารณา ให้เอามาใช้ และถ้าไม่มี ให้เริ่มจดตั้งแต่วันนี้

> **คำถามที่เคยถูกถามจริง คือวัตถุดิบที่ดีที่สุดสำหรับการซ้อมครั้งหน้า**

### หลักที่ 3 — ขอคำถามที่ตอบยากที่สุด พร้อมเหตุผลว่าทำไมถึงถาม

สั่งว่า

> "ถามคำถามที่ยากที่สุด 5 ข้อ ที่ถ้าฉันตอบไม่ได้ เคสนี้จะถูกตีกลับ เรียงจากยากที่สุด และ **บอกด้วยว่าผู้อนุมัติกำลังกังวลเรื่องอะไรอยู่จริงๆ เบื้องหลังคำถามนี้**"

**ส่วนที่ขีดเส้นใต้สำคัญที่สุด** เพราะคำถามในที่ประชุมพิจารณามักไม่ได้ถามในสิ่งที่อยากรู้ตรงๆ

*ตัวอย่าง:* คำถาม "ลูกค้ารายนี้ทำธุรกิจมากี่ปีแล้ว" ความกังวลจริงอาจเป็น "เขาเคยผ่านวิกฤตมาแล้วหรือยัง" ซึ่งถ้าเราตอบแค่จำนวนปี เราจะไม่ได้ตอบความกังวล

### หลักที่ 4 — ถ้าตอบไม่ได้ อย่าแก้คำตอบ ให้กลับไปหาข้อมูล

> ## **นี่คือหลักที่สำคัญที่สุดของบทนี้**

เมื่อ red team เจอคำถามที่เราตอบไม่ได้ มีสองทาง

| ทางที่ผิด | ทางที่ถูก |
|---|---|
| แก้เมโมให้ "ตอบคำถามนั้นได้" | กลับไปหาข้อมูลจริง |
| เพิ่มประโยคที่ทำให้ฟังดูมีคำตอบ | ถามลูกค้าเพิ่ม |
| ตัดส่วนที่ทำให้เกิดคำถาม | ยอมรับในเมโมว่ายังไม่มีข้อมูล |
| ใช้ภาษาที่กลบจุดอ่อน | เลื่อนการเสนอออกไป |

**ทางที่ผิดทำให้เมโมผ่านการประชุม แต่ปัญหายังอยู่** และเมื่อปัญหานั้นปรากฏในอีกสองปี เอกสารที่เราแก้ให้ "ตอบได้" จะกลายเป็นหลักฐานว่าเรารู้แล้วแต่กลบไว้

**การเขียนในเมโมว่า "ประเด็นนี้ยังไม่มีข้อมูลเพียงพอ อยู่ระหว่างดำเนินการ" ปลอดภัยกว่าการเขียนคำตอบที่เราพิสูจน์ไม่ได้มาก**

## 3. Input ที่ต้องเตรียมก่อนสั่งงาน

```
1. เมโมทั้งฉบับ
2. ผู้อนุมัติคือใคร              ตามหลักที่ 2
3. คำถามที่เคยถูกถามในอดีต      (มีค่าที่สุด)
4. จุดอ่อนที่เรารู้ตัว            บอกไปเลย
5. เคสคล้ายกันที่เคยถูกปฏิเสธ    และเหตุผล
6. บริบทของที่ประชุม            มีกี่เคส เวลาต่อเคสเท่าไร
```

**ข้อ 4 คนไม่กล้าบอก แต่ต้องบอก** — จุดที่เรารู้ว่าอ่อนคือจุดที่ควรถูกเจาะก่อน ไม่ใช่จุดที่ควรซ่อน

## 4. กลุ่มความเสี่ยง

**ตรวจง่าย · เสียหายน้อย** — เป็นการซ้อม ไม่มีอะไรออกไปข้างนอก

**ความเสี่ยงเดียว: ความมั่นใจปลอม**

ถ้าคำถามที่ AI ถามเป็นคำถามตามตำรา และเราตอบได้หมด เราจะเดินเข้าห้องประชุมด้วยความมั่นใจ แล้วเจอคำถามจริงที่ไม่เหมือนที่ซ้อมเลย

**วิธีกัน:** ขั้นตรวจที่ 1 — เทียบคำถามที่ได้กับคำถามที่เคยถูกถามจริง

## 5. วิธีตรวจ

### ขั้นที่ 1 — เทียบคำถามกับที่ผู้อนุมัติเคยถามจริง *(5 นาที)*

| ผล | แปลว่า | ทำอย่างไร |
|---|---|---|
| คล้ายกันมาก | บทบาทแม่น | ซ้อมต่อได้ |
| คล้ายบางส่วน | ขาดมิติบางอย่าง | เติมคุณสมบัติ สั่งใหม่ |
| ไม่เหมือนเลย | บทบาทผิด | **เขียนใหม่ทั้งหมด อย่าซ้อมต่อ** |

### ขั้นที่ 2 — นับว่าตอบไม่ได้กี่ข้อ *(15 นาที)*

ลองตอบทุกข้อจริงๆ โดย **พูดออกมา ไม่ใช่คิดในใจ**

| ตอบไม่ได้ | แปลว่า | ทำอย่างไร |
|---|---|---|
| 0 ข้อ | คำถามยังไม่แรงพอ | สั่งใหม่ให้แรงกว่านี้ |
| 1–2 ข้อ | ปกติ | ไปหาข้อมูลเพิ่ม |
| 3+ ข้อ | **เมโมยังไม่พร้อม** | **เลื่อนการเสนอ** |

### ขั้นที่ 3 — ตรวจว่าคำตอบอยู่ในเมโมหรืออยู่ในหัวเรา *(10 นาที)*

**นี่คือขั้นตรวจที่จับปัญหาที่พบบ่อยที่สุด**

สำหรับคำถามที่เราตอบได้ ถามต่อว่า **"คำตอบนี้อยู่ในเมโมไหม"**

| ผล | แปลว่า |
|---|---|
| อยู่ในเมโม | ✓ ดี |
| **อยู่ในหัวเรา แต่ไม่ได้เขียน** | **ต้องเขียนเพิ่ม** |

**เพราะผู้อนุมัติอ่านเมโม ไม่ได้อ่านหัวเรา** และในบางกรณีผู้อนุมัติอ่านเมโมโดยที่เราไม่ได้อยู่ในห้อง

จากประสบการณ์ ข้อนี้มักพบ 3–5 จุดในทุกเมโม — เรารู้คำตอบ แต่ลืมเขียน

### ขั้นที่ 4 — ให้ประเมินคำตอบแบบเจาะจง *(10 นาที)*

**ห้ามถามว่า "คำตอบนี้ดีไหม"** เพราะจะได้คำชม

สั่งว่า
```
ประเมินคำตอบนี้ในบทบาทผู้อนุมัติ:
1. จุดที่คุณจะไม่พอใจ
2. คำถามที่คุณจะถามต่อทันที
3. ส่วนที่ฟังเหมือนเลี่ยงคำถาม
4. ถ้าคุณเป็นผู้อนุมัติ คุณจะอนุมัติไหม เพราะอะไร

ห้ามชม ให้บอกเฉพาะจุดที่ยังไม่ดี
```

### ขั้นที่ 5 — ถามคำถามที่ไม่เกี่ยวกับเนื้อหา *(5 นาที)*

คำถามที่คนไม่ซ้อมและโดนบ่อย

```
- "เคสนี้ต่างจากเคส [X] ที่เคยมีปัญหาอย่างไร"
- "ถ้าไม่อนุมัติ ลูกค้าจะเป็นอย่างไร"
- "RM เคยไปดูกิจการเมื่อไร"
- "ถ้าเคสนี้มีปัญหา เราจะรู้ตัวเมื่อไร"
- "ทำไมต้องเป็นวงเงินนี้ ไม่ใช่น้อยกว่านี้"
- "ใครในทีมเคยทำ sector นี้มาก่อน"
```

**คำถามเหล่านี้ไม่ได้อยู่ในเมโม แต่มักเป็นคำถามที่ตัดสินว่าผ่านหรือไม่ผ่าน**

### ขั้นที่ 6 — ให้ตรวจความสอดคล้องทั้งฉบับ *(5 นาที)*

สั่งแยกต่างหาก
```
ตรวจเมโมนี้ว่ามี:
1. ตัวเลขที่ปรากฏหลายที่แล้วไม่ตรงกัน
2. ความเสี่ยงในข้อ 6 ที่ไม่มีเงื่อนไขในข้อ 7 รองรับ
3. ข้อสรุปที่ไม่มีหลักฐานในย่อหน้าก่อนหน้า
4. ประโยคที่พิสูจน์ไม่ได้
```

**รวมเวลา: 50 นาที**

## 6. จุดพลาดที่พบบ่อย

| จุดพลาด | ลักษณะ | วิธีกัน |
|---|---|---|
| **AI ถามตามตำรา ไม่ถามตามวัฒนธรรมองค์กร** | คำถามถูกต้องแต่ไม่ใช่ที่คนจะถาม | ขั้นตรวจที่ 1 + ใส่คำถามที่เคยถูกถามจริง |
| **แก้เมโมให้ "ตอบได้" แทนที่จะแก้ปัญหาจริง** | เมโมผ่าน ปัญหายังอยู่ | หลักที่ 4 |
| **เชื่อคำชมของ AI** | "เมโมนี้ครบถ้วนดีมาก" | ขั้นตรวจที่ 4 — สั่งห้ามชม |
| **คำถามไม่แรงพอ** | ตอบได้หมด เลยคิดว่าพร้อม | ถ้าตอบได้หมด = ยังไม่พอ |
| **ลืมว่าคำตอบต้องอยู่ในเมโม** | รู้คำตอบแต่ไม่ได้เขียน | ขั้นตรวจที่ 3 |
| **ซ้อมแต่คำถามเนื้อหา** | โดนคำถามเชิงบริบทแล้วตอบไม่ได้ | ขั้นตรวจที่ 5 |
| **ป้อนเมโมบางส่วน** | ไม่เห็นความไม่สอดคล้องระหว่างส่วน | ป้อนทั้งฉบับ |
| **ไม่บอกจุดอ่อนที่รู้ตัว** | AI ไม่เจาะจุดที่ควรเจาะ | บอกไปตรงๆ |

## 7. เคสจริง 1 เคส

*(ตัวอย่างสมมติ)*

### สถานการณ์

เมโมขออนุมัติวงเงินสำหรับกิจการแปรรูปสินค้าเกษตร เขียนเสร็จแล้ว ผ่านการตรวจตามบทที่ 24 มาแล้ว

### ผลจาก red team รอบแรก (บทบาทไม่ชัด)

สั่งว่า "สมมติคุณเป็นผู้อนุมัติสินเชื่อ ถามคำถามจากเมโมนี้"

ได้คำถาม
> 1. DSCR อยู่ในเกณฑ์ที่ยอมรับได้หรือไม่
> 2. หลักประกันเพียงพอหรือไม่
> 3. มีการวิเคราะห์ความเสี่ยงครบถ้วนหรือไม่
> 4. ลูกค้ามีประวัติการชำระหนี้อย่างไร
> 5. มีแผนติดตามอย่างไร

**ขั้นตรวจที่ 1** — เทียบกับคำถามที่ผู้อนุมัติของเราเคยถามจริง (จากบันทึกการประชุม)

คำถามที่เคยถูกถามจริง
- "RM ไปดูกิจการครั้งล่าสุดเมื่อไร เห็นอะไรบ้าง"
- "เคสนี้ต่างจากรายที่เป็น NPL เมื่อปีที่แล้วยังไง"
- "ตัวเลขนี้เอามาจากงบหรือจาก statement"
- "ถ้าเขาขายไม่ได้ตามที่คาด เราจะรู้เมื่อไร"

**ไม่เหมือนกันเลย** — คำถามที่ AI ถามเป็นคำถามเชิงหลักการ ส่วนที่ถูกถามจริงเป็นคำถามเชิงข้อเท็จจริงและเชิงเปรียบเทียบ

**ขั้นตรวจที่ 2** — ตอบได้หมดทั้ง 5 ข้อ ซึ่งตามเกณฑ์แปลว่าคำถามยังไม่แรงพอ

### รอบที่สอง — เขียนบทบาทใหม่

```
คุณเป็นผู้อนุมัติที่:
- ทำงานสินเชื่อเกษตรมา 18 ปี รู้ sector นี้ดีกว่าผม
- ปีที่แล้วมีเคสใน sector เดียวกันกลายเป็น NPL
  และเขาเป็นคนอนุมัติเอง → ระวังเป็นพิเศษกับเคสแบบนี้
- ไม่เชื่อตัวเลขที่ไม่รู้ที่มา จะถามเสมอว่า
  "เอามาจากงบหรือจาก statement"
- ให้ความสำคัญกับการที่ RM ได้ไปเห็นกิจการจริง
- อ่านเมโมละเอียด และจับได้เมื่อตัวเลขไม่ตรงกัน
- มี 15 เคสในวาระ มีเวลาต่อเคสประมาณ 8 นาที

คำถามที่เขาถามจริงในการประชุมครั้งก่อนๆ:
- "RM ไปดูกิจการครั้งล่าสุดเมื่อไร เห็นอะไรบ้าง"
- "เคสนี้ต่างจากรายที่เป็น NPL เมื่อปีที่แล้วยังไง"
- "ตัวเลขนี้เอามาจากงบหรือจาก statement"
- "ถ้าเขาขายไม่ได้ตามที่คาด เราจะรู้เมื่อไร"

จุดอ่อนที่ผมรู้ตัว:
- ตัวเลขรายได้ในเมโมมาจากงบ แต่ statement
  ยืนยันได้แค่ 86%
- ยังไม่ได้ไปดูกิจการรอบนี้ ใช้ข้อมูลจากการเข้าพบ 5 เดือนก่อน

ถามคำถามที่ยากที่สุด 5 ข้อ ที่ถ้าผมตอบไม่ได้
เคสนี้จะถูกตีกลับ เรียงจากยากที่สุด
แต่ละข้อบอกด้วยว่าเขากังวลเรื่องอะไรอยู่จริงๆ
```

### ผลจาก red team รอบที่สอง

> **1.** "ตัวเลขรายได้ 42 ล้านนี่ มาจากงบใช่ไหม แล้ว statement บอกเท่าไร ต่างกันเท่าไร แล้วส่วนต่างนั้นคืออะไร"
>
> *ความกังวลจริง: เคยเจอเคสที่งบสูงกว่าความจริงแล้วกลายเป็น NPL*
>
> **2.** "RM ไปดูกิจการครั้งล่าสุดเมื่อไร ตอนนั้นเห็นอะไร แล้วตอนนี้ยังเหมือนเดิมไหม"
>
> *ความกังวลจริง: กลัวว่าเมโมทำจากเอกสารอย่างเดียว ไม่ได้ไปเห็นของจริง*
>
> **3.** "เคสนี้ต่างจากรายที่เป็น NPL เมื่อปีที่แล้วยังไง ทั้งสองรายก็มีคู่ค้ารายใหญ่รายเดียวเหมือนกัน"
>
> *ความกังวลจริง: กลัวทำผิดซ้ำแบบเดิม และกลัวว่าเราไม่ได้เรียนรู้จากเคสนั้น*
>
> **4.** "เงื่อนไขที่เสนอมาว่าให้รายงานทุกไตรมาส ใครจะเป็นคนตรวจว่าเขาส่งมาจริง แล้วถ้าไม่ส่งจะเกิดอะไรขึ้น"
>
> *ความกังวลจริง: เคยเห็นเงื่อนไขในเมโมที่ไม่มีใครติดตามจริง*
>
> **5.** "ถ้าคู่ค้าหลักลดคำสั่งซื้อ เราจะรู้ตัวเมื่อไร — ก่อนหรือหลังจากที่เขาเริ่มค้างชำระ"
>
> *ความกังวลจริง: อยากรู้ว่าระบบเตือนภัยทำงานทันไหม*

### ผลการตอบ

| ข้อ | ตอบได้? | หมายเหตุ |
|---|---|---|
| 1 | ✓ ตอบได้ | **แต่คำตอบไม่ได้อยู่ในเมโม** (ขั้นตรวจที่ 3) |
| 2 | ✗ **ตอบไม่ได้** | ไปครั้งล่าสุด 5 เดือนก่อน ไม่รู้สถานะปัจจุบัน |
| 3 | ✗ **ตอบไม่ได้** | ไม่เคยเปรียบเทียบกับเคสนั้นเลย |
| 4 | ✗ **ตอบไม่ได้** | เขียนเงื่อนไขไว้แต่ไม่ได้คิดว่าใครจะตรวจ |
| 5 | ✓ ตอบได้บางส่วน | มีเงื่อนไขรายงานไตรมาส แต่ช้าไป |

**ตอบไม่ได้ 3 ข้อ → ตามเกณฑ์ขั้นตรวจที่ 2 แปลว่าเมโมยังไม่พร้อม**

### สิ่งที่ทำต่อ (หลักที่ 4 — หาข้อมูล ไม่ใช่แก้คำตอบ)

**ข้อ 1** *(ตอบได้แต่ไม่อยู่ในเมโม)*
→ เพิ่มในเมโม: "รายได้ตามงบ 42 ล้าน ตรวจสอบได้จาก statement 36.1 ล้าน (86%) ส่วนต่าง 5.9 ล้าน ลูกค้าแจ้งว่าเป็นการขายเงินสดที่ไม่ผ่านบัญชี ซึ่งยังไม่สามารถตรวจสอบได้ **การวิเคราะห์ความสามารถชำระหนี้ในข้อ 4 ใช้ตัวเลขที่ยืนยันได้ 36.1 ล้านเป็นฐาน**"

**ข้อ 2** *(ตอบไม่ได้)*
→ **ลงพื้นที่ใหม่ก่อนเสนอ** ใช้เวลา 1 วัน แต่แก้ปัญหาที่รากจริง
→ ได้ข้อมูลเพิ่มด้วย: พบว่าลูกค้าเพิ่มสายการผลิตใหม่ที่ไม่มีในเมโม

**ข้อ 3** *(ตอบไม่ได้)*
→ ไปดูแฟ้มเคสที่เป็น NPL แล้วเทียบ

พบความต่าง 3 ข้อที่ชัดเจน
```
1. เคสนั้นคู่ค้ารายใหญ่ 85% เคสนี้ 65%
2. เคสนั้นไม่มีสัญญาและคู่ค้าเปลี่ยนทุกปี
   เคสนี้ค้าขายกับรายเดิมต่อเนื่อง 7 ปี
3. เคสนั้นไม่มีเงื่อนไขติดตามสัดส่วนคู่ค้า
   → **จึงไม่มีใครรู้จนกระทั่งค้างชำระ**
```

→ เพิ่มหัวข้อในเมโม: **"การเปรียบเทียบกับเคสที่เคยมีปัญหาใน sector เดียวกัน"** พร้อมตารางเทียบ

**นี่คือหัวข้อที่ไม่มีใครสั่งให้เขียน แต่เป็นหัวข้อที่ตอบความกังวลจริงของผู้อนุมัติโดยตรง**

**ข้อ 4** *(ตอบไม่ได้)*
→ แก้เงื่อนไขในเมโมจาก
```
❌ "ให้ลูกค้ารายงานสัดส่วนยอดขายแยกตามคู่ค้าทุกไตรมาส"
```
เป็น
```
✅ "ให้ลูกค้ารายงานสัดส่วนยอดขายแยกตามคู่ค้า ภายใน 30 วัน
   นับจากสิ้นไตรมาส
   ผู้ติดตาม: RM ผู้ดูแลเคส
   กรณีไม่ส่งภายในกำหนด: RM ติดตามภายใน 7 วัน
   หากยังไม่ส่ง ให้รายงานผู้บังคับบัญชาและระงับการเบิกวงเงิน
   จนกว่าจะได้รับรายงาน"
```

**ข้อ 5** *(ตอบได้บางส่วน)*
→ เพิ่มกลไกที่เร็วกว่า: "ตรวจสอบรายการเงินเข้าจากคู่ค้าหลักใน statement **ทุกเดือน** หากไม่มีรายการเข้าจากคู่ค้ารายนี้ติดต่อกัน 2 เดือน ให้เข้าพบลูกค้าทันที"

→ ทำให้ระบบเตือนเร็วขึ้นจาก 3 เดือน (รายไตรมาส) เป็น 2 เดือน และไม่ต้องรอให้ลูกค้าส่งรายงาน

### ผลลัพธ์

**เมโมถูกเลื่อนออกไป 1 สัปดาห์** เพื่อลงพื้นที่และเพิ่มการวิเคราะห์เปรียบเทียบ

ในการประชุมจริง ผู้อนุมัติถามคำถามข้อ 1, 2 และ 3 **แบบเกือบตรงคำ**

ตอบได้ทั้งหมด และคำตอบข้อ 3 ที่มีตารางเปรียบเทียบกับเคส NPL อยู่ในเมโมแล้ว ทำให้ผู้อนุมัติเห็นทันทีว่าเราคิดถึงประเด็นนั้นแล้ว

**สิ่งที่ได้จากการซ้อมไม่ใช่การตอบที่ลื่นขึ้น แต่คือเมโมที่ดีขึ้นจริง** — ทั้งการลงพื้นที่ใหม่ การเปรียบเทียบกับเคสเก่า และเงื่อนไขที่ติดตามได้จริง ล้วนเป็นสิ่งที่ทำให้เคสนี้ปลอดภัยขึ้นจริง ไม่ใช่แค่ดูดีขึ้น

**เวลาที่ใช้: red team 50 นาที + ลงพื้นที่ 1 วัน + แก้เมโม 2 ชั่วโมง**

### รอบที่ 1 — สร้างคำถาม

```
บทบาท: ผู้อนุมัติสินเชื่อที่กำลังพิจารณาเมโมนี้

เมโม: [วางทั้งฉบับ]

**บทบาทของคุณ:**
- ประสบการณ์: [กี่ปี รู้ sector นี้แค่ไหนเทียบกับผม]
- สิ่งที่ให้ความสำคัญที่สุด: [...]
- สิ่งที่กังวล: [...]
- ประวัติ: [เคยปฏิเสธเคสแบบไหน / เคยมีเคสที่เป็น NPL
  ใน sector นี้ไหม]
- นิสัยการอ่านเมโม: [ละเอียด / ดูเฉพาะสรุป]
- เวลาที่มีต่อเคส: [X] นาที

**คำถามที่ผู้อนุมัติคนนี้เคยถามจริงในที่ประชุม:**
- "..."
- "..."
- "..."
(ถามในสไตล์เดียวกันนี้)

**จุดอ่อนที่ผมรู้ตัว (ให้เจาะตรงนี้ด้วย):**
- [...]
- [...]

**เคสคล้ายกันที่เคยมีปัญหา:**
- [เล่าคร่าวๆ]

สิ่งที่ต้องการ:

ถามคำถามที่ยากที่สุด 5 ข้อ ที่ถ้าผมตอบไม่ได้
เคสนี้จะถูกตีกลับ เรียงจากยากที่สุดลงมา

แต่ละข้อระบุ:
- คำถาม (ใช้ภาษาพูดแบบที่คนถามจริงในที่ประชุม)
- **ความกังวลที่แท้จริงเบื้องหลังคำถามนี้**
- ถ้าผมตอบแบบตื้นๆ เขาจะถามอะไรต่อ

เพิ่มอีก 3 คำถามที่ไม่ได้ถามเรื่องในเมโมโดยตรง
แต่เป็นคำถามที่ตัดสินว่าผ่านหรือไม่ผ่าน เช่น
- RM ไปดูกิจการเมื่อไร
- เคสนี้ต่างจากเคสที่เคยมีปัญหาอย่างไร
- ถ้ามีปัญหา เราจะรู้ตัวเมื่อไร

ข้อห้าม:
- ห้ามถามคำถามเชิงหลักการ
  ("DSCR อยู่ในเกณฑ์หรือไม่" / "วิเคราะห์ครบถ้วนหรือไม่")
- ห้ามถามอย่างสุภาพ ให้ถามแบบที่คนถามเวลาไม่เชื่อ
- ห้ามชมเมโม
```

### รอบที่ 2 — ตรวจความสอดคล้อง (สั่งแยก)

```
ตรวจเมโมนี้ทั้งฉบับ แล้วรายงาน:

1. ตัวเลขที่ปรากฏมากกว่าหนึ่งที่ และไม่ตรงกัน
   (ระบุตำแหน่งทั้งสองที่)
2. ความเสี่ยงที่ระบุในส่วนความเสี่ยง
   ที่ไม่มีเงื่อนไขในส่วนข้อเสนอรองรับ
3. ข้อสรุปหรือการตัดสินที่ไม่มีหลักฐาน
   ในย่อหน้าก่อนหน้ารองรับ
4. ประโยคที่พิสูจน์ไม่ได้
   (ใช้คำว่า "มีศักยภาพ" "มีแนวโน้ม" "มีความสัมพันธ์ที่ดี"
    โดยไม่มีตัวเลขกำกับ)
5. เงื่อนไขที่ไม่ได้ระบุว่าใครตรวจ ตรวจอย่างไร
   และถ้าไม่ปฏิบัติจะเกิดอะไร
6. ตัวเลขที่ไม่ได้ระบุว่ามาจากงบ statement หรือคำบอกเล่าลูกค้า

รายงานเป็นตาราง ระบุตำแหน่งในเมโมทุกข้อ
```

### รอบที่ 3 — ประเมินคำตอบ

```
[พิมพ์คำตอบของผมลงไป]

ประเมินในบทบาทผู้อนุมัติคนเดิม:
1. จุดที่คุณจะไม่พอใจ
2. คำถามที่คุณจะถามต่อทันทีหลังคำตอบนี้
3. ส่วนที่ฟังเหมือนเลี่ยงคำถามหรือตอบไม่ตรง
4. **คำตอบนี้อยู่ในเมโมหรือไม่**
   ถ้าไม่อยู่ ระบุว่าควรเพิ่มในส่วนไหน
5. ถ้าคุณเป็นผู้อนุมัติ คุณจะอนุมัติไหม เพราะอะไร

ห้ามชม ให้บอกเฉพาะจุดที่ยังไม่ดี
```

**ข้อ 4 ของรอบที่ 3 คือข้อที่จับปัญหาได้มากที่สุด** — คำตอบที่อยู่ในหัวเราแต่ไม่อยู่ในเมโม คือคำตอบที่ผู้อนุมัติไม่เห็น
