# บทที่ 20 — เขียน Call Report จากโน้ตดิบ

> **กลุ่มเสี่ยง:** ตรวจง่าย · เสียหายปานกลาง (เป็นเอกสารที่ติดตัวเคสไปตลอด)
>
> *ตัวเลขและเคสในบทนี้เป็นตัวเลขสมมติ*

---

## 1. งานนี้คืออะไร ปกติทำอย่างไร ใช้เวลาเท่าไร

กลับจากพบลูกค้า มีโน้ตที่จดหน้างาน ความจำที่ยังสด และรูปที่ถ่ายมา ต้องแปลงเป็น Call Report ที่เข้าแฟ้ม

**เวลาที่ใช้แบบเดิม:** 30–60 นาทีต่อเคส และมักเขียนตอนเย็นหรือวันถัดไป ซึ่งความจำเริ่มเลือน

**เวลาที่ใช้เมื่อมี AI ช่วย:** ร่าง 3 นาที + ตรวจ 15 นาที

**ทำไม Call Report สำคัญกว่าที่คนคิด:** มันคือเอกสารที่จะถูกอ่านโดย

- ตัวเราเองในอีกหกเดือน ตอนที่จำอะไรไม่ได้แล้ว
- RM คนถัดไปที่รับช่วงเคสนี้
- ผู้อนุมัติที่กำลังพิจารณาคำขอ
- ผู้ตรวจสอบที่มาดูย้อนหลัง

**และในสามกลุ่มหลัง ไม่มีใครถามเราได้ว่า "ตอนนั้นหมายความว่าอะไร"**

---

## 2. AI ช่วยตรงไหนได้ ตรงไหนช่วยไม่ได้

| ช่วยได้ดี | ช่วยไม่ได้ |
|---|---|
| เรียงโน้ตกระจัดกระจายให้เป็นโครง | รู้บรรยากาศตอนคุย |
| เปลี่ยนภาษาจดเป็นภาษาเขียน | รู้ว่าลูกค้าลังเลตอนตอบคำถามไหน |
| ดึงเรื่องติดตามออกมาเป็นรายการ | รู้ว่าสิ่งที่เห็นหน้างานผิดปกติหรือไม่ |
| ตรวจว่าครบตามโครงมาตรฐานไหม | แยกสิ่งที่ลูกค้าพูดกับสิ่งที่เราสรุปเอง |
| ถามหาข้อมูลที่ขาด | รู้ว่าเรื่องไหนต้องบันทึกให้ชัดเพื่อป้องกันตัว |

### หลักที่ 1 — แยก "ลูกค้าบอก" ออกจาก "เราสังเกต" ให้เด็ดขาด

นี่คือหลักที่สำคัญที่สุดของบทนี้

ใน Call Report ข้อมูลมีสามชนิดที่ต้องไม่ปนกัน

| ชนิด | คืออะไร | เขียนอย่างไร |
|---|---|---|
| **ลูกค้าบอก** | สิ่งที่ลูกค้าพูด | "ลูกค้าแจ้งว่า..." |
| **เราสังเกต** | สิ่งที่เราเห็นด้วยตา | "จากการสังเกตพบว่า..." |
| **เราประเมิน** | ความเห็นของเรา | "ผู้บันทึกเห็นว่า..." |

**ทำไมต้องแยก:** เพราะทั้งสามมีน้ำหนักต่างกันโดยสิ้นเชิงเมื่อมีคนอ่านย้อนหลัง

"ลูกค้ามียอดขายเดือนละ 800,000 บาท" กับ "ลูกค้าแจ้งว่ามียอดขายเดือนละ 800,000 บาท" — ประโยคแรกคือข้อเท็จจริงที่เราค้ำประกัน ประโยคที่สองคือคำกล่าวอ้างของลูกค้าที่เราบันทึกไว้

ถ้าตัวเลขนั้นผิดในภายหลัง ประโยคแรกคือปัญหาของเรา ประโยคที่สองไม่ใช่

**AI รวมสามอย่างนี้เป็นอย่างเดียวเสมอถ้าเราไม่สั่ง** เพราะในโน้ตเราจดปนกัน และภาษาเขียนทางการมีแรงดึงให้เขียนเป็นข้อเท็จจริงทั้งหมด

### หลักที่ 2 — จดโน้ตหน้างานให้ AI ใช้ต่อได้

ปรับวิธีจดเล็กน้อย ได้ผลลัพธ์ต่างกันมาก

```
[พูด]  = ลูกค้าพูด — ถ้าเป็นคำพูดสำคัญ จดแบบยกคำพูดเลย
[เห็น] = เราเห็นกับตา
[คิด]  = ความเห็นเรา
[?]    = ไม่แน่ใจ ต้องเช็ค
[ทำ]   = เรื่องต้องติดตาม
```

**ตัวอย่างโน้ตที่ใช้ได้ดี**

```
[พูด] ยอดขายเดือนละ 7-8 แสน ช่วง พ.ย.-ม.ค. ขึ้นเป็นล้าน
[พูด] "ปีนี้ราคาไม่ดีเท่าปีที่แล้ว แต่ปริมาณได้มากกว่า"
[เห็น] ลานกว้างประมาณ 2 ไร่ มีกองสินค้า 3 กอง กองละประมาณ 40-50 ตัน
[เห็น] รถบรรทุก 2 คัน ทะเบียนต่างจังหวัด กำลังลง
[เห็น] เครื่องชั่งใหม่ มีใบรับรองติดอยู่
[คิด] ดูคึกคักกว่าที่คาดจากตัวเลขในงบ
[?] เครื่องชั่งซื้อเมื่อไร ใช้เงินจากไหน
[ทำ] ขอสำเนาใบเสร็จค่าเครื่องชั่ง
[ทำ] ขอรายชื่อคู่ค้าหลัก 5 ราย
```

**สิ่งที่ต้องจดเสมอ:** ตัวเลขทุกตัวที่ลูกค้าพูด (จดตามที่ได้ยิน ไม่ปัด) · คำพูดที่สำคัญ (ยกมาเป็นคำพูด) · สิ่งที่เห็นด้วยตา · สิ่งที่ผิดจากที่คาด

**สิ่งที่คนลืมจดบ่อยที่สุด: สิ่งที่เห็นแต่ไม่ได้ถาม** เช่น รถคันใหม่ในลาน เครื่องจักรที่ไม่ได้เดิน สินค้าที่กองอยู่นานผิดปกติ — สิ่งเหล่านี้มีค่าในการวิเคราะห์มากกว่าคำตอบหลายข้อ

### โครง Call Report มาตรฐาน

```
1. ข้อมูลการเข้าพบ      วันที่ เวลา สถานที่ ผู้ที่พบ ตำแหน่ง
2. วัตถุประสงค์การเข้าพบ
3. สรุปข้อมูลที่ลูกค้าแจ้ง   (แยกชัดว่าลูกค้าบอก)
4. สิ่งที่พบจากการสังเกต    (แยกชัดว่าเราเห็น)
5. ประเด็นที่ยังไม่ได้ข้อมูล / ต้องตรวจสอบเพิ่ม
6. ความเห็นของผู้บันทึก     (แยกชัดว่าเป็นความเห็น)
7. เรื่องที่ต้องดำเนินการต่อ  (ใคร / อะไร / เมื่อไร)
```

**ข้อ 5 คือข้อที่คนข้ามบ่อยที่สุดและมีค่าที่สุด** เพราะมันบอกคนอ่านว่าอะไรที่ยังไม่รู้ ซึ่งสำคัญพอๆ กับสิ่งที่รู้

## 3. Input ที่ต้องเตรียมก่อนสั่งงาน

```
1. โน้ตดิบ พร้อมสัญลักษณ์กำกับ
2. วัตถุประสงค์การเข้าพบ
3. สิ่งที่ตั้งใจไปหาคำตอบ (จะได้เช็คว่าได้ครบไหม)
4. Call Report ครั้งก่อน (ถ้ามี) — เพื่อดูเรื่องติดตามที่ค้าง
5. โครงเอกสารมาตรฐานของ ธ.ก.ส.
```

> ### ⚠️ ข้อควรระวังสำคัญ
> **Call Report มีข้อมูลลูกค้าเต็มไปหมด — ชื่อ ตัวเลข ที่ตั้ง เงื่อนไข**
>
> **ห้ามใส่ในเครื่องมือนอกระบบองค์กรเด็ดขาด** (บทที่ 5)
>
> ถ้ามีเฉพาะเครื่องมือนอกระบบ ให้ใช้ได้เพียงการขอ **โครงเอกสารเปล่า** หรือ **รายการคำถามที่ควรถาม** เท่านั้น แล้วเขียนเนื้อหาจริงเองในเครื่ององค์กร

---

## 4. กลุ่มความเสี่ยง

**ตรวจง่าย** — เราเพิ่งกลับจากพบลูกค้า ความจำยังสด มีโน้ตอยู่ในมือ

**เสียหายปานกลาง — แต่เป็นความเสียหายชนิดพิเศษ**

Call Report ไม่ได้ทำให้ใครตัดสินใจผิดทันที แต่มันเป็น **เอกสารที่ติดตัวเคสไปตลอดอายุสัญญา** ความผิดพลาดใน Call Report จะ

- ถูกอ้างอิงในเมโมขออนุมัติ
- ถูกใช้โดย RM คนถัดไปที่ไม่เคยเจอลูกค้ารายนี้
- ถูกตรวจสอบย้อนหลังเมื่อเคสมีปัญหา

**และเมื่อเคสมีปัญหาในอีกสองปี Call Report คือหลักฐานว่าเรารู้อะไรและเมื่อไร**

ประโยคที่เขียนว่า "ธุรกิจมีแนวโน้มเติบโตดี" โดยไม่มีหลักฐานรองรับ จะกลายเป็นคำถามในวันที่เคสเป็น NPL

## 5. วิธีตรวจ

### ขั้นที่ 1 — ทุกตัวเลขในรายงาน ต้องมีในโน้ต *(4 นาที)*

ไล่ขีดเส้นใต้ตัวเลขทุกตัวใน Call Report แล้วย้อนหาในโน้ต

> **ถ้าตัวเลขไหนไม่มีในโน้ต แปลว่า AI แต่ง — ตัดทิ้งทันที**

ไม่มีทางอื่น ไม่มี "น่าจะใช่" เพราะเราไม่มีทางรู้ว่ามันเอามาจากไหน

**จุดที่ AI ชอบแต่งตัวเลข**
- ตัวเลขประมาณการที่เราจดคร่าวๆ แล้วมันทำให้เจาะจงขึ้น ("ประมาณ 40-50 ตัน" → "ประมาณ 45 ตัน")
- ตัวเลขที่คำนวณต่อจากที่เราจด (เราจดยอดรายเดือน มันคำนวณยอดรายปีให้)
- สัดส่วนและเปอร์เซ็นต์ที่เราไม่ได้พูดถึง

ตัวเลขกลุ่มที่สองไม่ได้ผิดเสมอไป แต่ต้องทำเครื่องหมายว่าเป็นการคำนวณ ไม่ใช่สิ่งที่ลูกค้าแจ้ง

### ขั้นที่ 2 — ทุกประโยค "ลูกค้าแจ้งว่า" ต้องเป็นสิ่งที่ลูกค้าพูดจริง *(4 นาที)*

ค้นหาคำว่า "ลูกค้าแจ้ง" "ลูกค้าให้ข้อมูล" "ตามที่ลูกค้าระบุ" แล้วเช็คทีละจุดกับโน้ต

**สิ่งที่ต้องดูสองทาง**

1. สิ่งที่เขียนว่าลูกค้าบอก ลูกค้าบอกจริงไหม
2. **สิ่งที่ลูกค้าบอกจริง ถูกเขียนเป็นข้อเท็จจริงหรือเปล่า** ← จุดนี้พลาดบ่อยกว่า

*ตัวอย่างที่ต้องแก้*

| ที่ AI เขียน | ควรเป็น |
|---|---|
| "กิจการมียอดขายเฉลี่ยเดือนละ 750,000 บาท" | "ลูกค้าแจ้งว่ามียอดขายเฉลี่ยเดือนละ 700,000–800,000 บาท" |
| "ลูกค้าไม่มีภาระหนี้กับสถาบันการเงินอื่น" | "ลูกค้าแจ้งว่าไม่มีภาระหนี้กับสถาบันการเงินอื่น (ยังไม่ได้ตรวจสอบ)" |
| "ธุรกิจมีคู่ค้าประจำ 5 ราย" | "ลูกค้าแจ้งว่ามีคู่ค้าประจำประมาณ 5 ราย ขอรายชื่อแล้ว อยู่ระหว่างรอ" |

### ขั้นที่ 3 — หาข้อมูลที่ AI เติมเข้ามาเอง *(3 นาที)*

อ่านทีละย่อหน้า ถามว่า **"ย่อหน้านี้มีอะไรที่ไม่ได้อยู่ในโน้ตบ้าง"**

**สิ่งที่ AI ชอบเติมมากที่สุดในงานนี้: ข้อมูลธุรกิจทั่วไปที่ฟังดูเหมือนข้อมูลของลูกค้ารายนี้**

*ตัวอย่าง:* เราจดว่าลูกค้าทำลานรับซื้อ AI เขียนมาว่า

> "ธุรกิจลานรับซื้อโดยทั่วไปมีวงจรเงินสดสั้น เนื่องจากรับซื้อและขายต่อภายในระยะเวลาไม่นาน อย่างไรก็ตาม ในช่วงฤดูกาลรับซื้อจะมีความต้องการเงินทุนหมุนเวียนสูง"

ประโยคนี้**ถูกต้องในเชิงทั่วไป** แต่มันไม่ใช่ข้อมูลของลูกค้ารายนี้ และเมื่อมันอยู่ใน Call Report คนอ่านจะเข้าใจว่าเป็นสิ่งที่เราพบจากการเข้าพบ

**กฎ:** Call Report บันทึกสิ่งที่เกิดขึ้นในการเข้าพบครั้งนั้น ความรู้ทั่วไปเกี่ยวกับ sector ไปอยู่ในเอกสารวิเคราะห์ ไม่ใช่ที่นี่

### ขั้นที่ 4 — เช็คน้ำเสียงเทียบกับโน้ต *(2 นาที)*

อ่านรวดเดียว แล้วถามว่า **"อ่านแล้วรู้สึกบวก/ลบ ตรงกับที่รู้สึกตอนอยู่หน้างานไหม"**

**AI เขียนบวกกว่าโน้ตเสมอ** เพราะภาษาเขียนทางการมีคำเชิงบวกเยอะกว่าภาษาจด และเพราะมันไม่ได้อยู่ในที่นั้น

*ตัวอย่าง:* โน้ตจดว่า `[คิด] ดูคึกคักแต่ตอบเรื่องสต็อกไม่ค่อยชัด` แต่ Call Report เขียนว่า "จากการสังเกตพบว่ากิจการมีการดำเนินงานอย่างคึกคัก มีรถบรรทุกเข้า-ออกตลอดเวลาที่เข้าพบ"

ส่วนที่ว่า "ตอบเรื่องสต็อกไม่ชัด" หายไป — **และนั่นคือส่วนที่มีค่าที่สุดในโน้ต**

### ขั้นที่ 5 — เช็คเรื่องติดตามให้ครบ *(2 นาที)*

```
□ เรื่องติดตามจาก Call Report ครั้งก่อน มีการรายงานผลไหม
□ เรื่องติดตามครั้งนี้ ครบตามที่จด [ทำ] ไว้ไหม
□ แต่ละเรื่องมี: ใครทำ / ทำอะไร / ภายในเมื่อไร ครบไหม
□ เรื่องที่ลูกค้ารับปากว่าจะส่งเอกสาร ระบุกำหนดไหม
```

**รวมเวลาตรวจ: 15 นาที**

## 6. จุดพลาดที่พบบ่อย

| จุดพลาด | ลักษณะ | วิธีกัน |
|---|---|---|
| **เติมข้อมูลธุรกิจทั่วไปเหมือนเป็นของลูกค้ารายนี้** | ย่อหน้าที่อ่านดูดีแต่ไม่ได้มาจากการเข้าพบ | ขั้นตรวจที่ 3 |
| **น้ำเสียงบวกเกินโน้ตจริง** | ความลังเลและข้อสงสัยหายไป | ขั้นตรวจที่ 4 |
| **เปลี่ยน "ลูกค้าบอก" เป็นข้อเท็จจริง** | เราไปค้ำประกันคำพูดของลูกค้า | ขั้นตรวจที่ 2 |
| **ทำตัวเลขประมาณให้เจาะจง** | "40-50 ตัน" → "45 ตัน" | ขั้นตรวจที่ 1 + สั่งให้คงช่วงตัวเลข |
| **ตัดสิ่งที่สังเกตเห็นแต่ไม่สำคัญในตอนนั้นทิ้ง** | ข้อมูลที่จะมีค่าในอีกหกเดือนหายไป | สั่งให้เก็บทุก [เห็น] ไว้ครบ |

### ก่อน — Call Report ที่ AI ร่างมา

> **3. สรุปข้อมูลจากการเข้าพบ**
>
> กิจการดำเนินธุรกิจลานรับซื้อมันสำปะหลัง ตั้งอยู่บนพื้นที่ประมาณ 3 ไร่ มีการดำเนินงานอย่างต่อเนื่อง ในปีนี้กิจการสามารถรับซื้อผลผลิตได้เพิ่มขึ้นประมาณ 25% เมื่อเทียบกับปีก่อน แสดงถึงศักยภาพในการขยายกิจการ
>
> กิจการมียอดขายเฉลี่ยเดือนละ 2.5 ล้านบาท และในช่วงฤดูกาลรับซื้อ (ธันวาคม–มีนาคม) ยอดขายเพิ่มขึ้นเป็นเดือนละ 5.5 ล้านบาท คิดเป็นยอดขายรวมต่อปีประมาณ 42 ล้านบาท
>
> กิจการจำหน่ายผลผลิตให้แก่โรงงานแป้งมันสำปะหลัง 2 แห่ง โดยมีความสัมพันธ์ทางการค้าที่ดีและต่อเนื่อง ทั้งนี้ ธุรกิจลานรับซื้อโดยทั่วไปจะมีความต้องการเงินทุนหมุนเวียนสูงในช่วงฤดูกาลรับซื้อ เนื่องจากต้องชำระค่าผลผลิตให้เกษตรกรเป็นเงินสด ขณะที่ได้รับชำระจากโรงงานในระยะเวลา 15–30 วัน
>
> **4. สิ่งที่พบจากการสังเกต**
>
> จากการสังเกตพบว่ากิจการมีความพร้อมด้านเครื่องมือและอุปกรณ์ มีเครื่องชั่งรถบรรทุกที่ได้รับการรับรองมาตรฐาน และมีรถบรรทุกสำหรับขนส่งจำนวน 2 คัน นอกจากนี้ยังมีการนำระบบบัญชีคอมพิวเตอร์มาใช้ในการบริหารจัดการ แสดงถึงการบริหารงานที่เป็นระบบ
>
> **6. ความเห็นของผู้บันทึก**
>
> กิจการมีศักยภาพในการดำเนินธุรกิจ มีการบริหารจัดการที่เป็นระบบ และมีแนวโน้มการเติบโตที่ดี เห็นควรพิจารณาสนับสนุนวงเงินตามที่ลูกค้าร้องขอ

อ่านแล้วเป็นมืออาชีพ ครบถ้วน เรียบร้อย — และมีปัญหา 9 จุด

### จับผิดอย่างไร

**ขั้นตรวจที่ 1 (ตัวเลขต้องมีในโน้ต)**

| ตัวเลขในรายงาน | ในโน้ต | ปัญหา |
|---|---|---|
| "เพิ่มขึ้นประมาณ 25%" | "20-30%" | ทำช่วงให้เป็นตัวเดียว |
| "ยอดขายเฉลี่ยเดือนละ 2.5 ล้าน" | "2-3 ล้าน" | เดียวกัน |
| "ฤดูกาล 5.5 ล้าน" | "5-6 ล้าน" | เดียวกัน |
| **"ยอดขายรวมต่อปีประมาณ 42 ล้านบาท"** | **ไม่มีเลย** | **AI คำนวณเอง** |

ตัวเลข 42 ล้านคือตัวที่อันตรายที่สุด เพราะมันจะถูกอ้างต่อในเมโม และไม่มีใครรู้ว่ามันมาจากการคำนวณโดยใช้ค่ากลางของช่วงที่ลูกค้าประมาณให้ ซึ่งซ้อนความคลาดเคลื่อนสองชั้น

**ขั้นตรวจที่ 2 ("ลูกค้าแจ้ง" หายไป)**

ทั้งรายงานไม่มีคำว่า "ลูกค้าแจ้งว่า" แม้แต่ครั้งเดียว ทั้งที่ข้อมูลในข้อ 3 เกือบทั้งหมดมาจากคำบอกเล่าของลูกค้า และยังไม่ได้ตรวจสอบกับเอกสารใดๆ เลย

**เท่ากับเรากำลังค้ำประกันตัวเลขทั้งหมดด้วยลายเซ็นของเราเอง**

**ขั้นตรวจที่ 3 (ข้อมูลที่เติมเอง)** — พบ 3 จุด

1. **"แสดงถึงศักยภาพในการขยายกิจการ"** — ไม่มีในโน้ต เป็นการตีความ และตีความผิดด้วย เพราะรับซื้อได้มากขึ้นในปีที่ราคาต่ำ อาจแปลว่ามูลค่ารวมไม่ได้เพิ่ม
2. **"มีความสัมพันธ์ทางการค้าที่ดีและต่อเนื่อง"** — ลูกค้าไม่ได้พูด เราไม่ได้สังเกต
3. **ย่อหน้าเรื่อง "ธุรกิจลานรับซื้อโดยทั่วไป..."** — ความรู้ทั่วไปเกี่ยวกับ sector ไม่ใช่ข้อมูลจากการเข้าพบ

**ขั้นตรวจที่ 4 (น้ำเสียง)** — **จับได้จุดที่ใหญ่ที่สุด**

ข้อสังเกตที่น่าห่วงที่สุดในโน้ตหายไปทั้งหมด

- `[คิด] เรื่องคู่ค้ากระจุกที่เจ้าเดียว 70% น่าห่วง` → ในรายงานกลายเป็น "มีความสัมพันธ์ทางการค้าที่ดี"
- `[พูด] "ช่วงนี้เงินตึงหน่อย"` → หายไปเลย
- `[?] ขอเพิ่มวงเงิน 3 ล้าน คำนวณมาจากอะไร ตอบไม่ชัด` → หายไป แต่ข้อ 6 กลับเสนอให้สนับสนุนตามที่ขอ

**จุดสุดท้ายคือความผิดพลาดที่ร้ายแรงที่สุด** — ลูกค้าตอบไม่ได้ว่าทำไมต้อง 3 ล้าน แต่รายงานเสนอให้อนุมัติ 3 ล้าน

**ขั้นตรวจที่ 5 (เรื่องติดตาม)** — ในร่างไม่มีข้อ 5 และข้อ 7 เลย ทั้งที่ในโน้ตมี `[?]` 3 ข้อ และ `[ทำ]` 4 ข้อ

### ถ้าไม่จับผิด จะเกิดอะไร

Call Report ฉบับแรกจะเข้าแฟ้ม แล้วเมื่อทำเมโมขออนุมัติ เราจะหยิบตัวเลข "ยอดขายต่อปี 42 ล้าน" มาใช้ — ตัวเลขที่ไม่มีใครเคยพูด

ความเสี่ยงเรื่องคู่ค้ากระจุกตัว 70% จะไม่ปรากฏในเอกสารไหนเลย และถ้าในอีกสองปีโรงงานรายนั้นเปลี่ยนเงื่อนไขจนลูกค้ามีปัญหา คำถามในการตรวจสอบจะเป็น **"ตอนเข้าพบ ไม่เห็นความเสี่ยงนี้เหรอ"**

เราเห็น — เราจดไว้ในโน้ตด้วยซ้ำ แต่มันหายไประหว่างทาง

**เวลาที่ใช้ตรวจและแก้ทั้งหมด: 22 นาที**

## 8. Prompt ตั้งต้น

> **ใช้กับเครื่องมือในระบบองค์กรเท่านั้น**

```
บทบาท: ผู้ช่วยจัดทำ Call Report

โน้ตจากการเข้าพบ:
[วางโน้ตดิบพร้อมสัญลักษณ์ [พูด] [เห็น] [คิด] [?] [ทำ] ]

วัตถุประสงค์การเข้าพบ: [...]
สิ่งที่ตั้งใจไปหาคำตอบ: [...]
เรื่องติดตามค้างจากครั้งก่อน: [...]

เรียบเรียงตามโครงนี้:
1. ข้อมูลการเข้าพบ
2. วัตถุประสงค์
3. ข้อมูลที่ลูกค้าแจ้ง (จาก [พูด] เท่านั้น)
4. สิ่งที่พบจากการสังเกต (จาก [เห็น] เท่านั้น)
5. ประเด็นที่ยังไม่ได้ข้อมูล (จาก [?] ทั้งหมด)
6. ความเห็นของผู้บันทึก (จาก [คิด] เท่านั้น)
7. เรื่องที่ต้องดำเนินการต่อ (จาก [ทำ] — ตาราง ใคร/อะไร/เมื่อไร)

ข้อกำหนดเด็ดขาด:

- ข้อมูลจาก [พูด] ต้องขึ้นต้นด้วย "ลูกค้าแจ้งว่า" หรือ
  "ลูกค้าระบุว่า" ทุกข้อ ห้ามเขียนเป็นข้อเท็จจริง
- คำพูดที่จดเป็นเครื่องหมายคำพูดในโน้ต ให้ยกมาทั้งประโยค
- ตัวเลขที่เป็นช่วง ("2-3 ล้าน") ต้องคงเป็นช่วง
  ห้ามทำเป็นตัวเดียวหรือค่าเฉลี่ย
- ห้ามคำนวณตัวเลขใหม่ที่ไม่มีในโน้ต
  (เช่น ยอดรายปีจากยอดรายเดือน)
- ห้ามเพิ่มข้อมูลใดๆ ที่ไม่มีในโน้ต
- ห้ามใส่ความรู้ทั่วไปเกี่ยวกับธุรกิจประเภทนี้
  ("ธุรกิจลานรับซื้อโดยทั่วไป...") เด็ดขาด
- ห้ามตัดข้อสังเกตเชิงลบหรือข้อสงสัยออก
  ทุก [คิด] และ [?] ต้องปรากฏในรายงาน
- ห้ามใช้คำว่า "มีศักยภาพ" "มีแนวโน้มที่ดี"
  "แสดงถึง" "มีความสัมพันธ์ที่ดี"
  เว้นแต่มีหลักฐานเฉพาะเจาะจงในโน้ตรองรับ
- ห้ามให้ความเห็นเรื่องการอนุมัติ ถ้าใน [?] ยังมี
  ประเด็นที่เกี่ยวกับวงเงินหรือความสามารถชำระค้างอยู่

ท้ายเอกสาร ให้ระบุแยกออกมา:
A. รายการข้อมูลที่ฉันจดไว้แต่ยังไม่ครบถ้วน
   (เช่น ตัวเลขที่ไม่มีหน่วย ช่วงเวลาที่ไม่ชัด)
B. คำถามที่ควรถามในการเข้าพบครั้งถัดไป
   จากช่องว่างในโน้ตครั้งนี้
```

**ส่วน A และ B เป็นส่วนที่ทำให้ Call Report ครั้งถัดไปดีขึ้น** — เก็บสะสมไปเรื่อยๆ จะกลายเป็นรายการคำถามประจำตัวของเราสำหรับ sector นั้น
