# Call Report Writer — ธกส. มาตรฐาน 301.02.05

## ภาพรวม

Skill นี้ทำ 4 งานหลัก:

| Mode | Trigger | Output |
|------|---------|--------|
| **DRAFT** | ข้อมูลดิบ / bullet / free-text | Call Report ฉบับร่าง ครบ 8 หัวข้อ |
| **EXPORT** | Draft ที่อนุมัติแล้ว | ไฟล์ `.docx` format 301.02.05 |
| **ANALYZE** | PDF/text Call Report เดิม | สรุปสถานะ + ประเด็นเสี่ยง |
| **ACTION** | Call Report ใดก็ได้ | Action Items + Deadline table |

---

## โครงสร้าง Call Report มาตรฐาน (Full Form)

Call Report ของ ธกส. แบบ Full Form มี **8 หัวข้อบังคับ** ดังนี้:

```
HEADER
  - แบบฟอร์ม 301.02.05
  - เรียน / เพื่อ (ทราบ / พิจารณา / สั่งการ)
  - วันที่เริ่มติดต่อ / ช่วงที่ติดต่อ
  - ครั้งที่ / ลูกค้าเป้าหมาย (รายเดิม/รายใหม่) / ผู้แนะนำ

SECTION 1: ข้อมูลลูกค้า
  - ชื่อ / ที่อยู่ / เบอร์ / อีเมล / ประเภทธุรกิจ

SECTION 2: เจ้าหน้าที่ธนาคาร + ลูกค้าที่พบ (แยกตามครั้ง)

SECTION 3: วัตถุประสงค์ครั้งนี้

SECTION 4: สรุปรายละเอียดการติดต่อ/เข้าพบ
  4.1 ข้อมูลทั่วไปและความเป็นมาของธุรกิจ
  4.2 ลักษณะของการดำเนินธุรกิจ (flow การผลิต/บริการ)
  4.3 วิเคราะห์ผลการดำเนินงานที่ผ่านมา
  4.4 วัตถุประสงค์และความจำเป็นครั้งนี้
  4.5 ประวัติการติดต่อกับธนาคารและสถาบันการเงินอื่น [ตารางหนี้ CSR]
  4.6 หลักประกันที่เสนอ
  4.7 คุณสมบัติผู้ขอสินเชื่อ
  4.8 เรื่องที่ต้องติดตาม

SECTION 5: สรุปความเห็น RM
SECTION 6: ความเห็น ผจธ. (ว่างไว้ให้ลงนาม)
SECTION 7: ความเห็น ผช.ธญ. (ว่างไว้ให้ลงนาม)
```

---

## MODE 1: DRAFT — เขียน Call Report จาก input ดิบ

### ขั้นตอน

**Step 1 — รับ input และระบุ Mode**

วิเคราะห์ว่า user ให้ข้อมูลมาในรูปแบบใด:
- **Bullet list** → map ตรงสู่แต่ละ section
- **Free-text เล่าสรุป** → extract ตามหมวด แล้วถามเพิ่มส่วนที่ขาด
- **ตอบสั้นแบบ Q&A** → ถามเป็นชุด (ดู Interview Guide ด้านล่าง)

**Step 2 — ถามข้อมูลที่ขาดหายก่อนเขียน**

ก่อนเขียน Draft ต้องมีข้อมูลขั้นต่ำดังนี้ครบ:

```
MUST HAVE (ขาดไม่ได้):
□ ชื่อลูกค้า / ประเภทธุรกิจ
□ วัตถุประสงค์การเข้าพบ (ติดตามหนี้ / นำเสนอสินเชื่อ / ติดตามงาน ฯลฯ)
□ ชื่อเจ้าหน้าที่ ธกส. ที่เข้าพบ
□ วันที่ / ช่วงเวลาที่ติดต่อ

NICE TO HAVE (เขียนได้ แต่จะ draft ส่วนนั้นเป็น [กรุณาระบุ]):
□ ข้อมูลธุรกิจและความเป็นมา
□ ข้อมูลหนี้ (วงเงิน / ภาระหนี้ / อัตราดอกเบี้ย / สถานะ)
□ หลักประกัน
□ เรื่องที่ต้องติดตาม / deadline
```

**Step 3 — เขียน Draft**

- ใช้ภาษาราชการสุภาพ เป็นทางการ ตามสไตล์ ธกส.
- ขึ้นต้นแต่ละ section ด้วยหัวข้อเลขตามโครงสร้างด้านบน
- ส่วน 4.1 ความเป็นมา → เขียนเป็นย่อหน้าบรรยาย ไม่ใช่ bullet
- ส่วน 4.2 การดำเนินธุรกิจ → บรรยาย flow แบบ step-by-step (ถ้า export docx จะทำ flowchart)
- ส่วน 4.5 ประวัติหนี้ → ใส่เป็นตาราง CSR (ถ้ามีข้อมูล)
- ส่วนที่ไม่มีข้อมูลให้ใส่ `[กรุณาระบุ]` หรือ `[RM กรอกเพิ่มเติม]`
- สรุปความเห็น RM → เขียนสรุปสถานการณ์ + แนวทาง 1 ย่อหน้า
- ส่วนลายเซ็น ผจธ. และ ผช.ธญ. → เว้นว่างไว้

### Interview Guide (ถามเป็นชุดเมื่อ input น้อยมาก)

```
ชุดที่ 1 — ข้อมูลพื้นฐาน:
- ลูกค้าชื่ออะไร / ประกอบธุรกิจอะไร / ที่อยู่จังหวัดไหน
- เข้าพบเมื่อไหร่ / ครั้งที่เท่าไหร่ / รายเดิมหรือรายใหม่

ชุดที่ 2 — วัตถุประสงค์และสถานการณ์:
- จุดประสงค์การเข้าพบคืออะไร (ติดตามหนี้ / นำเสนอสินเชื่อ / ตรวจเยี่ยม)
- ลูกค้ามีปัญหาอะไรบ้างในตอนนี้ / สถานการณ์ธุรกิจเป็นอย่างไร

ชุดที่ 3 — หนี้และหลักประกัน:
- มีวงเงินกี่สัญญา / แต่ละสัญญาวงเงินเท่าไหร่ / ภาระหนี้คงเหลือเท่าไหร่
- หลักประกันมีอะไรบ้าง

ชุดที่ 4 — Action Items:
- มีเรื่องอะไรที่ต้องติดตาม / deadline เมื่อไหร่
```

## MODE 2: EXPORT — สร้างไฟล์ .docx

เมื่อ user อนุมัติ Draft แล้วต้องการ export ให้:

1. อ่าน SKILL.md ของ `docx` skill ก่อน (`/mnt/skills/public/docx/SKILL.md`)
2. สร้างไฟล์ `.js` และรัน Node.js เพื่อสร้าง `.docx`
3. ใช้ format ตามข้อกำหนดด้านล่าง

### Format Spec สำหรับ Call Report .docx

```
กระดาษ: A4 (11906 x 16838 DXA)
Margin: บน/ล่าง/ซ้าย/ขวา = 1134 DXA (2cm)
Font: TH SarabunPSK หรือ Arial (fallback) ขนาด 14pt (28 half-points)
Line spacing: 1.15x

Header:
  - ขวาบน: "301.02.05" ตัวเล็ก
  - ตรงกลาง: "แบบรายงานการเข้าพบ/ติดต่อลูกค้า (Call Report)"
  - ตรงกลาง: "แบบ Full Form"

ตาราง Header Form:
  - ตาราง 2 คอลัมน์: ซ้าย (เรียน/เพื่อ) / ขวา (วันที่/ครั้งที่/ประเภท)
  - ตามด้วยตารางข้อมูลลูกค้า + เจ้าหน้าที่

Heading styles:
  - หัวข้อหลัก: Bold underline (เช่น "วัตถุประสงค์ครั้งนี้")
  - หัวข้อย่อย: Bold (เช่น "1. ข้อมูลทั่วไป...")

ตาราง CSR หนี้:
  - Header สีเทาอ่อน #D9D9D9
  - คอลัมน์: ลำดับ | ประเภทสัญญา | วงเงิน | ภาระหนี้ | อัตราดอกเบี้ย | สถานะ
  - แถวรวม: Bold

ส่วนลายเซ็น:
  - กล่องความเห็น ผจธ. และ ผช.ธญ. → ตาราง border ประกบ พร้อมเส้นลายเซ็น
```

### รูปแบบชื่อไฟล์

```
Call_report_[ชื่อลูกค้าย่อ]_[DDMMYY].docx
ตัวอย่าง: Call_report_955_กาวหนา_260314.docx
```

## MODE 3: ANALYZE — สรุปและวิเคราะห์ Call Report ที่มีอยู่

เมื่อ user แนบ Call Report (PDF หรือ text) ให้:

**Output template:**

```
## สรุป Call Report: [ชื่อลูกค้า]

**ข้อมูลพื้นฐาน**
- วันที่เข้าพบ: ...
- วัตถุประสงค์: ...
- เจ้าหน้าที่: ...

**สถานการณ์ธุรกิจ**
[สรุป 3-5 ประโยค: ธุรกิจทำอะไร / ปัญหาคืออะไร / แนวทางลูกค้า]

**สถานะหนี้**
[ตาราง: จำนวนสัญญา / วงเงินรวม / ภาระหนี้รวม / สถานะรวม]

**ประเด็นเสี่ยงที่ RM ควรระวัง**
[bullet ประเด็นเสี่ยงที่พบจากเนื้อหา]

**Sentiment ลูกค้า**
[ประเมิน: ให้ความร่วมมือ / มีความกังวล / ต้องการความช่วยเหลือ]
```

---

## MODE 4: ACTION — ดึง Action Items

**Output template:**

```markdown
## Action Items จาก Call Report: [ชื่อลูกค้า]

| # | Action | ผู้รับผิดชอบ | Deadline | สถานะ |
|---|--------|-------------|----------|-------|
| 1 | ...    | RM / ลูกค้า | DD/MM/YY | 🔴 Pending |
```

กฎการดึง Action Items:
- ค้นหาทุกประโยคที่มี "ต้องติดตาม", "ให้ดำเนินการ", "ภายในวันที่", "จะดำเนินการ"
- ระบุ deadline ที่ชัดเจน ถ้าไม่มีใส่ "-"
- ระบุว่าเป็น Action ของ RM หรือ ลูกค้า หรือ ทั้งสองฝ่าย

---

## ข้อควรระวัง (Quality Rules)

```
✅ ใช้ปีพุทธศักราช (พ.ศ.) เสมอ ไม่ใช่ ค.ศ.
✅ ชื่อหน่วยงานใน ธกส. ต้องถูกต้อง เช่น "ผช.ผอ.ธญ." ไม่ใช่ตัวย่ออื่น
✅ ราคา/ตัวเลขจากลูกค้าต้องใส่ตามที่ได้รับ ไม่เพิ่มเองเด็ดขาด
✅ ถ้าไม่มีข้อมูล → [กรุณาระบุ] ไม่ใช่เขียนตัวเลขสมมติ
✅ ภาษา: ราชการ สุภาพ กระชับ ไม่ใช้ภาษาพูด
✅ ตรวจสอบ CSR table ให้ครบทุก column ก่อน export
```

## ตัวอย่าง Input → Output

**Input (free-text):**
> "เข้าพบลูกค้า บริษัท ABC ทำโรงสับไม้ที่สุพรรณบุรี เมื่อวาน วัตถุประสงค์ติดตามหนี้คาบมีนา มีหนี้ 3 สัญญา รวมวงเงิน 34 ล้าน ลูกค้าขอ Restructure ภายใน 25 มีนา"

**Output: Draft ย่อ (Mode DRAFT)**
→ เขียน Draft Call Report Full Form ครบ 8 section
→ ส่วนที่ขาดข้อมูล ใส่ `[กรุณาระบุ]`
→ สรุปความเห็น RM อัตโนมัติจาก context ที่มี
→ ถามต่อ: "มีข้อมูลหนี้แต่ละสัญญา (เลขสัญญา วงเงิน ภาระหนี้) เพื่อทำตาราง CSR ไหมครับ?"
