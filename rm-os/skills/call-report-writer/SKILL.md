# Call Report Writer

ใช้ skill นี้เพื่อเปลี่ยน bullet notes หรือบันทึกย่อจากการเยี่ยมลูกค้า ให้กลายเป็น Call Report มาตรฐาน ธ.ก.ส. แบบ 301.02.05

## Inputs ที่ต้องดึงก่อนเขียน

ดึง fields เหล่านี้จาก request ของ RM — ถ้าไม่มีให้ infer จาก context หรือถามเฉพาะ field ที่จำเป็น

- `report_type`: `loan-disbursement` (RM-03) หรือ `debt-follow-up` (RM-03b)
- `visit_date`: วันที่เยี่ยม
- `customer_ref`: รหัสอ้างอิง (masked CIF หรือชื่อย่อที่ RM ระบุ)
- `visit_location`: สถานที่เยี่ยม (บ้าน / ที่นา / ร้าน / โทรศัพท์)
- `purpose`: วัตถุประสงค์การเยี่ยม
- `observations`: สิ่งที่พบเห็น — ธุรกิจ, ครัวเรือน, พืชผล, หลักประกัน
- `financial_status`: สถานะการเงิน — รายได้, รายจ่าย, ยอดค้างชำระ ถ้ามี
- `customer_statement`: สิ่งที่ลูกค้าพูด บอก หรือร้องขอ
- `rm_assessment`: ความเห็น RM ต่อสถานะลูกค้า
- `action_plan`: แผนงานต่อเนื่อง หรือนัดหมายถัดไป

## ประเภท Report และการเลือก mode

### RM-03 — จ่ายสินเชื่อ
ใช้เมื่อ RM เยี่ยมก่อน/หลังอนุมัติ หรือติดตามหลังจ่ายเงิน
- เน้น: วัตถุประสงค์การใช้เงิน, ความพร้อมของกิจการ, ความเสี่ยงที่พบ

### RM-03b — ติดตามหนี้
ใช้เมื่อ RM ติดตามลูกค้าที่มีหนี้ค้างหรืออยู่ระหว่างปรับโครงสร้าง
- เน้น: ยอดค้าง, สาเหตุ, แผนชำระ, ความร่วมมือของลูกค้า

## Core writing workflow

### 1. วิเคราะห์ context ก่อนเขียน

ก่อน draft กำหนด internally:
- ลูกค้าประเภทใด (เกษตร / SME / บุคคล)
- สถานะสินเชื่อ (ปกติ / จับตา / SM / NPL)
- ระดับความเสี่ยงที่ RM ประเมิน
- ข้อมูลสำคัญที่ขาดหาย (ถ้ามี ให้ mark ด้วย [RM กรุณาระบุ])

### 2. โครงสร้าง Call Report มาตรฐาน

เขียนตามลำดับนี้เสมอ:

**1. วัตถุประสงค์การเยี่ยม**
ระบุชัดว่าเยี่ยมเพื่ออะไร ติดตามอะไร

**2. ผลการเยี่ยม / สิ่งที่พบ**
บรรยายสิ่งที่พบเห็นจริง — กิจการ, ที่อยู่อาศัย, พืชผล, ทรัพย์สิน
ใช้ภาษาราชการที่กระชับ ตรงไปตรงมา

**3. สถานะการเงิน / การชำระหนี้**
ยอดค้างชำระ, รายได้ปัจจุบัน, ภาระหนี้รวม (ถ้ามีข้อมูล)

**4. ความเห็นและข้อเสนอแนะของ RM**
การประเมินความเสี่ยง, โอกาส, คำแนะนำที่ให้ลูกค้า

**5. แผนติดตามต่อเนื่อง**
วันนัดหมายถัดไป, action ที่ RM จะดำเนินการ

### 3. มาตรฐานภาษาและรูปแบบ

โหลดรายละเอียดจาก `references/language-standards.md`

กฎหลัก:
- ใช้ภาษาราชการกึ่งทางการ ไม่ใช้ภาษาปาก
- ระบุข้อเท็จจริงก่อน ตามด้วยความเห็น RM
- ตัวเลขต้องระบุหน่วยเสมอ (บาท, ไร่, ตัน, เดือน)
- ประโยคกระชับ ไม่ยืดยาวเกินความจำเป็น
- ใช้ราชาศัพท์เมื่อพูดถึงพระราชกรณียกิจ (ถ้ามีบริบท)

### 4. Calibrate ตามระดับความเสี่ยง

- **ปกติ / จับตาดู**: รายงานสั้น เน้น observation และ forward plan
- **SM / ใกล้ NPL**: รายงานละเอียด เน้น risk factors และ action plan ชัดเจน
- **NPL / ปรับโครงสร้าง**: รายงานยาว บันทึกทุก detail สำหรับ audit trail

### 5. Self-check ก่อน output

โหลด checklist จาก `references/output-checklist.md`

## Output format

```markdown
## Call Report ร่าง — [ประเภท] — [วันที่]

**วัตถุประสงค์การเยี่ยม**
[เนื้อหา]

**ผลการเยี่ยม / สิ่งที่พบ**
[เนื้อหา]

**สถานะการเงิน / การชำระหนี้**
[เนื้อหา]

**ความเห็นและข้อเสนอแนะของ RM**
[เนื้อหา]

**แผนติดตามต่อเนื่อง**
[เนื้อหา]

---
⚠️ นี่คือ draft เบื้องต้น — RM กรุณาตรวจสอบและแก้ไขก่อนบันทึกเป็นทางการ
[RM กรุณาระบุ]: รายการที่ต้องเติมข้อมูลเพิ่มเติม
```

## Failure modes ที่ต้องหลีกเลี่ยง

- เขียนข้อมูลที่ RM ไม่ได้บอก — ถ้าไม่รู้ให้ mark `[RM กรุณาระบุ]`
- ใช้ภาษาคลุมเครือที่ไม่ผ่าน audit (เช่น "ลูกค้าดูดี", "น่าจะโอเค")
- ละเว้น action plan — Call Report ทุกฉบับต้องมี next step
- ใส่ข้อมูลส่วนตัวที่ไม่จำเป็น — ใช้เฉพาะที่เกี่ยวกับสินเชื่อ
