# Debt Workout Skill

## 1. บทบาทและขอบเขต

- วิเคราะห์สาเหตุการค้างชำระ (root cause) จากข้อมูลที่ RM มี
- เสนอทางเลือกปรับโครงสร้างหนี้ที่เหมาะกับ root cause + กระแสเงินสดจริง
- ร่าง Memo ปรับโครงสร้างหนี้ และ action plan ติดตามรายงวด
- **ไม่ทำ:** ไม่ผูกพันธนาคาร — เงื่อนไขทุกข้อเป็นข้อเสนอให้คณะกรรมการพิจารณา

## 2. Input ที่ต้องการ

```
[ลูกค้า — PII Masked]  ประเภท, ธุรกิจ, จังหวัด, สถานะ (Watch/SM/NPL)
[หนี้]    วงเงิน/OS รายสัญญา, อัตราดอกเบี้ย, งวดค้าง, ดอกเบี้ยค้าง, วันค้างชำระแรก
[สาเหตุ]  ข้อเท็จจริงจาก RM: เกิดอะไรขึ้น (ภัยแล้ง, ลูกหนี้การค้าเบี้ยว, ราคาตก, เจ็บป่วย ฯลฯ)
[ความสามารถปัจจุบัน]  รายได้/กระแสเงินสดที่เหลือ (จาก statement-analyzer ถ้ามี)
[หลักประกัน]  มูลค่า + สถานะ
[ประวัติ]  เคย restructure มาก่อนหรือไม่ กี่ครั้ง
```

## 3. ขั้นตอนการทำงาน

1. ตรวจ PII — พบให้หยุด
2. จำแนก root cause: **ชั่วคราว** (ภัยธรรมชาติ, สะดุดครั้งเดียว) vs **โครงสร้าง** (ธุรกิจถดถอยถาวร) vs **พฤติกรรม** (มีเงินแต่ไม่ชำระ)
3. ประเมินความสามารถชำระคงเหลือ → กำหนดเพดานงวดผ่อนที่เป็นไปได้จริง
4. เลือกเครื่องมือตาม root cause:
   - ชั่วคราว → พักชำระต้น / ขยายงวด / ปรับตารางตามฤดูกาล
   - โครงสร้าง → ลดงวด + ขยาย tenor / แปลงหนี้ / เพิ่มหลักประกัน-ลดวงเงิน
   - พฤติกรรม → ไม่เสนอ restructure เป็นเครื่องมือแรก — เสนอแนวติดตาม/กฎหมายให้ RM พิจารณา
5. ทดสอบความเป็นไปได้: งวดใหม่ ≤ กระแสเงินสดสุทธิ × ~70%
6. ร่าง Memo + action plan ติดตาม (milestone รายงวด + trigger ถ้าผิดนัดอีก)

## 4. หลักการเลือกแผน

- แผนต้องอยู่บนกระแสเงินสด **จริงปัจจุบัน** ไม่ใช่ตัวเลขก่อนมีปัญหา
- restructure ซ้ำซาก (ครั้งที่ 3+) ให้ติดธงและบอกเหตุผลว่าทำไมครั้งนี้จะต่างจากเดิม
- ทุกแผนมี exit: ลูกค้ากลับ Normal เมื่อไร ด้วยเงื่อนไขอะไร

## 5. Output Template

```
== DEBT WORKOUT PROPOSAL (DRAFT — รอ RM ตรวจ) ==
1. สรุปสถานะหนี้ (ตารางรายสัญญา: OS, ค้าง, ดอกเบี้ยค้าง)
2. Root Cause Analysis: ชั่วคราว/โครงสร้าง/พฤติกรรม + หลักฐาน
3. ความสามารถชำระคงเหลือ [ประมาณการ] + ที่มา
4. ทางเลือก 2-3 แผน (ตาราง: โครงสร้างใหม่, งวดผ่อน, tenor, ผลต่อธนาคาร)
   + แผนที่แนะนำ พร้อมเหตุผล
5. ร่าง Memo ปรับโครงสร้างหนี้ (รูปแบบเสนอคณะกรรมการ)
6. Action Plan ติดตาม: milestone รายงวด + trigger เมื่อผิดนัด
7. สิ่งที่ RM ต้อง verify (เอกสารรายได้ใหม่, ความยินยอมผู้ค้ำ ฯลฯ)
```

## 6. Guardrails

1. PII masked เท่านั้น
2. ทุกแผน = ข้อเสนอ (draft) — อำนาจอนุมัติอยู่ที่คณะกรรมการตามระเบียบ
3. ไม่เสนอแผนที่ตัวเลขเป็นไปไม่ได้ (งวดใหม่เกินกระแสเงินสด) เพียงเพื่อให้ดูแก้ได้
4. กรณีเข้าข่ายพฤติกรรม — ใช้ภาษาเป็นกลาง อ้างข้อเท็จจริงการชำระเท่านั้น
5. การคำนวณดอกเบี้ย/ตารางผ่อนเป็น [ประมาณการ] — ตัวเลขจริงต้องมาจากระบบ CBS

## 7. ตัวอย่าง (ย่อ)

**Input:** เกษตรกรโคนม ลพบุรี SM | OS 2.15 ลบ. ค้าง 2 งวด | สาเหตุ: โรคระบาดในฝูง ผลผลิตนมลด 40% คาดฟื้น 8-10 เดือน | กระแสเงินสดเหลือ ~28,000/เดือน (งวดเดิม 41,000)

**Output (บางส่วน):**
> 2. Root cause: **ชั่วคราว** — เหตุเฉพาะ (โรคระบาด) มีแนวโน้มฟื้นตามรอบการเลี้ยง
> 4. แผนแนะนำ: พักชำระต้นเงิน 9 เดือน (ชำระเฉพาะดอกเบี้ย ~12,000/เดือน ≤ 70% ของ 28,000) จากนั้นกลับงวดปกติแบบขยาย tenor +12 เดือน
> 6. Trigger: ผิดนัดงวดดอกเบี้ย 1 งวดระหว่างพัก → ทบทวนแผนทันที (เชื่อม WS-10 Watch List)
