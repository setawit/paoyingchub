# ANONYMIZATION — กฎลบข้อมูลระบุตัวลูกค้า (PII Redaction)

ใช้เมื่อจะนำข้อมูลไป **เทรนโมเดล / สอนหนังสือ / ส่งต่อให้บุคคลภายนอก**
หลักการ: **ลบทุกอย่างที่ระบุตัวคนได้ แต่คงตัวเลขการเงินและวันที่ไว้ครบ** (เพราะคือสาระของการวิเคราะห์)

---

## 1. สิ่งที่ต้องลบ/แทนที่ด้วย Token

| ประเภทข้อมูล (PII) | วิธีจัดการ | ตัวอย่าง token |
|---|---|---|
| ชื่อ-นามสกุลบุคคล | แทนด้วย token คงที่ต่อคน | `PERSON_01`, `PERSON_02` |
| ชื่อบริษัท/ร้านค้า (คู่ค้า) | แทนด้วย token + ประเภท | `COMPANY_01 (ซัพพลายเออร์)` |
| เลขที่บัญชีธนาคาร | แทนทั้งก้อน | `ACCT_01` |
| เลขบัตรประชาชน / เลขผู้เสียภาษี | ลบทั้งหมด | `[ID_REDACTED]` |
| เบอร์โทรศัพท์ | ลบ | `[PHONE_REDACTED]` |
| อีเมล | ลบ | `[EMAIL_REDACTED]` |
| ที่อยู่ | ลบ | `[ADDR_REDACTED]` |
| เลขอ้างอิงรายการ (ที่สืบกลับตัวได้) | ลบ | `[REF_REDACTED]` |
| QR/PromptPay ID, e-Wallet ID | แทน | `WALLET_01` |
| เลขสาขา/รหัสเครื่อง EDC เฉพาะร้าน | ลบเฉพาะส่วนที่ระบุร้านได้ | `EDC_01` |

> **Token mapping** ต้องคงที่ภายในเอกสารเดียว (ชื่อเดียวกัน = token เดียวกันทุกที่) เพื่อให้ยัง track ความสัมพันธ์ได้ เช่น "โอนเข้า PERSON_03 แล้วโอนออก PERSON_03 ทันที" → ยังเห็น circular movement ได้

---

## 2. สิ่งที่ต้อง **คงไว้** (ห้ามลบ)
- จำนวนเงินทุกตัว (รวมทศนิยม)
- วันที่ / เวลา
- ทิศทาง (เข้า/ออก) และยอดคงเหลือ
- ประเภทช่องทาง (K SHOP, K PLUS, ฝากสด, K BIZ ฯลฯ) — เพราะใช้วิเคราะห์พฤติกรรม
- ชื่อธนาคาร และประเภทบัญชี

---

## 3. ข้อควรระวัง (Re-identification Risk)
- **ห้ามทิ้งร่องรอยในช่อง description:** บางครั้งชื่อคนแฝงอยู่ในหมายเหตุ เช่น "ค่าเช่า นายสมชาย" → ต้องกลายเป็น "ค่าเช่า PERSON_05"
- **ยอดเงินที่เฉพาะตัวมาก** (เช่น เงินเดือน 87,432.17 ซ้ำทุกเดือน) อาจ re-identify ได้ — ถ้าจะเผยแพร่กว้าง ให้พิจารณาใส่หมายเหตุเตือน หรือปรับ statement_id ไม่ให้โยงกลับลูกค้าจริง
- **ห้ามใช้เลขบัญชีจริงเป็น `statement_id`** ให้ตั้งรหัสใหม่ เช่น `STM-2026-001`
- ตั้ง `meta.anonymized: true` เสมอหลังทำเสร็จ
