## 0. ภาพรวม: สถาปัตยกรรม 3 ชั้น

| ชั้น | ไฟล์ | หน้าที่ | เปลี่ยนบ่อยแค่ไหน |
| --- | --- | --- | --- |

## 1. The Chapter Loop — วงจรเขียน 6 จังหวะ

```
[0] BRIEF → [A] ANGLE → [B] DRAFT → [C] MIRROR → [D] POLISH → [E] LEDGER ─┐
   (คน)      (AI+คน)      (AI)        (AI)         (AI+คน)      (AI+คน)    │
     ▲                                                                   │
     └──────────── อัปเดตความจำของเล่ม → ป้อนให้บทถัดไป ─────────────────────┘
```

| จังหวะ | ใครทำ | Input | Output | ด่านตรวจของคน |
| --- | --- | --- | --- | --- |
| **0 BRIEF** | ผู้เขียนรับผิดชอบบท | ความรู้ + Ledger | Chapter Brief (§2) | Brief ครบทุกช่องบังคับ |
| **A ANGLE** | AI เสนอ / คนเลือก | Brief + Ledger | 3 มุมเล่า + โครงร่าง | **คนต้องเลือก 1 มุม** ก่อนไปต่อ |
| **B DRAFT** | AI | มุมที่เลือก | ร่างเต็มบท 5 ส่วน | — |
| **C MIRROR** | AI (วิจารณ์ตัวเอง) | ร่าง | Scorecard + รายการแก้ | ดูคะแนนต่ำสุดก่อน |
| **D POLISH** | AI แก้ / คนตรวจ | ร่าง + รายการแก้ | ฉบับพร้อมส่งบรรณาธิการ | Editor Gate (§5) |
| **E LEDGER** | AI สกัด / คนยืนยัน | ฉบับสุดท้าย | ข้อมูลอัปเดต Ledger | คนกด merge เข้า Ledger |

**ทำไมต้องแยกจังหวะ?** เพราะถ้าสั่ง AI ทีเดียว "เขียนบทที่ 3 ให้หน่อย" จะได้เนื้อหาที่ *ถูก* แต่ *จืด*
— มุมเล่าคือจุดที่มนุษย์ต้องตัดสินใจ (Human + AI Collaboration ตั้งแต่ขั้นตอนการผลิต)

## 2. [0] BRIEF — แบบฟอร์ม Chapter Brief

> คนกรอก ไม่ใช่ AI — ถ้า Brief อ่อน ร่างจะอ่อนตาม ไม่มี prompt ไหนช่วยได้
> ช่องที่มี `*` คือช่องบังคับ ดูตัวอย่างที่กรอกแล้วได้ที่ [`03_EXAMPLE_CHAPTER_BRIEF.md`](03_EXAMPLE_CHAPTER_BRIEF.md)

```yaml
# ===== CHAPTER BRIEF =====
chapter_number*:        # เช่น 3
working_title*:         # ชื่อบทชั่วคราว (ต้องไม่ซ้ำชื่อบทของหนังสือต้นทาง)
part_of_book:           # ภาค/Part ที่บทนี้อยู่
owner*:                 # ผู้เขียนที่รับผิดชอบ

# --- ตำแหน่งในเรื่องเล่า ---
previous_chapter_bridge*: # บทก่อนหน้าจบด้วยคำถาม/ประเด็นอะไร (คัดจาก Ledger)
next_chapter_setup*:      # บทนี้ต้องปูอะไรให้บทถัดไป

# --- แก่นของบท ---
core_question*:         # คำถามเดียวที่บทนี้ตอบ เช่น "ทำไม Data เยอะแต่ยังไม่เข้าใจลูกค้า"
human_truth*:           # ความจริงเรื่องมนุษย์ที่ใช้เปิดบท (Human First) — ห้ามขึ้นต้นด้วยเทคโนโลยี
reader_shift*:          # อ่านจบแล้วผู้อ่านเปลี่ยนความคิดจาก "..." เป็น "..."

# --- ผู้อ่าน & ความลึก ---
depth_mix:              # สัดส่วน Beginner/Intermediate/Advanced เช่น 30/50/20
primary_reader:         # ผู้บริหาร / นักการตลาด / ทีม Data / เจ้าของ SME

# --- วัตถุดิบ ---
source_concepts*:       # แนวคิดที่ใช้ (ใส่เป็น "ไอเดีย" ไม่ใช่ข้อความคัดลอก) + แหล่งอ้างอิงสำหรับทีมภายใน
forbidden_terms:        # ชื่อบท/ชื่อ framework ของหนังสือต้นทางที่ห้ามใช้
thai_context*:          # อุตสาหกรรม/บริบทไทยที่จะเชื่อม เช่น ค้าปลีก, ธนาคาร, SME, LINE OA
example_type*:          # real (ต้องมีแหล่งอ้างอิง) | fictional (สร้าง case สมมติ)
example_seed:           # ไอเดียตั้งต้นของตัวอย่าง / ตัวละครประจำเล่มที่จะใช้ (ดู Ledger §3)

# --- ลายเซ็น ---
framework_to_create*:   # สิ่งที่อยากให้เป็น framework ใหม่ของบท (ยังไม่ต้องตั้งชื่อ ให้ AI เสนอ)
themes_to_reinforce*:   # เลือก ≥1: Learning System | Human + AI Collaboration | Trust & Transparency
insight_direction:      # มุมพลิก/ความเสี่ยงที่อยากให้เจาะ (ถ้ามี)

# --- ข้อจำกัด ---
target_length:          # เช่น 2,500–3,500 คำ
notes:                  # สิ่งอื่นที่ AI ต้องรู้
```

## 3. ชุด Prompt ของแต่ละจังหวะ

> **วิธีใช้:**
> 1. ใส่ `00_BOOK_DNA.md` เป็น System Prompt
> 2. คัดลอก prompt ของแต่ละจังหวะไปวาง แทนที่ `{{ตัวแปร}}` ด้วยข้อมูลจริง
> 3. ใช้ **แชตเดียวกัน** ตั้งแต่จังหวะ A ถึง D (AI จะจำบริบทได้) — เปิดแชตใหม่เฉพาะจังหวะ E

### 3.1 Prompt A — ANGLE (หามุมเล่า)

```text
คุณกำลังจะเขียนบทที่ {{chapter_number}} ของหนังสือ AI Marketing ตาม System Instruction ที่ให้ไว้

## ความจำของหนังสือ (Book Ledger — ย่อ)
{{วาง Ledger §1–§4 แบบย่อ: framework ที่มีแล้ว, punchline ที่ใช้แล้ว, ตัวละครประจำเล่ม, ศัพท์บัญญัติ}}

## Chapter Brief
{{วาง Chapter Brief ทั้งก้อน}}

## งานของคุณในขั้นนี้ (ยังไม่ต้องเขียนเนื้อหา)
1. คิดผ่าน 4 เลนส์ (Business / Human / System / Ethics) แล้วสรุปสั้น ๆ เลนส์ละ 1–2 บรรทัด
   ว่าบทนี้ "ต้องระวัง" หรือ "ต้องไม่พลาด" อะไร
2. เสนอ "มุมเล่า" 3 แบบที่ต่างกันจริง (ไม่ใช่แค่เปลี่ยนคำ) แต่ละมุมให้มี:
   - ชื่อมุม (1 วลี)
   - ประโยคเปิดที่ชวนคิด (1 ประโยค — ต้องเริ่มจากมนุษย์ ไม่ใช่เทคโนโลยี)
   - ชื่อ framework ใหม่ที่เสนอ + องค์ประกอบย่อ (ต้องไม่ซ้ำกับ framework ใน Ledger และ forbidden_terms)
   - ไอเดียตัวอย่าง (ระบุว่า real หรือ fictional)
   - Insight ที่ไม่ obvious ของมุมนี้
   - ข้อดี / ความเสี่ยงของมุมนี้ 1 บรรทัด
3. แนะนำว่ามุมไหนดีที่สุด พร้อมเหตุผล โดยใช้คำถามตัดสิน:
   "มุมไหนช่วยให้คนเข้าใจโลกและลูกค้าได้ลึกขึ้นจริง?"
4. สำหรับมุมที่แนะนำ ให้ร่างโครงร่าง (outline) ตาม 5 ส่วน:
   Concept → Breakdown → Example → Insight → Takeaway
   ระบุว่าแต่ละส่วนจะ reinforce theme ไหน ({{themes_to_reinforce}})

ตอบเป็น Markdown กระชับ แล้วรอให้ผมเลือกมุมก่อน — ห้ามเขียนร่างเต็มในขั้นนี้
```

> ✋ **ด่านตรวจของคน:** เลือกมุม (หรือผสม) แล้วแก้ชื่อ framework ให้ถูกใจก่อนไปจังหวะ B
> ถ้าไม่มีมุมไหน "ว้าว" ให้สั่ง: `ขออีก 3 มุมที่กล้ากว่านี้ โดยเฉพาะมุมที่ขัดกับความเชื่อทั่วไปของนักการตลาดไทย`

### 3.2 Prompt B — DRAFT (เขียนร่างเต็ม)

หัวข้อภาษาไทยในร่าง map กับ 5 องค์ประกอบใน DNA ดังนี้ (ใช้ชื่อเดียวกันทุกบท):

| DNA | หัวข้อในหนังสือ |
| --- | --- |
| Concept | แนวคิด |
| Breakdown | แตกภาพให้ชัด |
| Example | เห็นภาพจริง |
| Insight | มุมที่คนมักมองข้าม |
| Takeaway | สิ่งที่ต้องจำ (+ ลองถามองค์กรของคุณ) |

```text
ผมเลือกมุม: {{ชื่อมุมที่เลือก}}
การปรับเพิ่มเติม: {{ถ้ามี เช่น เปลี่ยนชื่อ framework เป็น ... / ใช้ตัวละคร ... จาก Ledger}}

เขียนร่างเต็มของบทที่ {{chapter_number}} ความยาว {{target_length}}
ตาม System Instruction ทุกข้อ และใช้โครงสร้าง Markdown นี้ "ตรงตามนี้":

---
# บทที่ {{chapter_number}}: {{ชื่อบท — ตั้งใหม่ ห้ามซ้ำหนังสือต้นทาง}}

> {{ประโยคเปิดที่ชวนคิด — เริ่มจากมนุษย์}}

## แนวคิด
(3–5 ย่อหน้า เชื่อมจากบทก่อน: "{{previous_chapter_bridge}}"
 อธิบายแก่นของบทแบบเล่าเรื่อง ไม่ขึ้นต้นด้วยนิยามแบบตำรา)

## แตกภาพให้ชัด
(framework ที่ตั้งชื่อใหม่ + ตารางหรือข้อย่อย ที่ทำให้ "เห็นภาพ"
 ต้องมีอย่างน้อย 1 ตาราง หรือ 1 แผนภาพแบบ text)

## เห็นภาพจริง
(ตัวอย่างแบบ {{example_type}} ในบริบท {{thai_context}}
 - ถ้า real: ทุกข้อเท็จจริงต้องมี [อ้างอิง: ...] หรือ [ต้องตรวจสอบ]
 - ถ้า fictional: ขึ้นหัวว่า "กรณีสมมติ" และตัวเลขทุกตัวระบุว่าเป็นตัวเลขสมมติ
 เล่าเป็นเรื่อง มีคน มีปัญหา มีการตัดสินใจ มีผลลัพธ์ — ไม่ใช่ bullet list)

## มุมที่คนมักมองข้าม
(Insight ที่ไม่ obvious อย่างน้อย 1 ข้อ ในรูปแบบใดแบบหนึ่ง:
 พลิกมุม / เตือนความเสี่ยง / เชื่อมบริบทไทย
 ต้องมีมุม Ethics หรือ Trust & Transparency อย่างน้อย 1 ย่อหน้า)

## สิ่งที่ต้องจำ
(1–3 ประโยค อย่างน้อย 1 ประโยคเป็น punchline ที่คนอยากจดหรือแชร์)

### ลองถามองค์กรของคุณ
(คำถาม 3 ข้อให้ผู้อ่านนำไปใช้กับองค์กรตัวเอง — ข้อละ 1 บรรทัด
 ไล่ระดับ: ผู้เริ่มต้น → ผู้ปฏิบัติ → ผู้วางระบบ)

---
→ *ปูทางสู่บทถัดไป:* {{1–2 ประโยคที่ส่งต่อไปยัง "{{next_chapter_setup}}"}}
---

กฎเพิ่มเติมสำหรับร่างนี้:
- คำอังกฤษใช้เฉพาะที่จำเป็น ครั้งแรกที่ใช้ศัพท์เทคนิค ให้อธิบายเป็นภาษาคนในวงเล็บ
- ใช้ศัพท์บัญญัติให้ตรงกับ Ledger (ห้ามแปลศัพท์เดียวกันต่างกันในแต่ละบท)
- ห้ามใช้ประโยค punchline ซ้ำกับที่อยู่ใน Ledger
- ความยาวย่อหน้าไม่เกิน 5–6 บรรทัด อ่านบนมือถือแล้วไม่เหนื่อย
- ห้ามปิดบทด้วยคำคมลอย ๆ ต้องปิดด้วยสิ่งที่ผู้อ่านเอาไปทำต่อได้
```

### 3.3 Prompt C — MIRROR (ส่องกระจก: AI วิจารณ์ร่างตัวเอง)

```text
ตอนนี้ให้คุณเปลี่ยนบทบาทเป็น "บรรณาธิการอาวุโสที่เข้มงวดที่สุด"
ซึ่งไม่ได้เป็นคนเขียนร่างนี้ และมีหน้าที่หาจุดอ่อน ไม่ใช่ชม

ตรวจร่างบทที่ {{chapter_number}} ด้านบน แล้วตอบ 3 ส่วน:

### ส่วนที่ 1: Scorecard (1–5 คะแนน พร้อมหลักฐานจากตัวบท)
| # | เกณฑ์ | คำถามตรวจ | คะแนน | หลักฐาน (อ้างประโยค) | ต้องแก้อะไร |
|---|---|---|---|---|---|
| 1 | Human First | ย่อหน้าแรกเริ่มจากมนุษย์ ไม่ใช่เทคโนโลยี? | | | |
| 2 | Clarity | คนไม่มีพื้นเทคนิคอ่านเข้าใจไหม? มี jargon หลุดไหม? | | | |
| 3 | Insight | มีอย่างน้อย 1 ความคิดที่ผู้อ่าน "ไม่เคยคิดมาก่อน"? | | | |
| 4 | Structure | ครบ 5 ส่วน + แต่ละส่วนทำหน้าที่ของมันจริง? | | | |
| 5 | Example | ตัวอย่างเห็นภาพ มีคน มีการตัดสินใจ? ติดป้าย real/สมมติถูกต้อง? | | | |
| 6 | Thai Context | คนไทยอ่านแล้วรู้สึก "นี่เรื่องของเรา"? | | | |
| 7 | Depth Balance | มีของให้ทั้ง Beginner / Intermediate / Advanced? | | | |
| 8 | Continuity | เชื่อมบทก่อน-หลัง + reinforce theme ที่กำหนด? | | | |
| 9 | Signature | มี punchline ที่จำได้ + framework ชื่อใหม่? | | | |
| 10 | Originality | มีส่วนไหนเสี่ยงคล้ายข้อความ/ชื่อบท/framework ของหนังสือต้นทาง? | | | |
| 11 | Factual Integrity | มีตัวเลข/ชื่อ/คำพูดที่อาจถูกแต่งขึ้นโดยไม่ติดป้ายไหม? | | | |
| 12 | Ethics Lens | ชี้ความเสี่ยงของการใช้ AI กับลูกค้าอย่างตรงไปตรงมาไหม? | | | |

### ส่วนที่ 2: 4-Lens Stress Test
ตอบเลนส์ละ 1 ย่อหน้า จากมุมผู้อ่านจริง:
- Business: ผู้บริหารอ่านจบแล้วตัดสินใจอะไรได้ดีขึ้น? ถ้าไม่ได้ ขาดอะไร?
- Human: ลูกค้าปลายทางจะรู้สึกยังไง ถ้าองค์กรทำตามบทนี้?
- System: สิ่งที่บทนี้แนะนำ ทำซ้ำ/สเกลได้จริงไหม?
- Ethics: มีอะไรที่ถ้าทำตามแบบไม่ระวัง จะทำร้ายความไว้ใจของลูกค้า?

### ส่วนที่ 3: รายการแก้ (เรียงตามความสำคัญ)
- 🔴 ต้องแก้ (ผิดกฎ DNA / เสี่ยงลิขสิทธิ์ / ข้อมูลไม่ได้ติดป้าย / คะแนนข้อใด ≤ 2)
- 🟡 ควรแก้ (คะแนน 3 / จืด / ยาวเกิน)
- 🟢 ข้อเสนอเสริม (ทำให้ดีขึ้นอีกขั้น)

ปิดท้ายด้วยคำตัดสิน 1 บรรทัด:
```

## 4. Micro-Prompts — คำสั่งสั้นสำหรับแก้เฉพาะจุด

ใช้ในแชตเดียวกับร่าง เมื่อต้องการแก้เฉพาะส่วนโดยไม่ต้องวนทั้งลูป

| สถานการณ์ | คำสั่ง |
| --- | --- |
| ประโยคเปิดจืด | `เสนอประโยคเปิดใหม่ 5 แบบ: คำถามชวนคิด / ข้อเท็จจริงที่ขัดสามัญสำนึก / ฉากสั้น ๆ จากชีวิตจริง / ความเชื่อผิดที่คนไทยมักมี / ภาพเปรียบเทียบ — ทุกแบบต้องเริ่มจากมนุษย์` |
| Punchline ไม่ติดหู | `เสนอ punchline ใหม่ 5 แบบ สั้นไม่เกิน 15 คำ ใช้โครงสร้าง "ไม่ใช่ X แต่คือ Y" / คู่ตรงข้าม / สัมผัสคำ อย่างละอย่างน้อย 1 แบบ ห้ามซ้ำกับ Ledger` |
| ศัพท์เทคนิคเยอะไป | `หาทุกคำ/วลีในบทที่คนไม่มีพื้นเทคนิคอาจไม่เข้าใจ แล้วเสนอคำแทนที่เป็นภาษาคน เป็นตาราง: คำเดิม / คำใหม่ / เหตุผล` |
| ตัวอย่างไม่ไทย | `ย้ายตัวอย่างในส่วน "เห็นภาพจริง" ไปอยู่ในบริบท {{อุตสาหกรรมไทย}} ให้มีรายละเอียดที่คนไทยคุ้น (ช่องทาง พฤติกรรม เทศกาล ภาษา) แต่ยังคงแก่นของบทเดิม` |
| Framework ชื่อไม่ติด | `เสนอชื่อ framework ใหม่ 5 แบบ: ภาษาไทยล้วน / ตัวย่อภาษาอังกฤษที่ออกเสียงได้ / อุปมา / ตัวเลข+คำ / คำกริยา — ต้องจำได้ใน 1 ครั้ง และไม่ชนกับ Ledger หรือหนังสือต้นทาง` |
| ลึกไม่พอสำหรับ Advanced | `เพิ่มกล่อง "สำหรับผู้วางระบบ" ไม่เกิน 150 คำ อธิบายว่าจะต่อยอด framework นี้เป็นระบบในองค์กรอย่างไร (ข้อมูลที่ต้องมี / วงจร feedback / ตัวชี้วัด)` |
| ง่ายไปสำหรับ Beginner | `เพิ่มภาพเปรียบเทียบ 1 ภาพ ในส่วน "แนวคิด" ที่ทำให้คนไม่เคยทำการตลาดเข้าใจได้ใน 10 วินาที` |

## 5. Editor Gate — ด่านตรวจของมนุษย์ก่อนปิดบท

> AI วิจารณ์ตัวเองได้ แต่ **คนต้องเป็นผู้ตัดสินสุดท้าย** (Human + AI Collaboration)
> ต้องผ่าน **ทุกข้อในกลุ่ม 🔒** และ **ข้อ ☐ อย่างน้อย 6 จาก 8**

**🔒 ข้อบังคับ (ไม่ผ่าน = ไม่ปิดบท)**
- [ ] ไม่มีข้อความคัดลอก / ชื่อบท / ชื่อ framework ที่ตรงกับหนังสือต้นทาง
- [ ] ทุกข้อเท็จจริงจาก case จริงมีแหล่งอ้างอิงที่ **คนเปิดดูแล้ว** (ไม่ใช่แค่ AI บอก)
- [ ] case สมมติและตัวเลขสมมติติดป้ายชัดเจน
- [ ] ไม่มี `[ต้องตรวจสอบ]` ค้างอยู่ในฉบับสุดท้าย
- [ ] ครบ 5 ส่วน: แนวคิด / แตกภาพให้ชัด / เห็นภาพจริง / มุมที่คนมักมองข้าม / สิ่งที่ต้องจำ

**☐ ข้อคุณภาพ**
- [ ] อ่านย่อหน้าแรกแล้ว "อยากอ่านต่อ"
- [ ] อธิบายแก่นของบทให้เพื่อนที่ไม่ใช่นักการตลาดฟังได้ใน 30 วินาที
- [ ] มีอย่างน้อย 1 ความคิดที่ผู้ตรวจเองก็ "ไม่เคยคิดแบบนี้มาก่อน"
- [ ] framework ใหม่วาดลงกระดาษได้ภายใน 1 นาที
- [ ] punchline จำได้หลังปิดหน้าไป 10 นาที
- [ ] ตัวอย่างทำให้ "เห็นหน้าคน" ไม่ใช่แค่เห็นตัวเลข
- [ ] เชื่อมกลับมาที่มนุษย์ในย่อหน้าปิด
- [ ] ผ่านคำถามสุดท้าย: *"มันช่วยให้คนเข้าใจโลกและลูกค้าได้ลึกขึ้นจริงไหม"*
