## 1. เปิดห้อง + วางกติกา (0–5 นาที)

พูดประเด็นนี้ให้ชัดตั้งแต่นาทีแรก เพราะเป็นหัวใจของทั้งคาบ:

> "วันนี้เราไม่ได้มาเรียนเขียนโปรแกรม เราจะไม่แตะโค้ดสักบรรทัด
> สิ่งที่จะฝึกคือ **การแจ้งอาการให้ AI เข้าใจ** และ **การซ่อมเครื่องมือด้วย AI**
> เพราะในชีวิตจริง เมื่อ dashboard ตัวนี้ถูกส่งไปสาขา B–Z แล้วมีปัญหา
> ไม่มีใครเรียกโปรแกรมเมอร์มาซ่อมให้ — ทุกคนต้องซ่อมเองด้วย AI"

ย้ำกติกา 2 ข้อ: (1) ห้ามแนบไฟล์ลูกค้าจริง (2) เก็บไฟล์เก่าไว้เสมอก่อนขอไฟล์ใหม่

## 2. สาธิตสด: dashboard ทำงาน offline (5–15 นาที)

1. **ปิด WiFi ต่อหน้าห้อง** แล้วดับเบิลคลิกเปิด `npl-dashboard.html` — เน้นว่าไม่มี error, ไม่มีจอขาว
2. กดปุ่ม **"โหลดข้อมูลตัวอย่าง"** สาธิตให้เห็นทั้ง 6 บล็อก (KPI, NPL Trend, Migration Flow, Aging, Branch Ranking, Restructure Funnel)
3. สาธิต **Column Mapping**: ลองเปลี่ยนชื่อหัวคอลัมน์ในไฟล์ตัวอย่างแล้วโหลดใหม่ ให้เห็นว่าระบบเดาคอลัมน์ให้อัตโนมัติ และแก้เองผ่าน dropdown ได้
4. สาธิตตัวกรองสาขา — เน้นว่า**ทั้ง 6 บล็อกขยับพร้อมกัน** เมื่อกรอง
5. ปิดท้ายด้วยตราประทับ "v1.0 | 6 ส.ค. 69" มุมล่างขวา และตราวันที่ข้อมูล — อธิบายว่ามีไว้กันสับสนไฟล์เก่า/ใหม่เวลาไฟล์กระจายไปหลายสาขา

## 3. สอนสูตรแจ้งอาการ (15–20 นาที)

แจก `pocket-card.md` (พิมพ์ A5) ให้ทุกคน อธิบาย 3 ส่วนบนการ์ด:

- **สูตร 4 บรรทัด**: ทำอะไร / คาดว่าจะเห็นอะไร / เห็นอะไรจริง / เกิดทุกครั้งหรือบางครั้ง
- **ขั้นวินิจฉัย 2 ข้อ**: กดปุ่มโหลดข้อมูลตัวอย่างก่อนเสมอ (แยกว่าปัญหาอยู่ที่ไฟล์หรือเครื่องมือ) + เก็บบรรทัดสีแดงจาก Console (F12)
- **กฎซ่อม 3 ข้อ**: เก็บไฟล์เก่า / ขอไฟล์ใหม่ทั้งอัน / ซ่อมทีละอาการ

ให้ผู้เรียนลองพูดสูตร 4 บรรทัดออกเสียงคนละรอบ โดยสมมติอาการอะไรก็ได้ เพื่อให้คุ้นก่อนลงมือจริง

## 4. Workshop จับบั๊ก 3 ตัว (20–40 นาที)

แบ่งกลุ่ม/โต๊ะ แจกไฟล์บั๊กทีละไฟล์ (ไม่บอกล่วงหน้าว่าบั๊กคืออะไร — ให้เขาจับอาการเอง) ให้เวลาโต๊ะละประมาณ 6 นาทีต่อไฟล์:

| ไฟล์ | ระดับ | สิ่งที่ผู้เรียนต้องทำ |
|---|---|---|
| `bug-01-encoding.html` | ง่าย | เปิดไฟล์ → โหลด CSV ตัวอย่าง → เจอตัวอักษรยึกยือ → ใช้สูตร 4 บรรทัดเขียนอาการ → เปิด `starter-prompt.md` เป็นฐาน แล้วถาม Claude ให้ซ่อม |
| `bug-02-column.html` | กลาง | โหลดข้อมูลตัวอย่าง → สังเกตว่าบล็อก Aging ว่างเปล่าแต่บล็อกอื่นปกติ → แจ้งอาการเฉพาะจุด ไม่ใช่ "มันพัง" |
| `bug-03-logic.html` | ยาก ⭐ | เปิดจอ ดูเผินๆ เหมือนปกติทุกอย่าง ไม่มี error ใน Console → ต้องคำนวณ %NPL รวมด้วยมือ (Σยอดหนี้ชั้น NPL / Σยอดหนี้ทั้งหมด) เทียบกับตัวเลขบนจอ ถึงจะจับได้ว่าไม่ตรง |

**สิ่งที่วิทยากรต้องเดินดู**: ผู้เรียนใช้สูตร 4 บรรทัดจริงหรือแค่พิมพ์ "มันพัง"? ถ้าเจอกลุ่มไหนพิมพ์สั้นเกินไป ให้เข้าไปช่วยแปลงเป็น 4 บรรทัดสด ๆ

## 5. เฉลย + สรุปบทเรียนแต่ละบั๊ก (40–55 นาที)

เฉลยทีละไฟล์ ให้ผู้เรียนเล่าก่อนว่าเขาแจ้งอาการว่าอย่างไร แล้วจึงเติมบทเรียนที่ต้องติดตัวไป:

- **bug-01 (encoding)**: "ปัญหาอยู่ที่ไฟล์ ไม่ใช่เครื่องมือ" — พิสูจน์ได้ด้วยปุ่มโหลดข้อมูลตัวอย่างแล้วพบว่าปกติ → **บทเรียน: เช็คเครื่องมือด้วยข้อมูลตัวอย่างก่อนสรุปว่าเครื่องมือพัง**
- **bug-02 (column)**: บล็อกเดียวพัง บล็อกอื่นปกติ → **บทเรียน: อาการเฉพาะจุดชี้ไปที่สาเหตุเฉพาะจุด** การแจ้งว่า "บล็อกที่ 4 ว่าง บล็อกอื่นปกติ" มีค่ากว่าการแจ้งว่า "มันพัง" มาก เพราะช่วยให้ AI หาสาเหตุเร็วขึ้นมาก
- **bug-03 (logic)** ⭐ บั๊กสำคัญที่สุดของคาบ: หน้าจอสวยงามปกติทุกอย่าง ไม่มี error เลย แต่ตัวเลขผิด → **บทเรียนหลักของทั้งคาบ: "ไม่มี error ไม่ได้แปลว่าถูก" ต้องสุ่มตรวจตัวเลขด้วยมือเสมอ — นี่คือนิสัยที่ต้องติดตัวไปใช้กับทุกงานที่ทำร่วมกับ AI ต่อจากนี้ ไม่ใช่แค่กับ dashboard ตัวนี้**

ปิดหัวข้อนี้ด้วยการย้ำ **กฎเหล็กเรื่อง %NPL รวม**: ต้องคำนวณจาก Σตัวตั้ง/Σตัวหาร ห้ามเฉลี่ยเปอร์เซ็นต์ข้ามสาขา — เพราะเป็นความผิดพลาดที่มองไม่เห็นบนหน้าจอ (ตรงกับที่ bug-03 จำลองไว้)

## 6. สรุปรวม + วิธีส่งต่อไฟล์ให้สาขาอื่น (55–60 นาที)

- ย้ำอีกครั้ง: dashboard ตัวนี้ **"ส่งต่อได้"** — สาขา A สร้างครั้งเดียว ส่งไฟล์ให้สาขา B–Z ทาง LINE แต่ละสาขา import ข้อมูลของตัวเองแล้วใช้ได้ทันที ไม่ต้องรอทีมกลางทำให้
- ย้ำว่า `starter-prompt.md` ถูกฝังไว้ท้ายไฟล์ `npl-dashboard.html` แล้ว (เป็น HTML comment) — เวลาไฟล์มีปัญหา แค่ส่งไฟล์ทั้งอันกลับไปให้ AI พร้อมอาการที่เจอ AI จะเข้าใจเจตนาเดิมทันทีโดยไม่ต้องเดา
- แจกกลับบ้าน: `pocket-card.md` ที่พิมพ์แล้ว + ลิงก์/ไฟล์ `starter-prompt.md` เผื่อใครอยากสร้าง dashboard เวอร์ชันของสาขาตัวเองใหม่ทั้งหมด
- เปิดถาม-ตอบ 2–3 นาทีสุดท้าย ปิดคาบ
